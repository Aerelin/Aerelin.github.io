## 1. FSOP 介绍

### 1.1 什么是 FSOP

**FSOP** 是 **File Stream Oriented Programming** 的缩写，是一种基于 glibc 中 `FILE` 结构体的面向文件流编程攻击技术。

### 1.2 前置知识：`_IO_FILE` 与 `_IO_list_all`

根据对 `FILE` 的介绍可知：

- 进程内所有的 `_IO_FILE` 结构体会使用 `_chain` 域相互连接，形成一个**链表**。
- 这个链表的**头部**由全局变量 `_IO_list_all` 维护。

```
_IO_list_all -> FILE_1 -> FILE_2 -> FILE_3 -> ... -> NULL
                  ^_chain     ^_chain     ^_chain
```

### 1.3 FSOP 的核心思想

FSOP 的核心思想是：

1. **劫持 `_IO_list_all` 的值**，来伪造链表和其中的 `_IO_FILE` 项。
2. 但单纯的伪造只是构造了数据，还需要某种方法进行**触发**。
3. FSOP 选择的触发方法是调用 `_IO_flush_all_lockp`。

### 1.4 触发函数：`_IO_flush_all_lockp`

`_IO_flush_all_lockp` 函数会刷新 `_IO_list_all` 链表中所有项的文件流，相当于对每个 `FILE` 调用 `fflush`，也对应着会调用 `_IO_FILE_plus.vtable` 中的 `_IO_overflow`。

其源码逻辑如下：

```c
int
_IO_flush_all_lockp (int do_lock)
{
    ...
    fp = (_IO_FILE *) _IO_list_all;
    while (fp != NULL)
    {
        ...
        if (((fp->_mode <= 0 && fp->_IO_write_ptr > fp->_IO_write_base))
            && _IO_OVERFLOW (fp, EOF) == EOF)
        {
            result = EOF;
        }
        ...
    }
}
```

**关键条件**：当满足以下条件时，会调用 `_IO_OVERFLOW(fp, EOF)`：

- `fp->_mode <= 0`
- `fp->_IO_write_ptr > fp->_IO_write_base`

## 2. FSOP 利用

### 2.1 自动触发场景

`_IO_flush_all_lockp` **不需要攻击者手动调用**，在以下情况下会被系统自动调用：

| 序号 | 触发场景 | 说明 |
|------|---------|------|
| 1 | 当 libc 执行 **abort** 流程时 | 最常见，通过堆利用触发 |
| 2 | 当执行 **exit** 函数时 | 进程退出时自动刷新所有文件流 |
| 3 | 当执行流从 **main 函数返回**时 | 程序正常结束 |

### 2.2 abort 流程的触发路径

#### 2.2.1 堆检测失败触发 abort

在 ptmalloc 中，分配或者释放堆块失败就会调用 `malloc_printerr`。以下以 `unlink` 宏为例，展示了堆检测失败时的调用链：

```c
#define unlink(AV, P, BK, FD) {
    if (__builtin_expect (chunksize(P) != (next_chunk(P))->prev_size, 0))
        malloc_printerr (check_action, "corrupted size vs. prev_size", P, AV);
    FD = P->fd;
    BK = P->bk;
    if (__builtin_expect (FD->bk != P || BK->fd != P, 0))
        malloc_printerr (check_action, "corrupted double-linked list", P, AV);
    else {
        FD->bk = BK;
        BK->fd = FD;
        if (!in_smallbin_range (P->size)
            && __builtin_expect (P->fd_nextsize != NULL, 0)) {
            if (__builtin_expect (P->fd_nextsize->bk_nextsize != P, 0)
                || __builtin_expect (P->bk_nextsize->fd_nextsize != P, 0))
                malloc_printerr (check_action,
                    "corrupted double-linked list (not small)",
                    P, AV);
        }
        ...
    }
}
```

当堆块的 `fd`、`bk` 指针不一致（双向链表完整性检查失败）时，会触发 `malloc_printerr`。

#### 2.2.2 从 malloc_printerr 到 abort

在 `__libc_message` 中，会触发 `abort`，接着就会触发 `_IO_flush_all_lockp`：

```c
if (do_abort)
{
    BEFORE_ABORT (do_abort, written, fd);

    /* Kill the application. */
    abort ();
}
```

#### 2.2.3 完整调用链

当 glibc 检测到内存损坏时，完整的调用链如下：

```
malloc_printerr
    ↓
__libc_message (error msg)
    ↓
abort
    ↓
_IO_flush_all_lockp
    ↓ (如果满足条件)
JUMP_FIELD(_IO_overflow_t, __overflow)   ← 调用 vtable 中的 _IO_overflow
```

### 2.3 利用条件

梳理 FSOP 利用的条件：

#### 条件一：获取 libc 基址

首先需要攻击者获知 **libc.so 基址**，因为 `_IO_list_all` 是作为全局变量储存在 libc.so 中的，不泄露 libc 基址就不能改写 `_IO_list_all`。

#### 条件二：任意地址写

之后需要用**任意地址写**把 `_IO_list_all` 的内容改为指向我们可控内存的指针。

#### 条件三：构造 fake_FILE 和 fake_vtable

在可控内存中布置数据，需要布置一个理想函数的 vtable 指针。但为了让我们构造的 `fake_FILE` 能够正常工作，还需要布置一些其他数据。依据是前面给出的条件：

```c
if (((fp->_mode <= 0 && fp->_IO_write_ptr > fp->_IO_write_base))
    && _IO_OVERFLOW (fp, EOF) == EOF)
{
    result = EOF;
}
```

即需要满足：

- `fp->_mode <= 0`
- `fp->_IO_write_ptr > fp->_IO_write_base`

### 2.4 利用流程总结

完整的 FSOP 利用步骤如下：

#### 第一步：在可控内存处布置 fake_vtable 与 fake_fp

```
fake_vtable.overflow = system          // vtable 中的 _IO_overflow 指向 system
fake_fp.flags      = "sh"             // 作为 system 的参数，执行 system("sh")
fake_fp.mode       = 0                // 满足 fp->_mode <= 0 的条件
fake_fp.writeptr   > fake_fp.writebase // 满足 fp->_IO_write_ptr > fp->_IO_write_base
fake_fp.vtable     = fake_vtable      // vtable 指向我们伪造的 vtable
```

#### 第二步：通过任意地址写，覆盖 `_IO_list_all` 为 fake_fp

将 `_IO_list_all` 的值改写为指向我们布置好的 `fake_fp` 的地址。

#### 第三步：触发 `_IO_flush_all_lockp`

通过以下方式之一触发：

- 触发堆检测失败 → `malloc_printerr` → `abort` → `_IO_flush_all_lockp`
- 调用 `exit()` 函数
- 从 `main` 函数返回

当 `_IO_flush_all_lockp` 遍历到我们的 `fake_fp` 时，满足条件后会调用：

```
JUMP_FIELD(_IO_overflow_t, __overflow)
```

即调用 `fake_vtable` 中的 `_IO_overflow`，也就是 `system("sh")`，从而获得 shell。

## 附录：关键知识点速查

### FSOP 利用要素一览

| 要素 | 说明 |
|------|------|
| `_IO_list_all` | 全局变量，维护所有 `_IO_FILE` 结构体的链表头 |
| `_IO_flush_all_lockp` | 遍历链表并刷新所有文件流，触发 `_IO_overflow` |
| `_IO_OVERFLOW(fp, EOF)` | 宏展开后调用 `vtable->__overflow(fp, EOF)` |
| `fake_vtable` | 伪造的虚函数表，`__overflow` 字段指向目标函数（如 `system`） |
| `fake_fp` | 伪造的 `_IO_FILE` 结构体，需满足 `_mode <= 0` 且 `write_ptr > write_base` |
| 触发方式 | 堆检测失败 → abort、exit()、main 返回 |

### 前置漏洞要求

FSOP 利用通常需要以下漏洞原语的组合：

1. **信息泄露**：获取 libc 基址（用于定位 `_IO_list_all`）
2. **任意地址写**：覆盖 `_IO_list_all` 指向伪造的 `fake_FILE`
3. **堆漏洞**：触发 `malloc_printerr` → `abort` 流程（如 UAF、Double Free、堆溢出等导致堆检测失败）
