# House of Force 堆利用技术详解

## 一、概述

House of Force 是一种经典的堆利用方法。需要注意的是，House of Force 本身并不是一种堆漏洞，而是一种**利用手法**——如果一个基于堆的漏洞想要通过 House of Force 方法来进行利用，需要满足以下前提条件。

### 1.1 利用前提条件

1. **能够以溢出等方式控制到 top chunk 的 size 域**
   - 需要找到一个漏洞（如堆溢出），使得攻击者可以修改 top chunk 的 size 字段

2. **能够自由地控制堆分配尺寸的大小**
   - 程序需要允许用户指定 malloc 的分配大小，以便精确控制 top chunk 指针的移动

---

## 二、原理分析

### 2.1 核心原理

House of Force 产生的原因在于 **glibc 对 top chunk 的处理机制**。

根据堆数据结构的知识，进行堆分配时：

- 如果所有空闲的块都无法满足需求，glibc 就会从 **top chunk** 中分割出相应的大小作为堆块的空间。
- 当使用 top chunk 分配堆块时，如果 size 值是由用户控制的任意值，就可以使得 **top chunk 指向我们期望的任何位置**。
- 这就相当于实现了一次**任意地址写**。

### 2.2 glibc 的验证机制

然而，glibc 会对用户请求的大小和 top chunk 现有的 size 进行验证。在 `_int_malloc` 函数中，核心判断逻辑如下：

```c
victim = av->top;
size = chunksize(victim);

if ((unsigned long)(size) >= (unsigned long)(nb + MINSIZE))
{
    remainder_size = size - nb;
    remainder = chunk_at_offset(victim, nb);
    av->top = remainder;
    set_head(victim, nb | PREV_INUSE |
             (av != &main_arena ? NON_MAIN_ARENA : 0));
    set_head(remainder, remainder_size | PREV_INUSE);

    check_malloced_chunk(av, victim, nb);
    void *p = chunk2mem(victim);
    alloc_perturb(p, bytes);
    return p;
}
```

**验证条件解读：**

```
size >= nb + MINSIZE
```

即 top chunk 的 size 必须大于等于 `nb + MINSIZE`，才会进入分割流程。其中：

- `size`：top chunk 当前的 size 值
- `nb`：用户请求的分配大小（经过对齐处理后的内部大小）
- `MINSIZE`：最小可分配堆块的大小

---

## 三、绕过验证的方法

### 3.1 篡改 top chunk size 为 -1

如果可以篡改 top chunk 的 size 为一个很大的值，就可以轻松通过这个验证。

**一般做法是把 top chunk 的 size 改为 -1**，原因如下：

- 在进行比较时，size 会被转换成**无符号数**（`unsigned long`）
- -1 在 `unsigned long` 中表示最大的数（即 `0xFFFFFFFFFFFFFFFF`，64 位系统下）
- 因此无论如何都可以通过 `size >= nb + MINSIZE` 的验证

### 3.2 分配后的效果

验证通过后，glibc 会执行以下关键操作：

```c
remainder_size = size - nb;
remainder = chunk_at_offset(victim, nb);
av->top = remainder;
```

- `remainder_size = size - nb`：计算剩余大小
- `remainder = chunk_at_offset(victim, nb)`：计算新的 top chunk 位置（原 top chunk 地址 + nb）
- `av->top = remainder`：**更新 top 指针**

接下来的堆块就会分配到这个新位置。用户只要控制了这个指针，就相当于实现了**任意地址写任意值（write-anything-anywhere）**。

## 四、利用步骤

### 4.1 完整利用流程

```
┌─────────────────────────────────────────────────────────┐
│  步骤 1: 获取堆地址                                      │
│  利用 House of Force 需要堆地址，因为需要利用堆地址来计算  │
─────────────────────────────────────────────────────────┤
│  步骤 2: 找到漏洞修改 top_chunk size                      │
│  找到一个可以更改 top_chunk size 的漏洞（如堆溢出）         │
│  通常将 top chunk size 修改为 -1 (0xFFFFFFFFFFFFFFFF)     │
├─────────────────────────────────────────────────────────┤
│  步骤 3: 计算距离并申请堆块                                │
│  根据要写入的地址与 top chunk 的距离来申请相应大小          │
│  使 top chunk 指针指向目标写入地址                         │
├─────────────────────────────────────────────────────────┤
│  步骤 4: 再次申请进行写入                                  │
│  在目标地址处再次 malloc，写入任意数据                     │
└─────────────────────────────────────────────────────────┘
```

### 4.2 关键计算公式

```
需要申请的堆块大小 = 目标地址 - 当前 top chunk 地址 - 堆块头部大小(0x10)
```

注意：计算时需要确保对齐到 `0x10` 的倍数。

## 五、源码细节分析

### 5.1 checked_request2size 宏

在 byte 进入 `_int_malloc` 函数后，会经过 `checked_request2size` 这个宏进行处理：

```c
/*
 * Convert request size to internal form by adding SIZE_SZ bytes
 * overhead plus possibly more to obtain necessary alignment and/or
 * to obtain a size of at least MINSIZE, the smallest allocatable
 * size. Also, checked_request2size traps (returning 0) request sizes
 * that are so large that they wrap around zero when padded and
 * aligned.
 */
checked_request2size(bytes, nb);
```

该宏的作用：
- 将用户请求的字节数转换为内部形式
- 添加 `SIZE_SZ` 字节的开销
- 进行对齐处理，确保至少为 `MINSIZE`

### 5.2 REQUEST_OUT_OF_RANGE 检查

```c
#define REQUEST_OUT_OF_RANGE(req)                                 \
  ((unsigned long)(req) >=                                        \
   (unsigned long)(INTERNAL_SIZE_T)(-2 * MINSIZE))
```

**限制条件：** 必须满足 `REQUEST_OUT_OF_RANGE`，即：

```
byte < -2 * MINSIZE
```

这里一般没有什么问题，因为正常请求的大小远小于这个值。

### 5.3 request2size 对齐宏

```c
/* pad request bytes into a usable size -- internal version */
#define request2size(req)                                         \
  (((req) + SIZE_SZ + MALLOC_ALIGN_MASK < MINSIZE) ?              \
   MINSIZE :                                                      \
   ((req) + SIZE_SZ + MALLOC_ALIGN_MASK) & ~MALLOC_ALIGN_MASK)
```

**对齐逻辑：**
- 如果 `(req + SIZE_SZ + MALLOC_ALIGN_MASK) < MINSIZE`，则返回 `MINSIZE`
- 否则，对 `(req + SIZE_SZ + MALLOC_ALIGN_MASK)` 进行对齐，掩码为 `~MALLOC_ALIGN_MASK`

### 5.4 checked_request2size 完整定义

```c
/* Same, except also perform argument check */
#define checked_request2size(req, sz)                             \
  if (REQUEST_OUT_OF_RANGE(req)) {                                \
    __set_errno(ENOMEM);                                          \
    return 0;                                                     \
  }                                                               \
  (sz) = request2size(req);
```

### 5.5 对齐注意事项

通过 `request2size` 进行对齐时，如果中间的距离不是对齐的，需要调整申请的大小，**使其对齐到 0x10**。

原因：申请出来的 chunk 在 free 的时候，是有对齐检测的。如果不对齐，在后续 free 操作时可能会触发异常。

## 七、利用条件总结

| 条件 | 说明 |
|------|------|
| 堆地址泄漏 | 需要知道堆地址，用于计算目标地址与 top chunk 的距离 |
| top chunk size 可控 | 需要漏洞（如堆溢出）来修改 top chunk 的 size 字段 |
| 分配大小可控 | 程序需允许用户指定 malloc 的大小 |
| 无 ASLR 或已泄漏 | 需要知道目标写入地址（如 GOT 表地址） |

## 九、注意事项

1. **对齐问题**：计算 malloc 的大小时，必须确保对齐到 `0x10`（16 字节），否则在 free 时可能触发对齐检测导致程序崩溃。

2. **size 为 -1 的巧妙性**：将 top chunk size 设为 -1 是最常用的技巧，因为 -1 转为无符号数后是最大值，可以绕过任何大小检查。

3. **与现代 glibc 的兼容性**：较新版本的 glibc 可能增加了额外的安全检查（如 top chunk size 的 sanity check），House of Force 在某些版本上可能不再适用。

4. **与其他技术的结合**：House of Force 通常与其他漏洞利用技术结合使用，如 GOT 表覆写、__malloc_hook 覆写等，以实现最终的代码执行。
