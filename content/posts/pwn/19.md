## 二、Off-by-one 漏洞介绍

### 2.1 什么是 Off-by-one

严格来说，**off-by-one 漏洞是一种特殊的溢出漏洞**。off-by-one 指程序向缓冲区中写入时，写入的字节数超过了这个缓冲区本身所申请的字节数，并且**只越界了一个字节**。

```
┌─────────────────────────────┐
│   申请的缓冲区 (0x58 bytes)   │
├─────────────────────────────┤
│  [0x00] ... [0x57] [0x58]   │  ← 多写了 1 字节
└─────────────────────────────┘
                              ↑
                         越界的 1 字节
```

### 2.2 为什么 Off-by-one 可以被利用

一般来说，单字节溢出被认为是难以利用的。但是因为 **Linux 的堆管理机制 ptmalloc 验证的松散性**，基于 Linux 堆的 off-by-one 漏洞利用起来并不复杂，并且威力强大。

需要说明的是：

- off-by-one 可以基于**各种缓冲区**，比如栈、bss 段等等
- 但**堆上（heap based）的 off-by-one** 是 CTF 中比较常见的
- 本文档仅讨论**堆上的 off-by-one 情况**

### 2.3 堆上 Off-by-one 的核心原理

由于堆的分配机制，**free chunk 的 `prev_size` 是可以用作上一 chunk 的数据域的**。因此如果我们申请一个 `0x58` 的堆块，那么我们写 `0x59` 个字节就可以覆盖到下一 chunk 的最后 **1 byte size**。

```
┌──────────────────────────────────────────────┐
│  Chunk A (inuse)                              │
│  ──────────┬───────────────────────────────┐ │
│  │  header  │  data (0x58 bytes)            │ │
│  │  size    │  [0x00] ... [0x57] [0x58] ←越界│ │
│  └──────────┴───────────────────────────────┘ │
├──────────────────────────────────────────────┤
│  Chunk B (free)                               │
│  ┌──────────┬───────────────────────────────┐ │
│  │ prev_size│  size (最后1 byte被覆盖)       │ │
│  └──────────┴───────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

**关键点：** 通过覆盖下一 chunk 的 size 字段的最后一个字节，我们可以改变 ptmalloc 对该 chunk 大小的认知，从而为后续的 chunk extend 创造条件。

## 三、Chunk Extend 利用技术

### 3.1 什么是 Chunk Extend

**Chunk extend 是堆漏洞的一种常见利用手法**，通过 extend 可以实现 **chunk overlapping** 的效果。

所谓 **overlap（重叠）**，就是字面意思——部分重叠，通过使两个 chunk 部分重叠来达到溢出的效果。

### 3.2 Chunk Extend 的产生原因

Chunk extend 技术能够产生的原因在于 **ptmalloc 在对堆 chunk 进行操作时使用的各种宏是十分粗暴的**。具体细节可以查看 glibc malloc 源码。

ptmalloc 通过 **chunk header 的数据**判断 chunk 的使用情况和对 chunk 的前后块进行定位。简而言之，chunk extend 就是：

> **通过控制 `size` 和 `prev_size` 域来实现跨越块操作，从而导致 overlapping。**

### 3.3 Chunk Extend 的分类

Chunk extend 这种技术针对不同的 bin 类型有不同的利用方式，一般有以下**三种**：

| 序号 | 类型 | 目标状态 |
|------|------|----------|
| 1 | 针对 inuse 的 fastbin | 修改 inuse 状态的 fastbin chunk |
| 2 | 针对 inuse 的 smallbin | 修改 inuse 状态的 smallbin chunk |
| 3 | 针对 free 的 unsorted bin | 修改 free 状态的 unsorted bin chunk |

### 3.4 Chunk Shrink

与 chunk extend 类似的还有一种称为 **chunk shrink** 的操作。chunk shrink 一般使用在 **off-by-null** 的利用流程中。

## 四、针对不同 Bin 类型的 Chunk Extend

### 4.1 针对 Inuse 的 Fastbin

#### 原理

简单来说，该利用的效果是：**通过更改第一个块的大小来控制第二个块的内容**。

在 inuse 的 fastbin 中，修改本块 chunk 的 size，然后再进行 free，就可以实现在下一次 malloc 时分配出**包含下一 chunk 内存**的一块新的堆块，由此，就可以对下一 chunk 进行操作。

#### 利用步骤

```
步骤 1: 通过 off-by-one 修改 chunk A 的 size（使其变大，覆盖 chunk B 的头部）
步骤 2: free(chunk A)  —— 此时 chunk A 进入 fastbin
步骤 3: malloc(更大的size) —— 分配出的新块包含了 chunk B 的内存区域
步骤 4: 对新块进行写操作，即可控制 chunk B 的内容
```

#### 注意事项

> free 时要满足 fastbin 的要求，即 **next_chunk 的 size 合法**。

这意味着在修改 chunk size 时，必须确保下一个 chunk 的 size 字段仍然符合 fastbin 的大小范围要求，否则 free 时会触发安全检查导致程序崩溃。

### 4.2 针对 Inuse 的 Smallbin

#### 原理

通过之前的内容，我们得知：

- 处于 **fastbin 范围**的 chunk 释放后会被置入 **fastbin 链表**中
- 不处于这个范围的 chunk 被释放后会被置于 **unsorted bin 链表**中

与 fastbin 的 extend 一样，我们只需要修改当前 chunk 的 size，在对其进行 free，就可以包含下一 chunk 的部分内存。

#### 与 Fastbin 的区别

但是与 fastbin 不同，**small bin 的 free 会比较复杂**，我们需要伪造的东西也会比较多。一般选择使用现成的堆块或者按照以下方式伪造：

#### 伪造要求

1. **当前块的 size 中 prev_inuse 设为 1** —— 防止与上一 chunk 进行合并
2. **修改 size 后所对应的 next_chunk 位置，size 中的 prev_inuse 设为 1** —— 代表可进行 free
3. **next_chunk 的下一 chunk 中的 prev_inuse 设为 1** —— 防止当前 chunk 与 next_chunk 进行合并

```
┌─────────────────────────────────────────────────────────┐
│  Chunk A (修改size后)                                     │
│  size: [新size] | prev_inuse = 1  ← 防止与前块合并        │
├─────────────────────────────────────────────────────────┤
│  Chunk B (next_chunk)                                     │
│  size: [合法size] | prev_inuse = 1  ← 代表可free          │
├─────────────────────────────────────────────────────────┤
│  Chunk C (next_chunk的下一chunk)                          │
│  prev_inuse = 1  ← 防止与Chunk B合并                      │
└─────────────────────────────────────────────────────────┘
```

### 4.3 针对 Free 的 Unsorted Bin

#### 原理

对 free 的 unsorted bin 进行 extend 较为简单，因为 **unsorted bin 在进行分割时并没有过多的检测**。

只需要满足以下条件之一即可：

- `size > nb + MINSIZE`
- `size == nb`

#### 源码分析

以下是 glibc malloc 中 unsorted bin 分割的关键代码：

```c
if (in_smallbin_range (nb) &&
    bck == unsorted_chunks (av) &&
    victim == av->last_remainder &&
    (unsigned long) (size) > (unsigned long) (nb + MINSIZE))
{
    /* split and reattach remainder */
    remainder_size = size - nb;
    remainder = chunk_at_offset (victim, nb);
    unsorted_chunks (av)->bk = unsorted_chunks (av)->fd = remainder;
    av->last_remainder = remainder;
    remainder->bk = remainder->fd = unsorted_chunks (av);
    if (!in_smallbin_range (remainder_size))
    {
        remainder->fd_nextsize = NULL;
        remainder->bk_nextsize = NULL;
    }

    set_head (victim, nb | PREV_INUSE |
              (av != &main_arena ? NON_MAIN_ARENA : 0));
    set_head (remainder, remainder_size | PREV_INUSE);
    set_foot (remainder, remainder_size);

    check_malloced_chunk (av, victim, nb);
    void *p = chunk2mem (victim);
    alloc_perturb (p, bytes);
    return p;
}
```

当 `size == nb` 时：

```c
if (size == nb)
{
    set_inuse_bit_at_offset (victim, size);
    if (av != &main_arena)
        victim->size |= NON_MAIN_ARENA;
    check_malloced_chunk (av, victim, nb);
    void *p = chunk2mem (victim);
    alloc_perturb (p, bytes);
    return p;
}
```

#### 利用方法

对 free 状态的 **last remainder 的 unsorted bin 的 size 进行扩大**，在之后的申请时，直接申请扩大后的 size，就可以将此 chunk 拿出，且与 next_chunk 形成了 **overlap**。

```
利用流程：
1. 通过 off-by-one 扩大 free 状态 unsorted bin chunk 的 size
2. malloc(扩大后的size)
3. 分配出的 chunk 与 next_chunk 形成 overlap
4. 通过 overlap 控制 next_chunk 的内容
```

## 五、利用流程

对于 chunk extend 的利用也分为**两种方式**：

1. **通过 extend 进行后向 overlap（Backward Overlap）**
2. **通过 extend 进行前向 overlap（Forward Overlap）**

### 5.1 后向 Overlap（Backward Overlap）

通过 extend 进行的后向 overlap 是 **CTF 中较为常见的一种情况**，通过 overlap 来达到对下一堆块进行修改。

后向 overlap 就是：**通过构造 chunk extend 后直接申请一块较大的空间来达到两块 chunk 的 overlap**。

```
利用前：
┌──────────┬──────────┬──────────┐
│ Chunk A  │ Chunk B  │ Chunk C  │
│ (inuse)  │ (inuse)  │ (inuse)  │
└──────────┴──────────┴──────────┘

步骤 1: off-by-one 修改 Chunk A 的 size，使其覆盖 Chunk B 的 header
步骤 2: free(Chunk A) → malloc(更大的size)
步骤 3: 新分配的块跨越了原来的 Chunk A + Chunk B 的区域

利用后：
┌───────────────────────┬──────────┐
│   新 Chunk (overlap)   │ Chunk C  │
│   包含 A + B 的区域     │ (inuse)  │
└───────────────────────┴──────────┘
         ↑
    可以控制 Chunk B 的内容
```

### 5.2 前向 Overlap（Forward Overlap）

前向 overlap 的原理与后向类似，但方向相反——通过修改后续 chunk 的元数据，使得分配时向前覆盖之前的 chunk 区域。这种方式在实际 CTF 题目中相对少见，但原理相通。

## 六、总结与学习建议

### 核心知识点回顾

| 概念 | 说明 |
|------|------|
| **Off-by-one** | 写入字节数超过缓冲区 1 字节，在堆上可覆盖下一 chunk 的 size 最后 1 byte |
| **Chunk Extend** | 通过控制 size/prev_size 域实现 chunk overlapping |
| **Chunk Overlap** | 两个 chunk 部分内存重叠，实现跨块读写 |
| **Fastbin Extend** | 修改 size 后 free，下次 malloc 获得包含下一 chunk 的块 |
| **Smallbin Extend** | 需要伪造 prev_inuse 位，free 检测更严格 |
| **Unsorted Bin Extend** | 检测最少，只需 size > nb+MINSIZE 或 size == nb |
| **后向 Overlap** | CTF 中最常见，extend 后申请大块实现 overlap |
| **Chunk Shrink** | 与 extend 相反，常用于 off-by-null 利用 |

### 学习路径建议

1. **基础阶段**：理解 ptmalloc 的 chunk 结构（header、size、prev_size、prev_inuse 位）
2. **原理阶段**：掌握 off-by-one 如何影响下一 chunk 的 size 字段
3. **实践阶段**：分别练习三种 bin 类型的 chunk extend 利用
4. **进阶阶段**：结合 unlink、house of 系列手法进行综合利用

### 推荐练习资源

- glibc malloc 源码阅读（重点关注 `_int_malloc`、`_int_free` 函数）
- CTF 历年真题中的 off-by-one 题目
- 使用 GDB + pwndbg/gef 进行动态调试验证
