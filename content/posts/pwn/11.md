## 一、格式化字符串函数概述

格式化字符串函数可以接受**可变数量的参数**，并将第一个参数作为**格式化字符串**，根据其来解析之后的参数。

通俗来说，格式化字符串函数就是将计算机内存中表示的数据转化为我们人类可读的字符串格式。

几乎所有的 C/C++ 程序都会利用格式化字符串函数来：

- 输出信息
- 调试程序
- 处理字符串

一般来说，格式化字符串在利用的时候主要分为三个部分：

1. **格式化字符串函数**（如 `printf`、`sprintf` 等）
2. **格式化字符串**（如 `"%d %s %x"` 等）
3. **后续参数**（可选，即被格式化的实际数据）

| 函数 | 基本介绍 |
|------|---------|
| `printf` | 输出到 stdout |

| `err, verr, warn, vwarn` 等 | 错误/警告信息输出 |

## 三、格式化字符串格式规范

### 3.1 完整格式

```
%[parameter][flags][field width][.precision][length]type
```

### 3.2 各组成部分说明

#### parameter（参数位置）

- `n$`：获取格式化字符串中的**指定参数**（第 n 个参数）
- 例如 `%2$x` 表示取第 2 个参数以十六进制输出

#### flag（标志位）

- 控制输出的对齐方式、填充字符等

#### field width（字段宽度）

- 输出的**最小宽度**
- 不足时默认用空格填充

#### precision（精度）

- 输出的**最大长度**

#### length（长度修饰符）

| 修饰符 | 说明 |
|--------|------|
| `hh` | 输出一个字节 |
| `h` | 输出一个双字节 |

#### type（类型说明符）

| 类型 | 说明 |
|------|------|
| `d/i` | 有符号整数 |
| `u` | 无符号整数 |
| `x/X` | 16 进制 unsigned int。`x` 使用小写字母；`X` 使用大写字母。如果指定了精度，则输出的数字不足时在左侧补 0。默认精度为 1。精度为 0 且值为 0，则输出为空 |
| `o` | 8 进制 unsigned int。如果指定了精度，则输出的数字不足时在左侧补 0。默认精度为 1。精度为 0 且值为 0，则输出为空 |
| `s` | 如果没有用 `l` 标志，输出 null 结尾字符串直到精度规定的上限；如果没有指定精度，则输出所有字节。如果用了 `l` 标志，则对应函数参数指向 `wchar_t` 型的数组，输出时把每个宽字符转化为多字节字符，相当于调用 `wctomb` 函数 |
| `c` | 如果没有用 `l` 标志，把 `int` 参数转为 `unsigned char` 型输出；如果用了 `l` 标志，把 `wint_t` 参数转为包含两个元素的 `wchar_t` 数组，其中第一个元素包含要输出的字符，第二个元素为 null 宽字符 |
| `p` | `void *` 型，输出对应变量的值。`printf("%p", a)` 用地址的格式打印变量 `a` 的值，`printf("%p", &a)` 打印变量 `a` 所在的地址 |
| `n` | **不输出字符**，但是把已经成功输出的字符个数写入对应的整型指针参数所指的变量 |
| `%` | `%` 字面值，不接受任何 flags、width |

## 四、格式化字符串漏洞原理

### 4.1 printf 的处理流程

在进入 `printf` 之后，函数首先获取第一个参数，一个一个读取其字符，会遇到两种情况：

1. **当前字符不是 `%`**：直接输出到相应标准输出
2. **当前字符是 `%`**：继续读取下一个字符
   - 如果没有字符，报错
   - 如果下一个字符是 `%`，输出 `%`
   - 否则根据相应的字符，获取相应的参数，对其进行解析并输出

### 4.2 漏洞产生的根本原因

当用户输入的字符串被直接作为格式化字符串的第一个参数传入 `printf` 等函数时：

```c
// 危险写法（存在漏洞）
printf(user_input);

// 安全写法
printf("%s", user_input);
```

攻击者可以通过在输入中插入 `%x`、`%p`、`%s`、`%n` 等格式化符号，来：

- **读取栈上的数据**（信息泄漏）
- **向任意地址写入数据**（任意写）

## 五、利用格式化字符串漏洞泄漏信息

一般来说，在格式化字符串漏洞中，我们存在有**两种方式**去泄漏一些东西：

1. **泄漏栈上的内容**
2. **泄漏指定内存的内容**

---

## 六、泄漏栈上内容

### 6.1 方法

使用 `%x$p` 格式，会以 16 进制的方式输出栈上第 x 个位置的值。

### 6.2 示例

假设栈布局如下：

| 偏移 | 值 |
|------|-----|
| `0x8` | `0x28` |
| `0x10` | `0xFFFF1234` |
| `0x18` | `0xFFFF1235` |
| `0x20` | `0xFFFF1236` |
| `0x28` | `%2$p%3$p` |
| `0x30` | |
| `0x38` | |
| `0x40` | |

当格式化字符串为 `%2$p%3$p` 时：

- `%2$p` → 取第 2 个参数 → `0xFFFF1234`
- `%3$p` → 取第 3 个参数 → `0xFFFF1235`

**将会输出**：`0xFFFF12340xFFFF1235`（实际输出为 `0xffff12340xffff1235`）

> 注意：具体的偏移编号取决于调用约定和栈帧布局，需要通过调试确定。

---

## 七、确定偏移量（pwngdb fmtarg 指令）

### 7.1 问题

对于 `%x$p` 中的 `x` 具体数字的确定，可以使用 **pwngdb** 中的 `fmtarg` 指令。

### 7.2 使用示例

在 GDB 中调试时：

```
pwndbg> fmtarg 0xffffd5b4
The index of format argument : 1 ("%1$0$p")
```

### 7.3 调试过程分析

通过反汇编可以看到 `printf@plt` 的调用：

```asm
0x80485ae <main+99>    call   printf@plt
```

此时栈帧内容：

```
00:0000  esp 0xffffd5b0 -> 0xffffd5cc -> 0x333231  /* '123' */
01:0004       0xffffd5b4 -> 0x8048670 -> bound edi, ...
02:0008       0xffffd5b8 -> 0x1
03:000c       0xffffd5bc -> 0x1
04:0010       0xffffd5c0 -> 0xf7df6438 -> 0x2dfe
05:0014       0xffffd5c4 -> 0x93c /* '<\t' */
06:0018       0xffffd5c8 -> 0xf7df6cc8 -> add byte ...
07:001c  eax 0xffffd5cc -> 0x333231  /* '123' */
```

`fmtarg` 指令会自动计算格式化字符串参数相对于 `printf` 第一个参数的偏移，从而确定 `%x$p` 中 `x` 的值。

## 八、泄漏指定地址内容

### 8.1 方法

通过将目标地址写入栈中，然后使用 `%x$s` 格式来读取该地址处的字符串内容。

### 8.2 示例

假设栈布局如下：

| 偏移 | 值 |
|------|-----|
| `0x8` | `0x28` |
| `0x10` | `0xFFFF1234` |
| `0x18` | `0xFFFF1235` |
| `0x20` | `0xFFFF1236` |
| `0x28` | `p64(0x80102048)` |
| `0x30` | `%4$s` |
| `0x38` | |
| `0x40` | |

同时在内存 `0x80102048` 处存储了字符串 `"hello"`。

当格式化字符串为 `p64(0x80102048) + "%4$s"` 时：

- 首先将目标地址 `0x80102048` 写入栈的第 4 个参数位置
- `%4$s` 将第 4 个参数作为地址，读取该地址处的字符串

**会输出**：`0x80102048` 这个位置的内存中存储的字符串 **`hello`**

### 8.3 注意事项

- 需要知道目标地址在栈上的偏移位置
- 目标地址本身需要作为参数传入（通常通过 payload 拼接实现）
- 在 64 位程序中，地址需要用 `p64()` 打包；32 位程序用 `p32()`

## 九、格式化字符串泄漏总结与对比

### 9.1 两种泄漏方式

#### 方式一：泄漏栈上残留的 libc 地址

- **方法**：通过先确定偏移，然后使用 `%x$p` 第一种方法输出即可
- **适用场景**：栈上恰好残留了 libc 相关地址

#### 方式二：泄漏 GOT 表中的 libc 地址

- **方法**：通过第二种方法输出，地址注意填为一个已经进行过绑定的函数的 GOT 地址
- **适用场景**：已知 GOT 表地址，需要查询 libc 版本

### 9.2 优劣对比

| 对比项 | 方式一（泄漏栈上 libc 地址） | 方式二（泄漏 GOT 表中 libc 地址） |
|--------|---------------------------|--------------------------------|
| **libc 版本要求** | 需要已知 libc 版本，因为一般无法通过栈上残留的 libc 地址确定 libc 版本 | 不需要预先知道 libc 版本，可以用于查询 libc 版本 |
| **GOT 表地址要求** | 不需要知道 GOT 表地址 | 需要已知 GOT 表地址，因为需要将 GOT 表地址写入栈中 |
| **适用场景** | 已知 libc 版本，只需泄漏地址计算偏移 | 未知 libc 版本，需要先确定 libc 版本 |

### 9.3 利用思路总结

```
格式化字符串漏洞利用流程：

1. 确认漏洞点（用户输入直接作为 printf 的第一个参数）
2. 确定偏移量（使用 pwngdb 的 fmtarg 指令或手动测试）
3. 选择泄漏方式：
   ├── 方式一：泄漏栈上残留地址 → 需要已知 libc 版本
   └── 方式二：泄漏 GOT 表内容 → 可以确定 libc 版本
4. 根据泄漏的地址计算 system 等函数地址
5. 结合 %n 实现任意地址写入，完成 getshell
```

## 附录：关键知识点速查

### A. 格式化字符串类型速查表

| 格式符 | 作用 | 利用价值 |
|--------|------|---------|
| `%x` / `%p` | 以十六进制读取栈数据 | 泄漏栈信息 |
| `%s` | 以字符串形式读取指定地址内容 | 泄漏任意地址内容 |
| `%n` | 将已输出字符数写入指定地址 | 任意地址写入 |
| `%d` | 以十进制读取 | 读取整数值 |
| `%%` | 输出字面量 `%` | 绕过检测 |

### B. 常用工具

| 工具 | 用途 |
|------|------|
| **pwngdb** | GDB 插件，`fmtarg` 指令可自动计算偏移量 |
| **pwntools** | Python  exploit 框架，`FmtStr` 类可自动化利用 |
| **GDB** | 调试器，用于分析栈布局和函数调用 |

### C. 安全编程建议

```c
// 错误：用户输入直接作为格式化字符串
printf(user_input);

// 正确：使用 %s 包裹用户输入
printf("%s", user_input);
```
