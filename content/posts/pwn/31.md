## 一、Seccomp 简介

**seccomp** 是 **secure computing** 的缩写，是 Linux kernel 从 **2.6.23** 版本引入的一种简洁的 **sandboxing（沙箱）机制**。

### 背景

在 Linux 系统里，大量的系统调用直接暴露给用户态程序。但是：

- 并不是所有的系统调用都被程序实际需要
- 不安全的代码滥用系统调用会对系统造成安全威胁

### 作用

seccomp 安全机制能使一个进程进入到一种 **"安全"运行模式**，该模式下的进程**只能调用有限种系统调用**。

通过限制进程可用的系统调用集合，seccomp 可以：

- 减少内核攻击面
- 防止恶意代码执行危险操作（如执行 shell、网络通信等）
- 在 CTF Pwn 题目中，seccomp 常被用来限制 exploit 的方式，迫使选手使用 ORW（open-read-write）等替代方案来读取 flag

## 二、Seccomp 状态查看方法

### 方法一：查看 /proc/${pid}/status 文件

在 `/proc/${pid}/status` 文件中的 **Seccomp** 字段可以看到进程的 Seccomp 状态：

```
Seccomp:    0
```

Seccomp 字段的取值含义如下：

| 值 | 含义 |
|---|---|
| **0** | 尚未启动（未启用 seccomp） |
| **1** | 启用 **STRICT** 模式 |
| **2** | 启用 **FILTER** 模式 |

### 方法二：通过 seccomp-tools 工具查询

使用 **seccomp-tools** 工具可以详细查看 seccomp 的 BPF 过滤规则：

```bash
seccomp-tools dump PATH
```

其中 `PATH` 为可执行文件的路径。

#### 输出示例解读

```
line  CODE    JT    JF      K
=================================
0000: 0x20 0x00 0x00 0x00000004  A = arch
0001: 0x15 0x00 0x09 0x40000003  if (A != ARCH_I386) goto 0011
0002: 0x20 0x00 0x00 0x00000000  A = sys_number
0003: 0x15 0x07 0x00 0x000000ad  if (A == rt_sigreturn) goto 0011
0004: 0x15 0x06 0x00 0x00000077  if (A == sigreturn) goto 0011
0005: 0x15 0x05 0x00 0x000000fc  if (A == exit_group) goto 0011
0006: 0x15 0x04 0x00 0x00000001  if (A == exit) goto 0011
0007: 0x15 0x03 0x00 0x00000005  if (A == open) goto 0011
0008: 0x15 0x02 0x00 0x00000003  if (A == read) goto 0011
0009: 0x15 0x01 0x00 0x00000004  if (A == write) goto 0011
0010: 0x06 0x00 0x00 0x00050026  return ERRNO(38)
0011: 0x06 0x00 0x00 0x7fff0000  return ALLOW
```

**各列含义：**

| 列名 | 含义 |
|---|---|
| **line** | 规则行号 |
| **CODE** | BPF 操作码 |
| **JT** | Jump True（条件为真时跳转的行数） |
| **JF** | Jump False（条件为假时跳转的行数） |
| **K** | 操作数/比较值 |

**规则解读：**

- 第 0000 行：获取当前架构信息存入累加器 A
- 第 0001 行：判断架构是否为 I386，不是则跳转到 0011（ALLOW）
- 第 0002 行：获取系统调用号存入累加器 A
- 第 0003~0009 行：逐一判断系统调用号是否为 `rt_sigreturn`、`sigreturn`、`exit_group`、`exit`、`open`、`read`、`write`，匹配则跳转到 0011（ALLOW）
- 第 0010 行：如果以上都不匹配，返回 `ERRNO(38)`（即 ENOSYS，函数未实现）
- 第 0011 行：返回 `ALLOW`，允许该系统调用正常执行

**总结：** 该 seccomp 规则只允许 `rt_sigreturn`、`sigreturn`、`exit_group`、`exit`、`open`、`read`、`write` 这 7 个系统调用，其余系统调用均返回错误。

## 三、Seccomp 的两种模式

### 1. Strict Mode（严格模式）

仅允许以下 **4 个**系统调用：

| 系统调用 | 说明 |
|---|---|
| **read** | 读取数据 |
| **write** | 写入数据 |
| **_exit** | 退出进程 |
| **sigreturn** | 信号返回 |

**行为：** 当调用未在 seccomp 白名单中的系统调用后，应用程序会被 **kill**（进程被终止）。

> Strict Mode 是最简单的 seccomp 模式，通过 `prctl(PR_SET_SECCOMP, SECCOMP_MODE_STRICT)` 启用。

### 2. Filter Mode（过滤模式）

在此模式下，允许使用 **BPF（Berkeley Packet Filter）** 来设定黑名单或者白名单。

**特点：**

- 可以精细控制哪些系统调用被允许、哪些被禁止
- 支持基于系统调用号、参数值等条件进行过滤
- 若白名单中允许 `fork` 以及 `clone`，则此进程的子进程**一律继承**父进程原有的 system call filters

> Filter Mode 通过 `prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog)` 启用，其中 `prog` 是一个 `sock_fprog` 结构体，包含 BPF 过滤规则。

## 四、Seccomp Filter 行为定义

seccomp filter 定义了数种行为（返回值），用于决定当系统调用被过滤时程序应如何响应：

| 行为常量 | 说明 |
|---|---|
| **SECCOMP_RET_KILL** | 不执行 system call，**立即中止进程**（发送 SIGSYS 信号） |
| **SECCOMP_RET_TRAP** | 不执行 system call，进程送出（SIGSYS）system call，并且将 system call 相关信息储存至 `siginfo_t` |
| **SECCOMP_RET_ERRNO** | 不执行 system call，SECCOMP_RET_DATA 回传 **errno**（系统调用返回指定的错误码） |
| **SECCOMP_RET_TRACE** | 会驱动 ptrace base 的 tracer（如 gdb），让 tracer 可以来接手处理。若没有相关 tracer 则回传 **-ENOSYS** |
| **SECCOMP_RET_ALLOW** | system call **正常执行** |

### 行为优先级（从高到低）

```
SECCOMP_RET_KILL > SECCOMP_RET_TRAP > SECCOMP_RET_ERRNO > SECCOMP_RET_TRACE > SECCOMP_RET_ALLOW
```

当多条规则匹配同一个系统调用时，优先级最高的行为生效。

### 在 CTF 中的应用

在 CTF Pwn 题目中，最常见的情况是：

- seccomp 禁止了 `execve` 系统调用（无法直接 get shell）
- 但允许 `open`、`read`、`write` 系统调用
- 此时需要通过 **ORW（Open-Read-Write）** 的 ROP 链来读取 flag 文件内容并输出

## 五、ORW 系统调用详解

当 seccomp 禁用了 `execve` 等危险系统调用时，**ORW（open-read-write）** 是读取文件内容的经典方法。以下详细介绍这三个系统调用。

### 5.1 open 系统调用

#### 头文件

```c
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
```

#### 函数原型

```c
int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);
```

#### 参数说明

| 参数 | 说明 |
|---|---|
| **pathname** | 指向欲打开的文件路径字符串 |
| **flags** | 打开文件的标志位 |
| **mode** | 文件权限模式（仅在创建新文件时有效） |

#### 常用 flags

| 标志 | 值 | 说明 |
|---|---|---|
| **O_RDONLY** | 0 | 以只读方式打开文件 |
| **O_WRONLY** | 1 | 以只写方式打开文件 |
| **O_RDWR** | 2 | 以可读写方式打开文件 |

#### glibc 源码定义

根据 glibc 源码中的定义（源码路径：`/bits/fcntl.h`）：

```c
/* File access modes for `open' and `fcntl'. */
#define O_RDONLY    0    /* Open read-only. */
#define O_WRONLY    1    /* Open write-only. */
#define O_RDWR      2    /* Open read/write. */
```

#### 返回值

- 成功：返回**文件描述符**（非负整数）
- 失败：返回 **-1** 并设置 errno

#### 在 ROP 链中的使用

在 32 位程序中，`open` 的系统调用号为 **5**（`__NR_open`）：

```
eax = 5          ; sys_open
ebx = filename   ; 文件路径字符串地址
ecx = O_RDONLY   ; 0（只读）
edx = 0          ; mode（创建文件时使用，此处为0）
int 0x80
```

在 64 位程序中，`open` 的系统调用号为 **2**（`__NR_open`）：

```
rax = 2          ; sys_open
rdi = filename   ; 文件路径字符串地址
rsi = O_RDONLY   ; 0（只读）
rdx = 0          ; mode
syscall
```

> 注意：64 位下还有一个 `openat` 系统调用（syscall number 257），某些题目中 seccomp 可能只禁用了 `open` 而未禁用 `openat`，可以作为替代方案。

### 5.2 read 系统调用

#### 函数原型

```c
ssize_t read(int fd, void *buf, size_t count);
```

#### 返回值

| 情况 | 返回值 |
|---|---|
| 成功 | 返回**读取的字节数** |
| 出错 | 返回 **-1** 并设置 errno |
| 已到达文件末尾 | 返回 **0** |

#### 参数说明

| 参数 | 说明 |
|---|---|
| **fd** | 文件描述符。一般 **0 为 stdin**，**1 为 stdout**，**2 为 stderr** |
| **buf** | 所要读入数据的**目标地址**（缓冲区） |
| **count** | 所要读取的**字节数** |

#### 在 ROP 链中的使用

在 32 位程序中，`read` 的系统调用号为 **3**（`__NR_read`）：

```
eax = 3          ; sys_read
ebx = fd         ; 文件描述符（open 的返回值）
ecx = buf        ; 缓冲区地址
edx = count      ; 读取字节数
int 0x80
```

在 64 位程序中，`read` 的系统调用号为 **0**（`__NR_read`）：

```
rax = 0          ; sys_read
rdi = fd         ; 文件描述符
rsi = buf        ; 缓冲区地址
rdx = count      ; 读取字节数
syscall
```

### 5.3 write 系统调用

#### 函数原型

```c
ssize_t write(int fd, void *buf, size_t count);
```

#### 返回值

| 情况 | 返回值 |
|---|---|
| 成功 | 返回**输出的字节数** |
| 出错 | 返回 **-1** 并设置 errno |

#### 参数说明

| 参数 | 说明 |
|---|---|
| **fd** | 文件描述符。一般 **0 为 stdin**，**1 为 stdout**，**2 为 stderr** |
| **buf** | 所要输出数据的**源地址**（缓冲区） |
| **count** | 所要输出的**字节数** |

#### 在 ROP 链中的使用

在 32 位程序中，`write` 的系统调用号为 **4**（`__NR_write`）：

```
eax = 4          ; sys_write
ebx = fd         ; 文件描述符（通常为 1，即 stdout）
ecx = buf        ; 缓冲区地址
edx = count      ; 写入字节数
int 0x80
```

在 64 位程序中，`write` 的系统调用号为 **1**（`__NR_write`）：

```
rax = 1          ; sys_write
rdi = fd         ; 文件描述符（通常为 1，即 stdout）
rsi = buf        ; 缓冲区地址
rdx = count      ; 写入字节数
syscall
```

## 六、ORW 在 CTF Pwn 中的完整流程

当题目设置了 seccomp 禁用了 `execve` 但允许 `open`、`read`、`write` 时，完整的利用流程如下：

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   open()    │────▶│   read()    │────▶│   write()   │
│  打开flag文件 │     │  读取文件内容  │     │  输出到stdout │
└─────────────┘     └─────────────┘     └─────────────┘
       │                    │                    │
       ▼                    ▼                    ▼
  返回 fd (如3)        将内容读入缓冲区      将缓冲区内容写出
  O_RDONLY = 0         fd = 3              fd = 1 (stdout)
  pathname = "flag"    buf = 可读可写地址     buf = 同上
                       count = 0x30          count = 0x30
```

### 步骤详解

1. **open("flag", O_RDONLY)**
   - 打开 flag 文件
   - 返回文件描述符 fd（通常为 3，因为 0/1/2 已被 stdin/stdout/stderr 占用）

2. **read(fd, buf, count)**
   - 从 fd 指向的文件中读取 count 字节
   - 数据存入 buf 指向的缓冲区（需要可写地址，如 BSS 段或栈上）

3. **write(1, buf, count)**
   - 将 buf 中的内容输出到 stdout（fd=1）
   - 从而将 flag 内容打印出来

### 注意事项

- **文件路径**：需要知道 flag 文件的确切路径，常见路径包括 `./flag`、`/flag`、`/home/ctf/flag` 等
- **缓冲区地址**：需要一个可写且可读的地址作为 read 和 write 的缓冲区，通常选择 BSS 段或栈上的地址
- **系统调用号**：注意区分 32 位和 64 位的系统调用号差异
- **寄存器传递**：32 位通过栈传递参数，64 位通过寄存器传递参数（rdi, rsi, rdx, rcx, r8, r9）

## 七、常用系统调用号参考表

### 32 位（x86）

| 系统调用 | 调用号 | 参数传递 |
|---|---|---|
| read | 3 | ebx, ecx, edx |
| write | 4 | ebx, ecx, edx |
| open | 5 | ebx, ecx, edx |
| close | 6 | ebx |
| execve | 11 | ebx, ecx, edx |
| exit | 1 | ebx |

### 64 位（x86_64）

| 系统调用 | 调用号 | 参数传递 |
|---|---|---|
| read | 0 | rdi, rsi, rdx |
| write | 1 | rdi, rsi, rdx |
| open | 2 | rdi, rsi, rdx |
| close | 3 | rdi |
| execve | 59 | rdi, rsi, rdx |
| exit | 60 | rdi |

## 八、总结

| 知识点 | 关键内容 |
|---|---|
| **seccomp 本质** | Linux 内核沙箱机制，限制进程可用的系统调用 |
| **两种模式** | Strict Mode（仅4个syscall）和 Filter Mode（BPF自定义规则） |
| **查看方法** | `/proc/${pid}/status` 或 `seccomp-tools dump` |
| **Filter 行为** | KILL / TRAP / ERRNO / TRACE / ALLOW |
| **ORW 利用** | open → read → write 三步读取文件，绕过 execve 禁用 |
| **关键区别** | 32位和64位的系统调用号和参数传递方式不同 |
