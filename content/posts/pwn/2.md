## 五、栈操作

- 栈具有 **push**（入栈）和 **pop**（出栈）两种操作。
- `push eax` → 将 eax 寄存器的值入栈，`esp -= 4`
- `pop eax` → 将栈顶的值弹出给 eax 寄存器，`esp += 4`
- 进程中每个函数运行时都要保存自己的临时数据，这些数据保存在**栈**上。
- 不同函数不能把数据放在一块，每个函数都要有自己的栈空间，系统给出的解决方案就是**栈帧**。
- **栈帧**指一个函数在运行时使用的栈空间，由 **esp** 和 **ebp** 表示边界。
    - **esp**：栈顶指针寄存器
    - **ebp**：栈底指针寄存器

## 六、函数调用约定

调用约定规范了函数之间调用的方式、参数如何传递、返回值如何传递、栈由谁来平衡。

### 1. `__cdecl`（C 调用约定）

- C/C++ 语言**缺省**的调用约定
- 参数按照**从右至左**的方式入栈
- 函数本身**不清理栈**，由**调用者**负责清理
- 返回值在 **EAX** 中
- 允许**可变参数函数**存在，如 `int sprintf(char* buffer, const char* format, ...);`

### 2. `__stdcall`（Pascal 调用约定）

- 参数按照**从右至左**的方式入栈
- 函数**自身清理堆栈**
- 返回值在 **EAX** 中

### 3. `__fastcall`

- 通过 **CPU 寄存器**来传递参数（速度快）
- 用 **ECX** 和 **EDX** 传递前两个双字（DWORD）或更小的参数
- 剩下的参数按照从右至左的方式入栈
- 函数自身清理堆栈，返回值在 **EAX** 中

## 七、函数调用过程与栈帧结构

以 `int max(int a, int b)` 为例：

**调用方：**

Plain Text

```
push b
push a
call max        ; 等价于 push eip; jmp max
```

**被调用方（max 函数内部）：**

Plain Text

```
push ebp
mov ebp, esp
sub esp, XXXXX   ; 为局部变量分配空间
......
mov eax, retVal  ; 返回值放入 eax
leave            ; 等价于 mov esp, ebp; pop ebp
ret              ; 等价于 pop eip
```

**栈帧布局（从高地址到低地址）：**

|位置|内容|
|---|---|
|上层函数数据||
|b 参数||
|a 参数||
|return addr|返回地址|
|ebp|← ebp 指向此处|
|局部变量1||
|局部变量2||
|...||
|局部变量n|← esp 指向此处|

## 背景：缓冲区溢出攻击

当程序存在缓冲区溢出漏洞时，攻击者可以通过输入超长数据覆盖栈上的**返回地址**，从而劫持程序的控制流。但关键问题是：**从输入开始到返回地址之间到底隔了多少字节？** 这个距离就是"偏移量"。

## `cyclic` 的工作原理

`cyclic` 是 pwntools 提供的一个工具，它生成一个**不重复的德布鲁因序列（De Bruijn sequence）**。比如：

Plain Text

```
aaaabaaacaaadaaaeaaafaaagaaahaaaiaaajaaakaaalaaamaaanaaaoaaapaaa...
```

这个序列的特点是：**任意连续 4 个字节的组合在整个序列中只出现一次**。

## 攻击流程

1. **生成模式串**：用 `cyclic 200` 生成一段 200 字节的非重复模式串，作为 payload 输入给目标程序。
2. **程序崩溃**：由于缓冲区溢出，返回地址被模式串中的某 4 个字节覆盖，程序崩溃。
3. **查看崩溃时的返回地址**：在调试器（如 pwndbg）中查看崩溃时 EIP/RIP 的值，比如发现返回地址被覆盖成了 `0x62616164`（即 ASCII 字符串 `"daab"`，小端序）。
4. **反查偏移**：执行 `cyclic -l daab`，工具在德布鲁因序列中查找 `"daab"` 第一次出现的位置，返回 **112**。

## 为什么是 112？

这意味着从输入缓冲区的起始位置到返回地址之间正好有 **112 个字节**。所以：

- 输入前 112 个字节 → 填满缓冲区 + 覆盖保存的 ebp
- 第 113~116 个字节 → 恰好覆盖返回地址

因此，构造 exploit 时只需要：

Python

```python
payload = b'A' * 112 + p32(目标地址)
```

前 112 个字节是填充物（padding），后面的 4 字节才是真正要写入的返回地址（比如指向 shellcode 或 `system()` 函数）。

## `daab` 从哪来的？

`daab` 是**程序崩溃时，返回地址（EIP/RIP）被覆盖成的值**。它不是预先知道的，而是通过调试观察得到的。

具体流程：

1. 你用 `cyclic 200` 生成一段模式串（比如 `aaaabaaacaaadaaaeaaaf...`）作为输入，发送给目标程序。
2. 程序崩溃了，你在调试器（pwndbg/gdb）中查看崩溃时的 **EIP/RIP 寄存器值**。
3. 假设你看到 EIP = `0x62616164`。
4. 把这个值转成 ASCII 字符串：`0x64 0x61 0x61 0x62` → `"daab"`（小端序，低位字节在前）。
5. 然后执行 `cyclic -l daab`，工具告诉你这个子串在模式串中出现在第 **112** 个位置。

## 换个场景，值就不同了

如果缓冲区大小不一样，崩溃时 EIP 被覆盖的值也会不同。比如：

- EIP = `0x62616166` → ASCII `"faab"` → 执行 `cyclic -l faab`
- EIP = `0x62616168` → ASCII `"haab"` → 执行 `cyclic -l haab`

每次的值取决于**缓冲区到返回地址的距离**，所以 `daab` 只是这道题恰好崩溃时得到的值，不是固定的。
