## 一、tcache 概述

tcache（Thread Local Cache）是 glibc 2.26 引入的一种堆管理机制，旨在提升多线程程序中小内存分配/释放的性能。每个线程拥有独立的 tcache 缓存，避免了多线程竞争全局锁的开销。

**核心特点：**

- 每个线程独立维护，无需加锁
- 缓存小尺寸 chunk（最大 0x408 字节，对应 64 个 bin）
- 采用单链表结构，头插法管理
- 默认每个 bin 最多缓存 7 个 chunk（旧版本）
- 分配和释放时优先从 tcache 中操作，速度极快

## 二、tcache_perthread_struct 结构体

### 2.1 旧版本定义（glibc 2.26 ~ 2.28）

```c
/* We overlay this structure on the user-data portion of a chunk */
typedef struct tcache_entry
{
    struct tcache_entry *next;
} tcache_entry;

/* There is one of these for each thread, which contains the per-thread cache */
typedef struct tcache_perthread_struct
{
    char counts[TCACHE_MAX_BINS];
    tcache_entry *entries[TCACHE_MAX_BINS];
} tcache_perthread_struct;
```

### 2.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `counts` | `char[]` | 存放每个 tcache 链上 chunk 的个数，最大值 255（旧版本） |
| `entries` | `tcache_entry *[]` | tcache 链表的入口指针，与 fastbinY 类似，是每个 bin 链表的头指针 |

### 2.3 结构体布局

```
tcache_perthread_struct (位于堆头部)
├── counts[0]  →  bin 0 (size 0x20) 的 chunk 数量
── counts[1]  →  bin 1 (size 0x30) 的 chunk 数量
├── ...
├── counts[63] →  bin 63 (size 0x410) 的 chunk 数量
├── entries[0] →  bin 0 链表头指针
├── entries[1] →  bin 1 链表头指针
├── ...
└── entries[63] → bin 63 链表头指针
```

**关键理解：**

- `tcache_perthread_struct` 是 tcache 的管理结构，分配在堆的头部
- `counts` 数组记录每个 tcache bin 中已缓存的 chunk 数量
- `entries` 数组存储每个 tcache bin 链表的头指针，与 fastbin 的管理方式类似
- 由于该结构体位于堆头部，攻击者可以通过堆溢出等手段控制它

## 三、tcache_put() 与 tcache_get() 源码分析

### 3.1 tcache_put() — 释放时放入 tcache

```c
static void
tcache_put (mchunkptr chunk, size_t tc_idx)
{
    tcache_entry *e = (tcache_entry *) chunk2mem (chunk);
    assert (tc_idx < TCACHE_MAX_BINS);
    e->next = tcache->entries[tc_idx];
    tcache->entries[tc_idx] = e;
    ++(tcache->counts[tc_idx]);
}
```

**执行流程：**

1. 将 chunk 的用户数据部分转换为 `tcache_entry` 指针
2. 断言 bin 索引不越界
3. 将当前 entry 的 `next` 指向该 bin 链表的当前头节点（头插法）
4. 更新链表头为当前 entry
5. 对应 bin 的 `counts` 计数加 1

### 3.2 tcache_get() — 分配时从 tcache 取出

```c
static void *
tcache_get (size_t tc_idx)
{
    tcache_entry *e = tcache->entries[tc_idx];
    assert (tc_idx < TCACHE_MAX_BINS);
    assert (tcache->entries[tc_idx] > 0);
    tcache->entries[tc_idx] = e->next;
    --(tcache->counts[tc_idx]);
    return (void *) e;
}
```

**执行流程：**

1. 取出该 bin 链表头节点
2. 断言 bin 索引不越界且链表非空
3. 将链表头更新为下一个节点
4. 对应 bin 的 `counts` 计数减 1
5. 返回取出的 chunk 地址

### 3.3 关键观察

- `tcache_get()` 中**直接从 `tcache->entries` 中取出地址**，没有像 fastbin 那样做 size 校验
- 这意味着如果攻击者能控制 `entries` 指针，就能实现**任意地址分配**
- `tcache_put()` 和 `tcache_get()` 都没有对 chunk 的完整性做检查（如 fd 指针合法性）

## 四、tcache 泄漏方法

基于对 tcache 机制的理解，在启用 tcache 的情况下进行地址泄漏有多种方法：

### 方法一：填满 tcache 后放入 unsorted bin

**原理：**

tcache 每个 bin 默认最多缓存 7 个 chunk。当同一个 bin 的 tcache 已满后，继续 free 的 chunk 会进入 unsorted bin，从而获得 libc 地址。

**步骤：**

1. 分配多个相同大小的 chunk
2. 依次 free 这些 chunk，填满对应 tcache bin（7 个）
3. 再次 free 同大小的 chunk，此时 chunk 进入 unsorted bin
4. unsorted bin 的 fd/bk 指针会指向 main_arena，泄漏 libc 地址

```c
// 示例：泄漏 libc 地址
void *ptrs[8];
for (int i = 0; i < 7; i++) {
    ptrs[i] = malloc(0x100);
}
for (int i = 0; i < 7; i++) {
    free(ptrs[i]);  // 填满 tcache
}
free(ptrs[7]);  // 进入 unsorted bin，fd 指向 main_arena
// 此时 ptrs[7] 的 fd 字段包含 libc 地址
```

### 方法二：free largebin 直接进入 unsorted bin

**原理：**

当 free 的 chunk 大小超过 tcache 的最大尺寸（0x408 字节）时，chunk 不会进入 tcache，而是直接进入对应的 bin（large bin 或 unsorted bin）。

**步骤：**

1. 分配一个大于 0x408 字节的 chunk
2. free 该 chunk，它直接进入 unsorted bin
3. 读取 chunk 的 fd 字段，获得 libc 地址

```c
void *ptr = malloc(0x500);  // 大于 tcache 最大尺寸
free(ptr);  // 直接进入 unsorted bin
// ptr 的 fd 字段包含 main_arena 地址
```

### 方法三：修改 tcache_perthread_struct 中 count 的值

**原理：**

通过堆溢出等手段，将 `tcache_perthread_struct` 中某个 bin 的 `count` 值修改为 7（最大值），使该 bin 的 tcache 被视为已满。之后 free 同大小的 chunk 会直接进入 unsorted bin。

**步骤：**

1. 通过漏洞修改目标 bin 的 `count` 值为 7
2. free 同大小的 chunk
3. 由于 tcache 已满，chunk 进入 unsorted bin
4. 泄漏 libc 地址

**优势：** 这种方法比方法一更快，不需要先 free 7 个 chunk 来填满 tcache。

## 五、tcache_perthread_struct 攻击

### 5.1 攻击前提

`tcache_perthread_struct` 分配在堆的头部（heap base 附近），因此通过堆溢出等漏洞控制它是相对容易的。

### 5.2 攻击效果

如果能够控制 `tcache_perthread_struct`，那么对于 tcache 来说，基本就可以为所欲为：

- **任意地址分配：** 修改 `entries[i]` 指向目标地址，下次 `malloc` 对应大小即可分配到该地址
- **绕过保护机制：** tcache 没有 fastbin 的 double-free 检查和 size 校验
- **快速利用：** 无需复杂的堆风水，直接控制管理结构即可

### 5.3 攻击示例

```
假设堆布局如下：

heap_base:
├── tcache_perthread_struct  ← 目标
│   ├── counts[0..63]
│   ── entries[0..63]
├── chunk A (可溢出)
└── ...

通过 chunk A 的溢出，覆盖 tcache_perthread_struct：
- 将 entries[3]（对应 0x70 大小）修改为 __free_hook 或 __malloc_hook 的地址
- malloc(0x60) 即可分配到 __free_hook 处
- 写入 system 地址，free("/bin/sh") 即可 getshell
```

## 六、新版本变化

### 6.1 tcache_perthread_struct 结构变化

**新版本定义（glibc 2.29+）：**

```c
typedef struct tcache_perthread_struct
{
    uint16_t counts[TCACHE_MAX_BINS];
    tcache_entry *entries[TCACHE_MAX_BINS];
} tcache_perthread_struct;
```

**关键变化：** `count` 字段由 `char`（1 字节）改为 `uint16_t`（2 字节）。

**影响：**

| 项目 | 旧版本 (char) | 新版本 (uint16_t) |
|------|--------------|-------------------|
| 每个 count 占用空间 | 1 字节 | 2 字节 |
| 最大计数值 | 255 | 65535 |
| 结构体总大小 | 64 + 512 = 576 字节 | 128 + 512 = 640 字节 |
| 溢出覆盖难度 | 较低 | 需要多覆盖 64 字节 |

### 6.2 tcache 分配时的新增检查

新版本在使用 tcache 时，加入了 `tcache->counts[tc_idx] > 0` 的判断：

```c
#if USE_TCACHE
    /* int_free also calls request2size, be careful */
    size_t tbytes;
    if (!checked_request2size (bytes, &tbytes))
    {
        __set_errno (ENOMEM);
        return NULL;
    }

    size_t tc_idx = csize2tidx (tbytes);

    MAYBE_INIT_TCACHE ();

    DIAG_PUSH_NEEDS_COMMENT;
    if (tc_idx < mp_.tcache_bins
        && tcache
        && tcache->counts[tc_idx] > 0)
    {
        return tcache_get (tc_idx);
    }
    DIAG_POP_NEEDS_COMMENT;
#endif
```

**关键变化：** 分配时检查 `tcache->counts[tc_idx] > 0`。

**对攻击的影响：**

- 在伪造 `tcache->next` 指针时，必须同时注意对应的 `counts` 值
- 如果 `counts[tc_idx]` 为 0，即使 `entries[tc_idx]` 有值也不会从 tcache 中取
- 攻击时需要同时伪造 `entries` 指针和 `counts` 计数值

## 七、总结与实战要点

### 7.1 tcache 机制要点

1. tcache 是线程本地缓存，每个线程独立，无锁竞争
2. 每个 bin 默认最多缓存 7 个 chunk
3. 采用单链表头插法管理
4. 分配/释放时优先操作 tcache，速度极快
5. 缺乏完整性校验（无 size check、无 double-free check）

### 7.2 攻击面总结

| 攻击类型 | 原理 | 适用场景 |
|---------|------|---------|
| tcache double free | tcache 不检查 double free | 存在重复 free 漏洞 |
| tcache poisoning | 修改 tcache entry 的 next 指针 | 存在堆溢出/UAF |
| tcache_perthread_struct 攻击 | 直接控制管理结构 | 能溢出到堆头部 |
| tcache house of spirit | 伪造 chunk 放入 tcache | 能控制 free 的参数 |

### 7.3 版本差异注意事项

- **glibc 2.26-2.28：** count 为 char 类型，最大 7 个 chunk，结构体较小
- **glibc 2.29+：** count 改为 uint16_t，新增 `counts > 0` 检查，攻击时需同时伪造 counts 和 entries
- **glibc 2.32+：** 引入 key 字段（safe-linking 机制），tcache entry 的 next 指针被加密

### 7.4 实战建议

1. 首先确认目标程序的 glibc 版本
2. 根据版本选择合适的攻击手法
3. 利用 tcache 泄漏时，优先使用"填满 tcache"方法
4. 攻击 tcache_perthread_struct 时，注意结构体在不同版本中的偏移差异
5. 新版本中伪造 tcache 时，务必同时设置对应的 counts 值
