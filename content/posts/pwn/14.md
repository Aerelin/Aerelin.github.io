## 一、内容简介

本文档涵盖 CTF-Pwn 方向中两类常见的内存安全漏洞：

1. **整数溢出**（Integer Overflow）
2. **数组越界**（Array Out-of-Bounds）

这两类漏洞是 C/C++ 程序中最常见的安全缺陷之一，也是 Pwn 题目中频繁出现的考点。

---

## 二、整型数据基础

### 2.1 C语言整型数据类型表

在 C 语言中，整数的基本数据类型分为**短整型（short）**、**整型（int）**、**长整型（long）**，这三种数据类型还分为**有符号**和**无符号**。每种数据类型都有各自的大小范围。

> 以下数据基于 **64 位环境下使用 gcc-5.4** 编译器的默认行为。

| 类型 | 字节 | 范围 |
|------|------|------|
| `short int` | 2 byte (word) | 0 ~ 32767 (0 ~ 0x7fff) / -32768 ~ -1 (0x8000 ~ 0xffff) |
| `unsigned short int` | 2 byte (word) | 0 ~ 65535 (0 ~ 0xffff) |
| `int` | 4 byte (dword) | 0 ~ 2147483647 (0 ~ 0x7fffffff) / -2147483648 ~ -1 (0x80000000 ~ 0xffffffff) |
| `unsigned int` | 4 byte (dword) | 0 ~ 4294967295 (0 ~ 0xffffffff) |
| `long int` | 8 byte (qword) | 正：0 ~ 0x7fffffffffffffff / 负：0x8000000000000000 ~ 0xffffffffffffffff |
| `unsigned long int` | 8 byte (qword) | 0 ~ 0xffffffffffffffff |

### 2.2 什么是整数溢出

当程序中的数据**超过其数据类型的范围**时，就会造成溢出。整数类型的溢出被称为**整数溢出（Integer Overflow）**。

整数溢出本质上是因为计算机底层以固定位数存储数据，当运算结果超出该位数能表示的范围时，高位会被截断，导致结果与预期不符。

## 三、整数溢出

### 3.1 上界溢出

计算机底层指令**不区分有符号和无符号类型**，数据都是以二进制形式存在（编译器的层面才对有符号和无符号进行区分，产生不同的汇编指令）。

上界溢出分为两种情况，下面以 `short int` 类型与 `unsigned short int` 类型作为例子来进行讲解：

#### 3.1.1 情况一：0x7fff + 1

```
0x7fff + 1 = 0x8000
```

- 这种上界溢出对**无符号短整型**没有影响（0x8000 = 32768，仍在 0~65535 范围内）。
- 但是在**有符号短整型**中，0x7fff 是 32767，而 0x8000 表示的却是 **-32768**。

**影响分析：**

| 类型 | 0x7fff 的值 | 0x7fff + 1 的值 | 是否溢出 |
|------|------------|----------------|---------|
| `unsigned short int` | 32768 | 32768 | 否 |
| `short int` | 32767 | -32768 | **是** |

#### 3.1.2 情况二：0xffff + 1

```
0xffff + 1 = 0x10000
```

- 对于**有符号短整型**来说，0xffff == -1，-1 + 1 == 0，是没有问题的。
- 但是对**无符号短整型**来说，0xffff == 65535，65535 + 1 == 0，就出现了问题。

**影响分析：**

| 类型 | 0xffff 的值 | 0xffff + 1 的值 | 是否溢出 |
|------|------------|----------------|---------|
| `short int` | -1 | 0 | 否（数学上正确） |
| `unsigned short int` | 65535 | 0 | **是**（应为 65536，但被截断为 0） |

### 3.2 下界溢出

下界溢出是指运算结果低于数据类型能表示的最小值。例如：

- `unsigned short int` 类型中，0 - 1 = 0xffff（65535），而非 -1。
- `short int` 类型中，-32768 - 1 = 0x7fff（32767），而非 -32769。

## 四、整数溢出利用场景

### 4.1 利用场景1：范围问题（加法溢出）

**漏洞代码示例：**

```c
header_len = 0x10;
scanf("%uld", &data_len);
len = data_len + header_len;
buf = malloc(len);
read(0, buf, data_len);
```

**漏洞分析：**

如果我们让 `data_len` 输入 `0xffffffff`，那么：

```
len = 0xffffffff + 0x10 = 0x10000000f
```

发生了整数溢出，使得 `len = 0xf`（低 32 位截断）。

- `malloc(0xf)` 只申请了 0x20 的堆空间（堆分配器会对大小进行对齐）。
- 但我们却可以通过 `read` 向其中写入 `0xffffffff` 长度的数据。

**结果：** 显然出现了一个**堆溢出漏洞**。

**利用思路：**

```
输入 data_len = 0xffffffff
→ len 溢出为 0xf
→ malloc(0xf) 分配小缓冲区
→ read(0, buf, 0xffffffff) 写入大量数据
→ 堆缓冲区溢出 → 覆盖相邻堆块元数据或函数指针
```

### 4.2 利用场景2：变量类型转换问题（符号溢出）

**漏洞代码示例：**

```c
scanf("%d", &len);
if (len < 10) {
    read(0, buf, len);
} else {
    puts("NoNoNo");
}
```

**漏洞分析：**

如果我们让 `len` 输入 **-1**：

1. `-1 < 10` 成立，通过检查。
2. 而 `read` 函数的第三个参数是 `size_t`，也就是**无符号类型**。
3. `-1` 被转换为无符号数：`-1 = 0xffffffffffffffff`。

**结果：** 显然出现了溢出问题，`read` 会读取极大的数据量，导致**栈溢出或堆溢出**。

**关键知识点：**

| 步骤 | 操作 | 值 | 类型 |
|------|------|-----|------|
| 1 | 输入 len | -1 | `int`（有符号） |
| 2 | 检查 len < 10 | -1 < 10 = true | `int` 比较 |
| 3 | read 第三个参数 | 0xffffffffffffffff | `size_t`（无符号） |

**利用思路：**

```
输入 len = -1
→ 通过 if(len < 10) 检查
→ read(0, buf, 0xffffffffffffffff) 读取海量数据
→ 缓冲区溢出 → 覆盖返回地址/Canary 等关键数据
```

## 五、数组越界

### 5.1 数组越界的定义

所谓的数组越界，简单地讲就是指**数组下标变量的取值超过了初始定义时的大小**，导致对数组元素的访问出现在数组的范围之外。这类错误也是 C 语言程序中最常见的错误之一。

### 5.2 C语言数组越界的特点

- 在 C 语言中，数组必须是**静态的**。换言之，数组的大小必须在程序运行前就确定下来。
- 由于 C 语言并不具有类似 Java 等语言中现有的静态分析工具的功能，可以对程序中数组下标取值范围进行严格检查，一旦发现数组上溢或下溢，都会因抛出异常而终止程序。
- 也就是说，**C 语言并不检验数组边界**，数组的两端都有可能越界，从而使其他变量的数据甚至程序代码被破坏。
- 因此，数组下标的取值范围只能预先推断一个值来确定数组的维数，而**检验数组的边界是程序员的职责**。

### 5.3 数组越界的两种类型

一般情况下，数组的越界错误主要包括两种：

1. **数组下标取值越界**
2. **指向数组的指针的指向范围越界**

## 六、数组下标取值越界

### 6.1 概念说明

数组下标取值越界主要是指访问数组的时候，**下标的取值不在已定义好的数组的取值范围内**，而访问的是无法获取的内存地址。

例如，对于数组 `int a[3]`，它的下标取值范围是 **[0, 2]**（即 `a[0]`、`a[1]` 与 `a[2]`）。如果我们的取值不在这个范围内（如 `a[3]`），就会发生越界错误。

### 6.2 示例代码

```c
int a[3];
int i = 0;

for (i = 0; i < 4; i++)  // 循环到 i=3 时越界
{
    a[i] = i;
}

for (i = 0; i < 4; i++)
{
    printf("a[%d]=%d\n", i, a[i]);
}
```

**问题分析：**

- 数组 `a` 的大小为 3，合法下标为 0、1、2。
- 循环条件 `i < 4` 使得 `i` 可以取到 3。
- 当 `i = 3` 时，`a[3]` 访问了数组之外的内存，发生越界。
- 越界写入可能覆盖栈上相邻变量的值，越界读取可能泄露敏感信息。

---

## 七、指向数组的指针的指向范围越界

### 7.1 概念说明

指向数组的指针的指向范围越界是指定义数组时会返回一个指向第一个变量的头指针，对这个指针进行加减运算可以向前或向后移动这个指针，进而访问数组中所有的变量。

但在移动指针时，如果**不注意移动的次数和位置**，会使指针指向数组以外的位置，导致数组发生越界错误。

### 7.2 示例代码

```c
int i;
int *p;
int a[5];

p = a;
for (i = 0; i < 10; i++)  // 循环10次，但数组只有5个元素
{
    *p = i + 10;
    p++;
}
```

**问题分析：**

- 数组 `a` 的大小为 5，合法范围为 `a[0]` ~ `a[4]`。
- 指针 `p` 初始指向 `a[0]`。
- 循环执行 10 次，`p++` 移动 10 次。
- 当 `i >= 5` 时，`p` 已经指向数组 `a` 以外的存储单元。
- `*p = i + 10` 会向数组外的内存写入数据，造成越界写。

## 八、数组越界漏洞利用

### 8.1 利用数组越界进行数据读取

利用数组越界进行数据读取的场景一般如下：

```c
int id[5];
int idx;

scanf("%d", &idx);
printf("%d", id[idx]);
```

**漏洞分析：**

- 此时没有对 `idx` 的范围进行检查。
- 可以输出 `id` 数组以外的信息。
- 若 `id` 数组在栈上，可以用来输出 **Canary**、**ret 地址**等关键信息来进行保护绕过。

**利用思路：**

```
1. 确定 id 数组在栈上的位置
2. 通过越界读取 id[5]、id[6]... 等位置
3. 泄露 Canary 值 → 绕过栈保护
4. 泄露 ret 地址 → 计算程序基址（绕过 PIE/ASLR）
5. 结合其他漏洞完成利用
```

**典型利用流程：**

```
数组越界读 → 泄露 Canary → 数组越界写/栈溢出 → 覆盖返回地址 → ROP → get shell
```

## 九、总结与防御建议

### 9.1 整数溢出总结

| 溢出类型 | 触发条件 | 典型后果 |
|---------|---------|---------|
| 有符号上界溢出 | 正值超过类型最大值 | 变为负值，绕过大小检查 |
| 无符号上界溢出 | 值超过类型最大值 | 回绕为 0 或小值，导致分配过小缓冲区 |
| 有符号下界溢出 | 负值超过类型最小值 | 变为正值 |
| 无符号下界溢出 | 0 减正数 | 变为极大的正值 |
| 符号转换溢出 | 有符号负值传给无符号参数 | 变为极大的无符号值 |

### 9.2 数组越界总结

| 越界类型 | 触发条件 | 典型后果 |
|---------|---------|---------|
| 下标取值越界 | 下标超出数组定义范围 | 读/写相邻内存，泄露或破坏数据 |
| 指针范围越界 | 指针移动超出数组边界 | 同下标越界，但更隐蔽 |

### 9.3 防御建议

**针对整数溢出：**

- 使用安全数学运算库（如 SafeInt、IntegerLib）。
- 在运算前检查是否会发生溢出：`if (a > MAX - b)` 再执行 `a + b`。
- 避免有符号和无符号类型的混用。
- 对来自外部的输入进行严格的范围校验。
- 编译器选项：`-ftrapv`（GCC，有符号溢出时触发异常）。

**针对数组越界：**

- 始终对数组下标进行边界检查。
- 使用安全函数替代危险函数（如 `strncpy` 替代 `strcpy`）。
- 编译器选项：`-fstack-protector-all`（启用 Stack Canary）。
- 使用静态分析工具（如 Coverity、Clang Static Analyzer）检测越界。
- 考虑使用具有边界检查的语言或库（如 Rust、C++ 的 `std::vector::at()`）。

### 9.4 CTF 中的常见考法

1. **整数溢出 + 堆溢出组合**：通过整数溢出使 `malloc` 分配小缓冲区，再通过 `read`/`write` 造成堆溢出。
2. **符号转换 + 栈溢出组合**：输入负数绕过长度检查，`read` 以 `size_t` 解释为极大值，造成栈溢出。
3. **数组越界读泄露 Canary**：通过越界读取栈上 Canary 值，再结合栈溢出覆盖返回地址。
4. **数组越界读泄露地址**：通过越界读取返回地址或 GOT 表项，计算程序基址绕过 ASLR/PIE。
