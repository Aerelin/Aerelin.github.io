## 一、概述

IO_FILE 是 C 标准库（glibc）中用于管理文件 I/O 操作的核心数据结构。在 CTF-Pwn 方向中，IO_FILE 利用是一种高级的堆利用技术，通过伪造或修改 IO_FILE 结构体及其 vtable 中的函数指针，可以实现任意代码执行。

理解 IO_FILE 的关键在于掌握各个标准 I/O 函数（如 `fwrite`、`fread`、`fclose`、`exit`）的内部调用链，以及它们如何通过 vtable 进行函数分发。

## 二、IO_FILE 结构体基础

### 2.1 _IO_FILE 结构

```c
struct _IO_FILE {
    int _flags;           // 标志位
    char *_IO_read_ptr;   // 读指针
    char *_IO_read_end;   // 读结束位置
    char *_IO_read_base;  // 读缓冲区起始
    char *_IO_write_base; // 写缓冲区起始
    char *_IO_write_ptr;  // 写指针
    char *_IO_write_end;  // 写结束位置
    char *_IO_buf_base;   // 缓冲区起始
    char *_IO_buf_end;    // 缓冲区结束
    char *_IO_save_base;  // 保存缓冲区起始
    char *_IO_backup_base;// 备份缓冲区起始
    char *_IO_save_end;   // 保存缓冲区结束
    struct _IO_marker *_markers; // 标记
    struct _IO_FILE *_chain;     // 链表指针，指向下一个 FILE
    int _fileno;          // 文件描述符
    // ... 更多字段
};
```

### 2.2 _IO_FILE_plus 结构

```c
struct _IO_FILE_plus {
    _IO_FILE file;        // 基础 FILE 结构
    const struct _IO_jump_t *vtable;  // 虚函数表指针
};
```

**关键点：**
- `_IO_FILE_plus` 是 `_IO_FILE` 的扩展，增加了 `vtable` 指针
- `vtable` 指向 `_IO_jump_t` 结构，包含一系列函数指针
- 通过修改 `vtable` 中的函数指针，可以劫持程序控制流

### 2.3 全局链表 IO_list_all

```c
// glibc 内部维护的全局链表头
struct _IO_FILE *_IO_list_all;
```

- 所有打开的 FILE 结构通过 `_chain` 字段链接成链表
- `IO_list_all` 是链表的头指针
- 程序退出时会遍历此链表

## 三、vtable 机制

### 3.1 _IO_jump_t 结构

vtable（虚函数表）是 IO_FILE 利用的核心。`_IO_jump_t` 结构定义了一系列函数指针：

```c
struct _IO_jump_t {
    JUMP_FIELD(size_t, __dummy);
    JUMP_FIELD(size_t, __dummy2);
    JUMP_FIELD(_IO_finish_t, __finish);      // 对应 fclose 时的清理
    JUMP_FIELD(_IO_overflow_t, __overflow);  // 对应写操作溢出
    JUMP_FIELD(_IO_underflow_t, __underflow);// 对应读操作下溢
    JUMP_FIELD(_IO_underflow_t, __uflow);
    JUMP_FIELD(_IO_pbackfail_t, __pbackfail);
    JUMP_FIELD(_IO_xsputn_t, __xsputn);      // 对应 fwrite
    JUMP_FIELD(_IO_xsgetn_t, __xsgetn);      // 对应 fread
    JUMP_FIELD(_IO_seekoff_t, __seekoff);
    JUMP_FIELD(_IO_seekpos_t, __seekpos);
    JUMP_FIELD(_IO_setbuf_t, __setbuf);
    JUMP_FIELD(_IO_sync_t, __sync);
    JUMP_FIELD(_IO_doallocate_t, __doallocate);
    JUMP_FIELD(_IO_read_t, __read);
    JUMP_FIELD(_IO_write_t, __write);
    JUMP_FIELD(_IO_seek_t, __seek);
    JUMP_FIELD(_IO_close_t, __close);
    JUMP_FIELD(_IO_stat_t, __stat);
    JUMP_FIELD(_IO_showmanyc_t, __showmanyc);
    JUMP_FIELD(_IO_imbue_t, __imbue);
};
```

### 3.2 vtable 在利用中的意义

| 函数指针 | 触发时机 | 利用价值 |
|---------|---------|---------|
| `__overflow` | 写缓冲区满时调用 | 可劫持为 system 等函数 |
| `__underflow` | 读缓冲区空时调用 | 可劫持为 system 等函数 |
| `__finish` | fclose 时调用 | 可劫持为 system 等函数 |
| `__xsputn` | fwrite 时调用 | 中间跳转点 |
| `__xsgetn` | fread 时调用 | 中间跳转点 |

## 四、fwrite 函数调用链

### 4.1 完整调用链

```
fwrite()
  └── _IO_fwrite()
        └── _IO_XSPUTN (从 vtable 中取出)
              └── _IO_new_file_xsputn()
                    └── _IO_OVERFLOW (从 vtable 中取出)
                          └── _IO_new_file_overflow()
                                └── write() [系统调用]
```

### 4.2 逐步分析

#### 第一步：_IO_fwrite 调用 _IO_XSPUTN

```c
// _IO_fwrite 中主要是调用 _IO_XSPUTN 来实现写入功能
// _IO_XSPUTN 位于 _IO_FILE_plus 的 vtable 中
// 调用这个函数需要首先取出 vtable 中的指针，再跳过去进行调用

size_t _IO_fwrite(const void *buf, size_t size, size_t count, FILE *fp) {
    // ...
    // 从 vtable 中获取 __xsputn 函数指针
    _IO_XSPUTN(fp, buf, size * count);
    // ...
}
```

**关键点：**
- `_IO_XSPUTN` 是宏定义，实际从 `fp->vtable->__xsputn` 获取函数指针
- 默认情况下指向 `_IO_new_file_xsputn`

#### 第二步：_IO_new_file_xsputn 调用 _IO_OVERFLOW

```c
// 在 _IO_XSPUTN 对应的默认函数 _IO_new_file_xsputn 中
// 会调用同样位于 vtable 中的 _IO_OVERFLOW

size_t _IO_new_file_xsputn(FILE *fp, const void *data, size_t n) {
    // ...
    if (缓冲区满) {
        // 从 vtable 中获取 __overflow 函数指针并调用
        _IO_OVERFLOW(fp, ch);
    }
    // ...
}
```

**关键点：**
- 当写缓冲区满时，会触发 `_IO_OVERFLOW` 调用
- `_IO_OVERFLOW` 同样从 vtable 中获取，默认指向 `_IO_new_file_overflow`

#### 第三步：_IO_new_file_overflow 调用 write 系统调用

```c
// _IO_OVERFLOW 默认对应的函数是 _IO_new_file_overflow
// 在 _IO_new_file_overflow 内部最终会调用系统接口 write 函数

int _IO_new_file_overflow(FILE *fp, int ch) {
    // ...
    write(fp->_fileno, fp->_IO_buf_base, ...);
    // ...
}
```

### 4.3 利用思路

```
攻击者控制:
1. 伪造 FILE 结构体
2. 设置 vtable 指针指向可控地址
3. 在 vtable 的 __overflow 位置放置 system 地址
4. 触发 fwrite 操作
5. 最终执行 system("/bin/sh") 等命令
```

**调用链中的劫持点：**
```
_IO_fwrite -> _IO_XSPUTN -> _IO_new_file_xsputn -> _IO_OVERFLOW -> [劫持点]
                                                              ↓
                                                         system("/bin/sh")
```

## 五、fread 函数调用链

### 5.1 完整调用链

```
fread()
  └── _IO_fread() [/libio/iofread.c]
        └── _IO_sgetn()
              └── _IO_XSGETN (从 vtable 中取出)
                    ── _IO_file_xsgetn()
                          └── __underflow
                                └── _IO_new_file_underflow()
                                      └── read() [系统调用]
```

### 5.2 逐步分析

#### 第一步：_IO_fread 调用 _IO_sgetn

```c
// fread 的代码位于 /libio/iofread.c 中
// 函数名为 _IO_fread，但真正的功能实现在子函数 _IO_sgetn 中

size_t _IO_fread(void *buf, size_t size, size_t count, FILE *fp) {
    // ...
    _IO_sgetn(fp, buf, size * count);
    // ...
}
```

**关键点：**
- `_IO_fread` 是包装函数
- 真正的读取逻辑在 `_IO_sgetn` 中实现

#### 第二步：_IO_sgetn 调用 _IO_XSGETN

```c
// 在 _IO_sgetn 函数中会调用 _IO_XSGETN
// 而 _IO_XSGETN 是 _IO_FILE_plus.vtable 中的函数指针
// 在调用这个函数时会首先取出 vtable 中的指针然后再进行调用

size_t _IO_sgetn(FILE *fp, void *buf, size_t n) {
    // 从 vtable 中获取 __xsgetn 函数指针
    _IO_XSGETN(fp, buf, n);
}
```

**关键点：**
- `_IO_XSGETN` 从 `fp->vtable->__xsgetn` 获取
- 默认情况下指向 `_IO_file_xsgetn`

#### 第三步：_IO_file_xsgetn 调用 __underflow

```c
// 在默认情况下函数指针是指向 _IO_file_xsgetn 函数的
// _IO_file_xsgetn 函数内部调用 __underflow

size_t _IO_file_xsgetn(FILE *fp, void *buf, size_t n) {
    // ...
    if (缓冲区空) {
        __underflow(fp);  // 调用 vtable 中的 __underflow
    }
    // ...
}
```

#### 第四步：__underflow 调用 read 系统调用

```c
// __underflow 实际是 _IO_new_file_underflow
// 最终会调用 read 进行读入

int _IO_new_file_underflow(FILE *fp) {
    // ...
    read(fp->_fileno, fp->_IO_buf_base, ...);
    // ...
}
```

### 5.3 利用思路

```
攻击者控制:
1. 伪造 FILE 结构体
2. 设置 vtable 指针指向可控地址
3. 在 vtable 的 __underflow 位置放置 system 地址
4. 触发 fread 操作
5. 最终执行 system("/bin/sh") 等命令
```

**调用链中的劫持点：**
```
_IO_fread -> _IO_sgetn -> _IO_XSGETN -> _IO_file_xsgetn -> __underflow -> [劫持点]
                                                                         ↓
                                                                    system("/bin/sh")
```

## 六、fclose 函数调用链

### 6.1 函数说明

`fclose` 是标准 IO 库中用于关闭已打开文件的函数，其作用与 `fopen` 相反。

### 6.2 完整调用链

```
fclose()
  ├── _IO_unlink_it()          // 从 _chain 链表中脱链
  ├── _IO_file_close_it()      // 调用 close 系统调用
  └── _IO_FINISH (vtable)
        └── _IO_file_finish()
              └── free()       // 释放 FILE 结构
```

### 6.3 逐步分析

#### 第一步：_IO_unlink_it 脱链

```c
// fclose 首先会调用 _IO_unlink_it 将指定的 FILE 从 _chain 链表中脱链

void _IO_unlink_it(FILE *fp) {
    // 从 IO_list_all 链表中移除 fp
    // 通过修改 _chain 指针实现
}
```

**关键点：**
- 每个 FILE 结构通过 `_chain` 字段链接
- 脱链操作防止后续遍历访问到已关闭的 FILE

#### 第二步：_IO_file_close_it 关闭文件

```c
// 之后会调用 _IO_file_close_it 函数
// _IO_file_close_it 会调用系统接口 close 关闭文件

int _IO_file_close_it(FILE *fp) {
    // ...
    close(fp->_fileno);  // 系统调用关闭文件描述符
    // ...
}
```

#### 第三步：_IO_FINISH 清理结构

```c
// 最后调用 vtable 中的 _IO_FINISH
// 其对应的是 _IO_file_finish 函数
// 其中会调用 free 函数释放之前分配的 FILE 结构

void _IO_file_finish(FILE *fp) {
    // ...
    free(fp);  // 释放 FILE 结构体内存
    // ...
}
```

### 6.4 利用思路

```
攻击者控制:
1. 伪造 FILE 结构体
2. 设置 vtable 指针指向可控地址
3. 在 vtable 的 __finish 位置放置 system 地址
4. 触发 fclose 操作
5. 最终执行 system("/bin/sh") 等命令
```

**调用链中的劫持点：**
```
fclose -> _IO_unlink_it -> _IO_file_close_it -> _IO_FINISH -> [劫持点]
                                                              ↓
                                                         system("/bin/sh")
```

## 七、exit 函数调用链

### 7.1 完整调用链

```
exit()
  └── 遍历 IO_list_all 中的所有 FILE 结构
        └── 执行每个 FILE 的 vtable 中的:
              ├── _IO_overflow()
              └── setbuf()
```

### 7.2 详细分析

```c
// 程序调用 exit 后，会遍历 IO_list_all 中的所有 FILE 结构
// 并执行其 vtable 中的 _IO_overflow 函数与 setbuf 函数

void exit(int status) {
    // ...
    // 遍历 IO_list_all 链表
    for (FILE *fp = _IO_list_all; fp != NULL; fp = fp->_chain) {
        // 执行 vtable 中的 _IO_overflow
        if (fp->vtable->__overflow) {
            fp->vtable->__overflow(fp, EOF);
        }
        // 执行 setbuf 相关操作
        // ...
    }
    // ...
    _exit(status);
}
```

### 7.3 利用思路

这是 IO_FILE 利用中最经典的场景之一：

```
攻击者控制:
1. 伪造 FILE 结构体
2. 将伪造的 FILE 插入 IO_list_all 链表（或通过堆漏洞使 _IO_list_all 指向伪造结构）
3. 设置 vtable 指针指向可控地址
4. 在 vtable 的 __overflow 位置放置 system 地址
5. 程序调用 exit 时自动遍历并执行
6. 最终执行 system("/bin/sh") 等命令
```

**利用流程图：**
```
exit()
  │
  ├── _IO_list_all -> FILE1 -> FILE2 -> ... -> 伪造的FILE
  │                                              │
  │                                              ├── vtable -> 可控地址
  │                                              │     │
  │                                              │     └── __overflow -> system
  │                                              │
  │                                              └── 参数 -> "/bin/sh"
  │
  └── 执行 system("/bin/sh")
```

## 八、IO_FILE 利用思路

### 8.1 利用前提

1. **堆漏洞**：通常需要先获得堆溢出、UAF、Double Free 等漏洞
2. **泄露地址**：需要泄露 libc 基址、堆地址等
3. **控制 FILE 结构**：能够伪造或修改 FILE 结构体内容
4. **控制 vtable**：能够设置 vtable 指针指向可控区域

### 8.2 常见利用场景

| 场景 | 触发方式 | 劫持函数 |
|------|---------|---------|
| fwrite 利用 | 程序调用 fwrite | `__overflow` |
| fread 利用 | 程序调用 fread | `__underflow` |
| fclose 利用 | 程序调用 fclose | `__finish` |
| exit 利用 | 程序调用 exit | `__overflow` |

### 8.3 利用步骤总结

```
1. 利用堆漏洞获得任意写能力
2. 在堆上伪造 FILE 结构体
   - 设置 _flags 为合适值（如 0xfbad1800）
   - 设置 _IO_write_base、_IO_write_ptr 等指针
   - 设置 _fileno 为 1（stdout）
3. 伪造 vtable 结构
   - 在可控地址处布置函数指针
   - 将 __overflow/__underflow/__finish 设置为 system 地址
4. 修改 _IO_list_all 或相关指针指向伪造的 FILE
5. 触发相应的 I/O 操作或 exit
6. 获得 shell
```

### 8.4 注意事项

1. **vtable 检查**：高版本 glibc 会对 vtable 地址进行检查
   - vtable 必须在 libc 的 `_IO_file_jumps` 附近
   - 需要绕过 vtable 验证机制

2. **_flags 设置**：不同的 `_flags` 值会影响函数执行路径
   - `0xfbad1800`：常用于泄露 libc 地址
   - 需要正确设置以避免提前触发异常

3. **链表完整性**：伪造的 FILE 需要正确设置 `_chain` 指针
   - 防止遍历链表时访问非法地址

## 九、总结

### 9.1 核心知识点

| 函数 | 调用链关键节点 | vtable 劫持点 |
|------|--------------|--------------|
| fwrite | _IO_fwrite -> _IO_XSPUTN -> _IO_new_file_xsputn -> _IO_OVERFLOW | `__overflow` |
| fread | _IO_fread -> _IO_sgetn -> _IO_XSGETN -> _IO_file_xsgetn -> __underflow | `__underflow` |
| fclose | _IO_unlink_it -> _IO_file_close_it -> _IO_FINISH | `__finish` |
| exit | 遍历 IO_list_all -> 执行 vtable 中的函数 | `__overflow` |

### 9.2 学习建议

1. **理解基础**：先掌握堆利用基础（UAF、Double Free、Off-by-Null 等）
2. **源码阅读**：阅读 glibc 的 libio 目录源码，理解 IO_FILE 内部实现
3. **调试实践**：使用 GDB 调试 IO_FILE 相关程序，观察结构体变化
4. **CTF 练习**：通过 CTF 题目实践 IO_FILE 利用技巧

### 9.3 相关资源

- glibc 源码：`/libio/` 目录
- IO_FILE 结构定义：`libio.h`
- vtable 定义：`libioP.h`

## 附录：关键宏定义

```c
// vtable 函数指针调用宏
#define _IO_XSPUTN(FP, DATA, N) JUMP2 (__xsputn, FP, DATA, N)
#define _IO_XSGETN(FP, DATA, N) JUMP2 (__xsgetn, FP, DATA, N)
#define _IO_OVERFLOW(FP, CH) JUMP1 (__overflow, FP, CH)
#define _IO_UNDERFLOW(FP) JUMP0 (__underflow, FP)
#define _IO_FINISH(FP) JUMP1 (__finish, FP, 0)

// JUMP 宏展开后实际从 vtable 中取函数指针并调用
#define JUMP1(FUNC, THIS, X1) (_IO_JUMPS_FUNC(THIS)->FUNC) (THIS, X1)
#define JUMP2(FUNC, THIS, X1, X2) (_IO_JUMPS_FUNC(THIS)->FUNC) (THIS, X1, X2)
#define JUMP0(FUNC, THIS) (_IO_JUMPS_FUNC(THIS)->FUNC) (THIS)
```
