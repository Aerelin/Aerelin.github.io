## 一、IO_FILE 介绍

### 1.1 什么是 FILE 结构

FILE 在 Linux 系统的标准 IO 库中是用于描述文件的结构，称为**文件流**。FILE 结构在程序执行 `fopen` 等函数时会进行创建，并分配在**堆**中。我们常定义一个指向 FILE 结构的指针来接收这个返回值。

```c
FILE *fp = fopen("test.txt", "r");
```

### 1.2 FILE 结构的存储位置

- 使用 `fopen` 创建的文件流分配在**堆内存**上。
- 程序启动时自动打开的三个文件流（stdin、stdout、stderr）位于 **libc.so 的数据段**中。

### 1.3 FILE 链表结构

进程中的 FILE 结构会通过 `_chain` 域彼此连接形成一个**链表**，链表头部用全局变量 `_IO_list_all` 表示。通过这个值我们可以遍历所有的 FILE 结构。

```
_IO_list_all -> FILE_1 -> FILE_2 -> FILE_3 -> ... -> NULL
                  ↑         ↑         ↑
               _chain    _chain    _chain
```

### 1.4 三个默认文件流

在标准 IO 库中，每个程序启动时有三个文件流是自动打开的：

| 文件流 | 说明 | libc.so 中的符号名 |
|--------|------|-------------------|
| `stdin` | 标准输入 | `_IO_2_1_stdin_` |
| `stdout` | 标准输出 | `_IO_2_1_stdout_` |
| `stderr` | 标准错误 | `_IO_2_1_stderr_` |

> **注意**：这三个文件流位于 libc.so 的数据段，而使用 `fopen` 创建的文件流是分配在堆内存上的。

我们可以在 libc.so 中找到 `stdin`、`stdout`、`stderr` 等符号，这些符号是指向 FILE 结构的指针，真正结构的符号是：

- `_IO_2_1_stderr_`
- `_IO_2_1_stdout_`
- `_IO_2_1_stdin_`

### 1.5 struct _IO_FILE 结构体详解

```c
struct _IO_FILE {
    int _flags;       /* High-order word is _IO_MAGIC; rest is flags. */
#define _IO_file_flags _flags

    /* The following pointers correspond to the C++ streambuf protocol. */
    /* Note: Tk uses the _IO_read_ptr and _IO_read_end fields directly. */
    char* _IO_read_ptr;   /* Current read pointer */
    char* _IO_read_end;   /* End of get area. */
    char* _IO_read_base;  /* Start of putback+get area. */
    char* _IO_write_base; /* Start of put area. */
    char* _IO_write_ptr;  /* Current put pointer. */
    char* _IO_write_end;  /* End of put area. */
    char* _IO_buf_base;   /* Start of reserve area. */
    char* _IO_buf_end;    /* End of reserve area. */

    /* The following fields are used to support backing up and undo. */
    char *_IO_save_base;  /* Pointer to start of non-current get area. */
    char *_IO_backup_base;/* Pointer to first valid character of backup area */
    char *_IO_save_end;   /* Pointer to end of non-current get area. */

    struct _IO_marker *_markers;

    struct _IO_FILE *_chain;

    int _fileno;
#if 0
    int _blksize;
#else
    int _flags2;
#endif
    _IO_off_t _old_offset; /* This used to be _offset but it's too small. */

#define __HAVE_COLUMN /* temporary */
    /* 1+column number of pbase(); 0 is unknown. */
    unsigned short _cur_column;
    signed char _vtable_offset;
    char _shortbuf[1];

    /* char* _save_gptr;  char* _save_egptr; */

    _IO_lock_t *_lock;
#ifdef _IO_USE_OLD_IO_FILE
};
```

### 1.6 重点关注字段

在 IO_FILE 结构体中，我们主要关注以下三部分：

#### 1. read、write、buf 相关指针

| 字段 | 含义 |
|------|------|
| `_IO_read_ptr` | 当前读指针（Current read pointer） |
| `_IO_read_end` | 读区域结束位置（End of get area） |
| `_IO_read_base` | 读区域起始位置（Start of putback+get area） |
| `_IO_write_base` | 写区域起始位置（Start of put area） |
| `_IO_write_ptr` | 当前写指针（Current put pointer） |
| `_IO_write_end` | 写区域结束位置（End of put area） |
| `_IO_buf_base` | 缓冲区起始位置（Start of reserve area） |
| `_IO_buf_end` | 缓冲区结束位置（End of reserve area） |

#### 2. _chain

`_chain` 指针用于将多个 FILE 结构链接成链表，通过 `_IO_list_all` 可以遍历所有 FILE 结构。

#### 3. fileno

`_fileno` 是文件描述符编号，用于标识对应的文件描述符（0=stdin, 1=stdout, 2=stderr）。

## 二、IO_FILE 利用

### 2.1 输出函数调用链

当调用 `puts` 等输出函数时，底层会经过以下调用链：

```
_IO_puts
  -> _IO_new_file_xsputn
    -> _IO_new_file_overflow
      -> new_do_write
        -> _IO_SYSWRITE
```

### 2.2 调用链详解

#### 第一层：`_IO_new_file_xsputn`

定义在 `libio/fileops.c` 中，负责将数据写入文件流。关键逻辑：

```c
_IO_size_t block_size, do_write;
/* Next flush the (full) buffer. */
if (_IO_OVERFLOW (f, EOF) == EOF)
    /* If nothing else has to be written we must not signal the
       caller that everything has been written.  */
    return to_do == 0 ? EOF : n - to_do;
```

该函数调用了 `_IO_OVERFLOW`。

#### 第二层：`_IO_new_file_overflow`

`_IO_OVERFLOW` 实际上是 `_IO_new_file_overflow`，同样定义在 `libio/fileops.c` 中。当 `ch == EOF` 时，会触发写入操作：

```c
if (ch == EOF)
    return _IO_do_write (f, f->_IO_write_base,
                         f->_IO_write_ptr - f->_IO_write_base);
```

最终进入 `_IO_do_write` 进行输出。

#### 第三层：`new_do_write`

`_IO_do_write` 实际上是 `new_do_write`，调用了 `_IO_SYSWRITE` 进行实际输出：

```c
count = _IO_SYSWRITE (fp, data, to_do);
if (fp->_cur_column && count)
    ...
```

#### 第四层：`_IO_SYSWRITE`

最终通过系统调用 `write()` 将数据输出到文件描述符。

### 2.3 利用原理

在 `overflow` 函数中，当 `ch == EOF` 时，会输出 `_IO_write_ptr` 到 `_IO_write_base` 区间的数据：

```c
if (ch == EOF)
    return _IO_do_write (f, f->_IO_write_base,
                         f->_IO_write_ptr - f->_IO_write_base);
```

**核心思路**：通过伪造 FILE 结构，控制 `_IO_write_base` 和 `_IO_write_ptr` 的值，可以实现：

1. **任意地址读取（leak）**：将 `_IO_write_base` 指向目标地址，`_IO_write_ptr` 指向目标地址 + 要读取的长度，即可泄露任意内存内容。
2. **任意地址写入**：通过控制写缓冲区指针，实现向任意地址写入数据。

### 2.4 关键条件控制

#### 条件一：`_IO_CURRENTLY_PUTTING = 1`

为了不让程序进入以下流程修改 `_IO_write_ptr` 与 `_IO_write_base`，需要设置 `_flags` 中的 `_IO_CURRENTLY_PUTTING` 位为 1：

```c
if ((f->_flags & _IO_CURRENTLY_PUTTING) == 0 || f->_IO_write_base == NULL)
{
    /* Allocate a buffer if needed. */
    if (f->_IO_write_base == NULL)
    {
        _IO_doallocbuf (f);
        _IO_setg (f, f->_IO_buf_base, f->_IO_buf_base, f->_IO_buf_base);
    }
    /* Otherwise must be currently reading.
       If _IO_read_ptr (and hence also _IO_read_end) is at the buffer end,
       implicitly slide the buffer forward to make some room for the put area. */
    if (_IO_in_put_mode (f))
    {
        if (_IO_in_backup (f))
        {
            size_t nbackup = f->_IO_read_end - f->_IO_read_ptr;
            _IO_free_backup_area (f);
            f->_IO_read_base -= MIN (nbackup,
                                     f->_IO_read_base - f->_IO_buf_base);
            f->_IO_read_ptr = f->_IO_read_end;
        }
        ...
    }
}
```

设置 `_IO_CURRENTLY_PUTTING = 1` 可以跳过上述缓冲区分配和指针调整逻辑，使伪造的指针值不被覆盖。

#### 条件二：`_IO_NO_WRITES = 0`

需要控制 `_IO_NO_WRITES = 0`，否则会什么都不输出：

```c
if (f->_flags & _IO_NO_WRITES) /* SET ERROR */
{
    f->_flags |= _IO_ERR_SEEN;
    set_errno (EBADF);
    return EOF;
}
```

如果 `_IO_NO_WRITES` 标志位被设置，函数会直接返回 EOF，不会执行任何写入操作。

## 三、总结

### 关键知识点回顾

| 知识点 | 内容 |
|--------|------|
| FILE 结构位置 | fopen 创建的在堆上；stdin/stdout/stderr 在 libc 数据段 |
| FILE 链表 | 通过 `_chain` 链接，头节点为 `_IO_list_all` |
| 输出调用链 | `_IO_puts -> _IO_new_file_xsputn -> _IO_new_file_overflow -> new_do_write -> _IO_SYSWRITE` |
| 泄露原理 | 控制 `_IO_write_base` 和 `_IO_write_ptr` 实现任意地址读取 |
| 关键标志位 | `_IO_CURRENTLY_PUTTING = 1`，`_IO_NO_WRITES = 0` |

### 学习建议

1. **理解结构体布局**：熟悉 `struct _IO_FILE` 各字段的含义和偏移。
2. **跟踪调用链**：通过源码（glibc 的 `libio/fileops.c`）跟踪输出函数的完整调用链。
3. **实践利用**：在 CTF 题目中练习伪造 FILE 结构，控制指针实现 leak 或 write。
4. **结合堆漏洞**：IO_FILE 利用通常需要先通过堆漏洞（如 UAF、Double Free）获得对 FILE 结构的写能力。
