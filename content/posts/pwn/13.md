## 二、格式化字符串的位置区别

### 2.1 printf 函数源码分析

`printf` 函数的核心实现如下：

```c
__printf(const char *format, ...)
{
    va_list arg;
    int done;

    va_start(arg, format);
    done = vfprintf(stdout, format, arg);
    va_end(arg);

    return done;
}
```

**关键要点：**

- `printf` 函数的参数是 `format`，类型是一个 `char *` 指针。
- `vfprintf` 负责实际的格式化输出工作，它从 `format` 指针读取格式化字符串，从 `arg` 中读取可变参数。

### 2.2 格式化字符串在栈上 vs 不在栈上

#### 情况一：格式化字符串保存在栈上（常见情况）

大部分情况下，格式化字符串漏洞的格式化字符串都是**保存在栈上**的。此时可以通过 `%x`、`%p` 等格式符直接读取栈上的内容，也可以通过 `%n`、`%hn`、`%hhn` 等实现任意地址写。

#### 情况二：格式化字符串不在栈上

有时格式化字符串**并未保存在栈上**，而是保存在以下位置：

- **`.bss` 段**：未初始化的全局变量或静态变量存储区域
- **堆（Heap）**：通过 `malloc` 等函数动态分配的内存

**影响：**

> 这些地址在栈上通过参数是无法访问到的，也就是说前面所讲的格式化字符串漏洞的利用方法很多就无法使用了。

当格式化字符串不在栈上时，传统的利用方式（如直接通过偏移访问格式化字符串本身）会失效，需要采用更复杂的利用链。

### 2.3 两种情况的栈布局对比

#### 在栈上的情况

| 偏移地址 | 存储内容 | 说明 |
|----------|----------|------|
| `0x0`  | `0x1c`   | 某个参数值 |
| `0x4`  | `0x1234` | 某个参数值 |
| `0x8`  | `0x2121` | 某个参数值 |
| `0xc`  | `0x3332` | 某个参数值 |
| `0x10` | `0x4441` | 某个参数值 |
| `0x14` | `0x1235` | 某个参数值 |
| `0x18` | `0x3131` | 某个参数值 |
| `0x1c` | `%3$p`   | **格式化字符串本身就在栈上**，可通过 `%3$p` 直接引用 |

#### 不在栈上的情况

| 偏移地址 | 存储内容 | 说明 |
|----------|----------|------|
| `0x0`  | `0x801020a0` | 指向 `.bss` 段或堆中格式化字符串的指针 |
| `0x4`  | `0x1234` | 某个参数值 |
| `0x8`  | `0x2121` | 某个参数值 |
| `0xc`  | `0x3332` | 某个参数值 |
| `0x10` | `0x4441` | 某个参数值 |
| `0x14` | `0x1235` | 某个参数值 |
| `0x18` | `0x3131` | 某个参数值 |
| `0x1c` | `0x4141` | 普通数据 |

**`.bss` 段 / 堆中的格式化字符串：**

| 地址 | 内容 |
|------|------|
| `0x801020a0` | `%3$p`（格式化字符串存放在此） |

**核心区别：** 当格式化字符串不在栈上时，栈上 `0x1c` 处存放的不再是格式化字符串本身，而是一个指向外部存储区域的指针（如 `0x801020a0`）。这意味着无法通过简单的偏移量直接操控格式化字符串的内容。

## 三、利用方法

### 3.1 核心思路：地址链构造

当格式化字符串不在栈上时，需要构造一条**地址链**来实现任意地址写。

#### 地址链模型

```
p1 -> p2 -> p3 -> p4（目标地址）
```

其中：

| 节点 | 说明 |
|------|------|
| `p4` | **目标地址**，最终要写入数据的地址 |
| `p1` | 栈上的地址，其中存放 `p2` 的值 |
| `p2` | 栈上的地址，其中存放 `p3` 的值 |
| `p3` | 栈上的地址，其中存放 `p4` 的值 |

#### 利用步骤

1. **通过 `p1` 更改 `p2` 的低地址**，使其指向 `p3`
2. **通过 `p2` 更改 `p3` 的值**，使其指向 `p4`
3. **通过 `p3` 修改 `p4` 的值**，完成任意地址写

### 3.2 利用 ebp/rbp 链实现任意地址写

如果有嵌套的函数调用，栈上就会留存一个 **ebp/rbp 链**，它们都是栈地址。通过多次利用这里残留的栈地址，就可以做到任意地址写。

**过程简述：**

```
p4 是目标地址
p1 中存放 p2
p2 中存放 p3
通过 p1 更改 p2 的低地址使其指向 p3
通过 p2 更改 p3 的值，使其指向 p4
通过 p3 修改 p4 的值
```

即构造以下地址链：

```
p1 -> p2 -> p3 -> p4
```

**原理说明：**

- 每次函数调用时，旧的 `ebp`（32位）或 `rbp`（64位）会被压入栈中，形成一条链表。
- 这条链上的每个值都是栈地址，可以被格式化字符串的 `%n` 系列格式符修改。
- 通过逐跳修改，最终可以将写入目标扩展到任意地址。

### 3.3 栈内存布局实例

以下是一个实际的栈内存布局示例（64位系统）：

| 地址 | 内容 | 说明 |
|------|------|------|
| `0x7fffffffddc70` | `0x1` | 函数参数 |
| `0x7fffffffddc78` | `0x7fffffffddc88` | **ebp/rbp 链**，指向下一个栈帧 |
| `0x7fffffffddc80` | `0x1` | 函数参数 |
| `0x7fffffffddc88` | `0x7fffffffdddf6` | **ebp/rbp 链**，继续链接 |
| `0x7fffffffddc90` | `0x7fff7ffe168` | 其他栈数据 |
| `......` | `......` | `......` |
| `0x7fffffffddd8` | `string` | 字符串数据 |
| `0x7fffffffe190` | `string` | 字符串数据 |

**观察要点：**

- `0x7fffffffddc78` 处存放的值 `0x7fffffffddc88` 是一个栈地址，指向栈上另一个位置。
- `0x7fffffffddc88` 处存放的值 `0x7fffffffdddf6` 同样是一个栈地址。
- 这些地址构成了 ebp/rbp 链，可以作为地址链利用的跳板。

## 四、关键注意事项

### 4.1 需要多次格式化字符串漏洞

> **需要存在多次格式化字符串漏洞**，因为 `printf` 在解析格式化字符串的时候，对于 `%n`、`%hhn`、`%hn` 之类的地址覆写，是**同时进行的**而不是按从前向后解析。

### 4.2 不能在同一次 payload 中完成全部操作

由于上述原因，**不能够将以下操作放入同一次 payload 当中使用**：

| 操作 | 说明 |
|------|------|
| `p4` 是目标地址 | 最终写入目标 |
| `p1` 中存放 `p2` | 第一跳 |
| `p2` 中存放 `p3` | 第二跳 |
| 通过 `p1` 更改 `p2` 的低地址使其指向 `p3` | 修改第一跳 |
| 通过 `p2` 更改 `p3` 的值 | 修改第二跳 |

**正确做法：** 分多次利用，每次利用一次格式化字符串漏洞，逐步推进地址链的修改。

### 4.3 利用顺序

典型的利用顺序为：

1. **第一次利用**：通过 `p1` 修改 `p2` 的低字节，使 `p2` 指向 `p3`
2. **第二次利用**：通过 `p2`（现已指向 `p3`）修改 `p3` 的值，使 `p3` 指向 `p4`
3. **第三次利用**：通过 `p3`（现已指向 `p4`）修改 `p4` 的值，完成任意地址写

## 五、Demo 演示思路

### 5.1 实验环境准备

- 编译一个存在格式化字符串漏洞的 C 程序
- 关闭 ASLR（或已知地址）以便演示
- 确认格式化字符串不在栈上（如存放在 `.bss` 段）

### 5.2 演示步骤

1. **信息泄露**：使用 `%p` 或 `%x` 泄露栈上的 ebp/rbp 链地址
2. **构造地址链**：计算 `p1`、`p2`、`p3`、`p4` 的具体地址
3. **第一次写入**：修改 `p2` 的低字节，使其指向 `p3`
4. **第二次写入**：修改 `p3` 的值，使其指向 `p4`
5. **第三次写入**：通过 `p3` 向 `p4` 写入目标值（如 shellcode 地址或 GOT 表项）
6. **验证结果**：检查目标地址是否被成功修改

### 5.3 常用格式符回顾

| 格式符 | 作用 | 写入字节数 |
|--------|------|-----------|
| `%n`   | 将已输出字符数写入 4 字节地址 | 4 字节 |
| `%hn`  | 将已输出字符数写入 2 字节地址 | 2 字节 |
| `%hhn` | 将已输出字符数写入 1 字节地址 | 1 字节 |

**建议：** 在 64 位系统中优先使用 `%hhn` 逐字节写入，以减少需要输出的字符数量，避免 payload 过长。

## 附录：术语表

| 术语 | 说明 |
|------|------|
| **格式化字符串漏洞** | 用户输入的字符串被直接作为 `printf` 等函数的 format 参数，导致信息泄露或任意地址写 |
| **`.bss` 段** | 存放未初始化的全局变量和静态变量的内存区域 |
| **ebp/rbp 链** | 嵌套函数调用时，栈上保存的旧栈帧指针形成的链表 |
| **任意地址写** | 通过漏洞向内存中任意指定地址写入数据的能力 |
| **GOT 表** | Global Offset Table，全局偏移表，存放外部函数的实际地址 |
| **ASLR** | Address Space Layout Randomization，地址空间布局随机化 |
