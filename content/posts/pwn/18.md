## 一、fastbin 介绍

### 1.1 为什么需要 fastbin

大多数程序经常会申请以及释放一些比较小的内存块。如果将一些较小的 chunk 释放之后发现存在与之相邻的空闲 chunk 并将它们进行合并，那么当下一次再次申请相应大小的 chunk 时，就需要对 chunk 进行分割，这样就大大降低了堆的利用效率。因为我们把大部分时间花在了合并、分割以及中间检查的过程中。

因此，ptmalloc 中专门设计了 **fast bin**，对应的变量就是 `malloc_state` 中的 `fastbinsY`。

> **核心思想**：对于频繁申请和释放的小内存块，跳过合并/分割流程，直接缓存起来快速复用，从而提升堆的利用效率。

### 1.2 fastbin 的数据结构

在 glibc 源码中，fastbin 的定义如下：

```c
/*
  Fastbins

  An array of lists holding recently freed small chunks.  Fastbins
  are not doubly linked.  It is faster to single-link them, and
  since chunks are never removed from the middles of these lists,
  double linking is not necessary.  Also, unlike regular bins, they
  are not even processed in FIFO order (they use faster LIFO) since
  ordering doesn't much matter in the transient contexts in which
  fastbins are normally used.

  Chunks in fastbins keep their inuse bit set, so they cannot
  be consolidated with other free chunks. malloc_consolidate
  releases all chunks in fastbins and consolidates them with
  other free chunks.
*/
typedef struct malloc_chunk *mfastbinptr;

/*
  This is in malloc_state.
  /* Fastbins */
  mfastbinptr fastbinsY[ NFASTBINS ];
*/
```

**要点解读**：

| 特性 | 说明 |
|------|------|
| 单链表 | fastbin 使用单链表而非双链表，因为 chunk 不会从链表中间移除，单链表更快 |
| LIFO 策略 | 采用后进先出（LIFO）而非先进先出（FIFO），因为顺序在快速分配场景中不太重要 |
| inuse 位保持 | fastbin 中的 chunk 保持 inuse 位为 1，因此不会与其他空闲 chunk 合并 |
| 合并时机 | `malloc_consolidate` 会释放 fastbins 中的所有 chunk 并将它们与其他空闲 chunk 合并 |

### 1.3 fastbin 的组织方式

为了更加高效地利用 fast bin，glibc 采用**单向链表**对其中的每个 bin 进行组织，并且每个 bin 采取 **LIFO（后进先出）策略**——最近释放的 chunk 会更早地被分配，因此更加适合于局部性。

**分配流程**：当用户需要的 chunk 的大小小于 fastbin 的最大大小时，ptmalloc 会首先判断 fastbin 中相应的 bin 中是否有对应大小的空闲块：
- 如果有，就直接从这个 bin 中获取 chunk
- 如果没有，ptmalloc 才会做接下来的一系列操作（如从 unsorted bin 中获取、分割等）

**malloc 从 fastbin 获取 chunk 的核心代码**：

```c
if ((unsigned long) (nb) <= (unsigned long) (get_max_fast ()))
{
    idx = fastbin_index (nb);
    mfastbinptr *fb = &fastbin (av, idx);
    mchunkptr pp = *fb;
    do
    {
        victim = pp;
        if (victim == NULL)
            break;
    }
    while ((pp = catomic_compare_and_exchange_val_acq (fb, victim->fd, victim)));

    if (victim != 0)
    {
        if (__builtin_expect (fastbin_index (chunksize (victim)) != idx, 0))
        {
            errstr = "malloc(): memory corruption (fast)";
        errout:
            malloc_printerr (check_action, errstr, chunk2mem (victim), av);
            return NULL;
        }
        check_remalloced_chunk (av, victim, nb);
        void *p = chunk2mem (victim);
        alloc_perturb (p, bytes);
        return p;
    }
}
```

**代码逻辑分析**：

1. 首先判断请求大小 `nb` 是否小于等于 fastbin 的最大大小（`get_max_fast()`）
2. 计算对应的 fastbin 索引 `idx = fastbin_index(nb)`
3. 获取对应 fastbin 链表的头指针 `*fb`
4. 使用 CAS（Compare-And-Swap）原子操作从链表头部取出 chunk
5. 验证取出的 chunk 的 size 是否与索引匹配（防止 corruption）
6. 通过 `chunk2mem` 将 chunk 指针转换为用户指针并返回

### 1.4 fastbin 的大小范围

在 **64 位程序**中，fastbin 的范围是 **0x20 ~ 0x80**，以 **0x10** 为单位存储在 `fastbinY` 数组中。

| fastbin 索引 | chunk 大小（含 header） | 用户可用大小 |
|:---:|:---:|:---:|
| 0 | 0x20 | 0x10 |
| 1 | 0x30 | 0x20 |
| 2 | 0x40 | 0x30 |
| 3 | 0x50 | 0x40 |
| 4 | 0x60 | 0x50 |
| 5 | 0x70 | 0x60 |
| 6 | 0x80 | 0x70 |

> **注意**：chunk 大小包含 16 字节的 chunk header（prev_size + size），因此用户实际可用大小 = chunk 大小 - 0x10。

**pwngdb 查看 fastbin 示例**：

```
pwngdb> bins
fastbins
0x20: 0x0
0x30: 0x602080  <-- 0x0
0x40: 0x602060  <-- 0x0
0x50: 0x0
0x60: 0x0
0x70: 0x0
0x80: 0x0
unsortedbin
all: 0x0
smallbins
empty
largebins
empty
```

从输出可以看到：
- `0x30` 大小的 fastbin 链表中有一个 chunk，地址为 `0x602080`，其 fd 指向 `0x0`（链表尾部）
- `0x40` 大小的 fastbin 链表中有一个 chunk，地址为 `0x602060`，其 fd 指向 `0x0`

## 二、fastbin attack 利用

### 2.1 利用前提

fastbin attack 是一类漏洞的利用方法，是指所有基于 fastbin 机制的漏洞利用方法。这类利用的前提是：

1. **存在堆溢出、use-after-free 等能控制 chunk 内容的漏洞**
2. **漏洞发生于 fastbin 类型的 chunk 中**（即 chunk 大小在 0x20 ~ 0x80 范围内）

### 2.2 攻击分类

如果细分的话，fastbin attack 可以做如下的分类：

| 攻击类型 | 核心思路 |
|---------|---------|
| **Fastbin Double Free** | 利用 free 函数多次释放同一个 chunk，在 fastbin 链表中形成循环，再通过修改 fd 指针实现任意地址分配 |
| **House of Spirit** | 在目标位置伪造 fastbin chunk 并释放，使 malloc 分配到指定地址的 chunk |
| **Arbitrary Alloc** | 故意修改 fd 指针，直接利用 malloc 申请指定位置的 chunk 进行攻击 |

**分类说明**：
- **前两种**（Fastbin Double Free、House of Spirit）主要侧重于利用 `free` 函数释放**真的 chunk 或伪造的 chunk**，然后再次申请 chunk 进行攻击
- **后一种**（Arbitrary Alloc）侧重于故意修改 fd 指针，直接利用 `malloc` 申请指定位置 chunk 进行攻击

### 2.3 fastbin attack 存在的根本原因

fastbin attack 存在的原因在于：

1. **fastbin 使用单链表来维护释放的堆块**
2. **由 fastbin 管理的 chunk 即使被释放，其 next_chunk 的 prev_inuse 位也不会被清空**

prev_inuse 位不会被清空也就意味着一般情况下 fastbin 不会进行 unlink 合并。

> **关键理解**：普通 bin（如 unsorted bin、small bin、large bin）中的 chunk 被释放时会清空相邻 chunk 的 prev_inuse 位，从而可能触发合并。而 fastbin 中的 chunk 保持 inuse 位为 1，跳过了合并检查，这正是 fastbin 高效的原因，但也成为了安全漏洞的根源。

### 2.4 Fastbin Double Free

#### 2.4.1 原理

Fastbin Double Free 是指 fastbin 的 chunk 可以被多次释放，因此可以在 fastbin 链表中存在多次。这样导致的后果是多次分配可以从 fastbin 链表中取出同一个堆块，相当于多个指针指向同一个堆块，导致可能可以控制已 free 的堆块。

#### 2.4.2 能够成功利用的原因

Fastbin Double Free 能够成功利用主要有两部分的原因：

1. **fastbin 的堆块被释放后 next_chunk 的 prev_inuse 位不会被清空**
   - 这意味着不会触发与相邻 chunk 的合并检查

2. **fastbin 在执行 free 的时候仅验证了 main_arena 直接指向的块，即链表指针头部的块**
   - 对于链表后面的块，并没有进行验证

**glibc 源码中的 double free 检查**：

```c
/* Check that the top of the bin is not the record we are going to add
   (i.e., double free).  */
if (__builtin_expect (old == p, 0))
{
    errstr = "double free or corruption (fasttop)";
    goto errout;
}
```

这段代码说明：**free 操作只检查要释放的 chunk 是否是 fastbin 链表的头部（top）**。如果不是头部，就不会触发 double free 检测。

#### 2.4.3 绕过方法

如果我们连续 free 两次 chunk1 的话，就会触发该处报错，抛出一个错误。

但如果我们在 chunk1 释放后，再释放 chunk2，这样 main_arena 就指向 chunk2 而不是 chunk1 了，此时我们再去释放 chunk1 就不再会被检测到。

**绕过步骤**：

```
步骤1: free(chunk1)    → fastbin: chunk1 → NULL
步骤2: free(chunk2)    → fastbin: chunk2 → chunk1 → NULL
步骤3: free(chunk1)    → fastbin: chunk1 → chunk2 → chunk1 → NULL (循环链表!)
```

**链表结构图示**：

```
main_arena → chunk1 → chunk2 → chunk1 → ...（循环）
```

#### 2.4.4 利用效果

此时分配 chunk1 后，对其进行 fd 进行修改，就可以造成任意位置分配 chunk，造成这样一条链：

```
main_arena → chunk2 → chunk1 → target_address
```

**完整利用流程**：

1. 分配 chunk1 和 chunk2（大小相同，属于同一个 fastbin）
2. `free(chunk1)` — chunk1 进入 fastbin 链表头部
3. `free(chunk2)` — chunk2 成为新的头部，chunk1 在链表中
4. `free(chunk1)` — 绕过检测（因为头部是 chunk2 而非 chunk1），chunk1 再次进入链表
5. `malloc()` — 取出 chunk1，此时可以修改 chunk1 的 fd 指针
6. `malloc()` — 取出 chunk2
7. `malloc()` — 取出 chunk1（第二次），修改其 fd 指向目标地址
8. `malloc()` — 从目标地址分配 chunk，实现任意地址写入

### 2.5 House of Spirit

#### 2.5.1 原理

该技术的核心在于在**目标位置处伪造 fastbin chunk**，并将其释放，从而达到分配指定地址的 chunk 的目的。

#### 2.5.2 构造 fake chunk 的要求

要想构造 fastbin fake chunk，并且将其释放时，可以将其放入到对应的 fastbin 链表中，需要绕过一些必要的检测：

| 检测项 | 要求 | 原因 |
|--------|------|------|
| **ISMMAP 位** | 不能为 1 | free 时，如果是 mmap 的 chunk，会单独处理，不会进入 fastbin |
| **size 大小** | 需要满足对应的 fastbin 的需求 | malloc 分配时会验证 chunk size 与 fastbin 索引是否匹配 |
| **next chunk 的大小** | 应该合法 | free 时会检查下一个 chunk 的 size 是否合理 |

#### 2.5.3 关键要点

想要使用该技术分配 chunk 到指定地址，其实**并不需要修改指定地址的任何内容**，关键是要能够修改指定地址的**前后的内容**使其可以绕过对应的检测。

> **实践提示**：这个方法一般配合 chunk extend 共同使用构造出 overlap。通过堆溢出扩大前一个 chunk 的边界，使其覆盖到目标区域，然后在目标区域伪造符合 fastbin 要求的 chunk 结构。

#### 2.5.4 利用步骤

1. 在目标地址附近构造一个符合 fastbin 要求的 fake chunk
   - 设置正确的 size（在 0x20~0x80 范围内，且与目标 fastbin 索引匹配）
   - 确保 ISMMAP 位为 0
   - 确保 fake chunk 的下一个 chunk 的 size 合法
2. 通过漏洞（如堆溢出）控制指向 fake chunk 的指针
3. `free(fake_chunk_ptr)` — 将伪造的 chunk 释放到 fastbin 中
4. `malloc(size)` — 从 fastbin 中分配，获得指向目标地址的 chunk
5. 对目标地址进行读写操作

### 2.6 Arbitrary Alloc

#### 2.6.1 原理

Arbitrary Alloc 侧重于**故意修改 fd 指针**，直接利用 malloc 申请指定位置的 chunk 进行攻击。

#### 2.6.2 与 Double Free 的关系

Arbitrary Alloc 通常与 Fastbin Double Free 配合使用：

1. 通过 Double Free 使同一个 chunk 在 fastbin 链表中出现多次
2. 从 fastbin 中取出该 chunk 后，修改其 fd 指针指向目标地址（target_address）
3. 目标地址处需要满足 fastbin 的 size 检查（即 target_address 处的值对应的 chunk size 需要与当前 fastbin 索引匹配）
4. 后续 `malloc` 调用会从目标地址分配 chunk

#### 2.6.3 利用条件

- 能够控制 fastbin 中 chunk 的 fd 指针内容（通过 UAF 或堆溢出）
- 目标地址 - 0x10 处（chunk header 的 size 字段位置）的值需要满足 fastbin 的 size 要求
- 目标地址处的 next chunk 的 size 也需要合法

## 三、总结与对比

### 3.1 三种攻击方式对比

| 特性 | Fastbin Double Free | House of Spirit | Arbitrary Alloc |
|------|-------------------|-----------------|-----------------|
| **核心操作** | 多次 free 同一 chunk | free 伪造的 chunk | 修改 fd 指针 |
| **主要函数** | free + malloc | free + malloc | malloc |
| **需要伪造 chunk** | 否 | 是 | 否（但目标地址需满足 size 检查） |
| **利用难度** | 中等 | 较高 | 中等 |
| **常见配合技术** | Arbitrary Alloc | chunk extend / overlap | Fastbin Double Free |

### 3.2 防护机制

现代 glibc 引入了以下防护机制来缓解 fastbin attack：

| 防护机制 | 说明 |
|---------|------|
| **tcache** | glibc 2.26+ 引入 tcache，优先于 fastbin 使用，改变了小 chunk 的分配逻辑 |
| **fastbin double free 检测** | 检查要 free 的 chunk 是否是 fastbin 链表头部 |
| **size 验证** | malloc 从 fastbin 取出 chunk 时验证 size 是否与索引匹配 |
| **safe-linking** | glibc 2.32+ 引入，对链表指针进行加密，防止直接篡改 fd 指针 |

### 3.3 学习建议

1. **理解基础**：先掌握堆的基本结构（chunk header、prev_size、size、fd、bk）和 ptmalloc 的整体架构
2. **动手实践**：使用 pwngdb、heapdump 等工具实际观察 fastbin 的链表结构变化
3. **源码阅读**：结合 glibc 源码（`malloc.c`）理解每个检测点的具体逻辑
4. **CTF 练习**：通过实际 CTF 题目（如 hitcon-training 的 lab 系列）巩固 fastbin attack 的利用技巧
5. **关注新版本**：了解 tcache 和 safe-linking 等新机制对 fastbin attack 的影响及绕过方法

## 四、关键术语表

| 术语 | 含义 |
|------|------|
| **chunk** | 堆内存的基本管理单元，包含 header 和用户数据 |
| **fastbin** | ptmalloc 中用于缓存小尺寸空闲 chunk 的快速分配机制 |
| **fastbinY** | malloc_state 中存储 fastbin 链表头指针的数组 |
| **LIFO** | Last In First Out，后进先出，fastbin 的分配策略 |
| **fd 指针** | free chunk 中指向链表中下一个 chunk 的指针 |
| **prev_inuse** | chunk header 中标志前一个 chunk 是否在使用中的位 |
| **ISMMAP** | chunk header 中标志该 chunk 是否由 mmap 分配的位 |
| **unlink** | 将 chunk 从 bin 链表中移除并可能与相邻 chunk 合并的操作 |
| **fake chunk** | 攻击者在指定内存位置伪造的符合 chunk 结构的数据 |
| **UAF** | Use-After-Free，释放后使用漏洞 |
| **CAS** | Compare-And-Swap，原子操作，用于线程安全的链表操作 |
| **main_arena** | glibc 中管理主堆区的数据结构 |
| **malloc_consolidate** | 将 fastbin 中的 chunk 合并到其他 bin 的函数 |
