## 一、前置知识

### 1.1 off-by-null 漏洞概述

**off-by-null** 漏洞是 **off-by-one** 的一种特殊形式。off-by-one 指的是程序在写入数据时多写了一个字节，而 off-by-null 特指多写了一个 **NULL 字节（`\x00`）**。

一般认为 off-by-null 的利用十分困难，但由于 ptmalloc 的分配机制，仍然可以对其进行有效利用。本文介绍两种利用方式：

| 利用方式 | 核心思路 |
|---------|---------|
| **Chunk Shrink** | 利用 off-by-null 使 chunk 缩小，再利用 unlink 构造出 chunk overlap |
| **House of Einherjar** | 利用 off-by-null 修改 prev_size 和 PREV_INUSE 位，强制 malloc 返回几乎任意地址的 chunk |

### 1.2 ptmalloc 堆块结构回顾

每个堆块（chunk）的头部结构如下：

```
+------------------+
|    prev_size     |  8 bytes (前一个 chunk 的大小，仅当前一个 chunk 为 free 时有效)
+------------------+
|      size        |  8 bytes (当前 chunk 的大小，低3位为标志位)
+------------------+
|      fd          |  8 bytes (free chunk 时指向下一个 free chunk)
+------------------+
|      bk          |  8 bytes (free chunk 时指向上一个 free chunk)
+------------------+
|    user data     |  ... (用户数据区域)
+------------------+
```

**size 字段的低 3 位标志：**

| 位 | 名称 | 含义 |
|---|------|------|
| bit 0 | PREV_INUSE | 前一个 chunk 是否在使用中（1=使用中，0=已释放） |
| bit 1 | IS_MMAPPED | 是否通过 mmap 分配 |
| bit 2 | NON_MAIN_ARENA | 是否属于非主分配区 |

**关键宏定义：**

```c
// 根据当前 chunk 指针和偏移量获取下一个 chunk
#define chunk_at_offset(p, s) ((mchunkptr)(((char *)(p)) + (s)))

// 获取下一个 chunk（通过当前 chunk 的 size 字段）
#define next_chunk(p) chunk_at_offset(p, chunksize(p))

// 获取前一个 chunk（通过下一个 chunk 的 prev_size 字段）
#define prev_chunk(p) chunk_at_offset(p, -(long)(prev_size(p)))
```

### 1.3 unlink 机制与限制

当一个 free chunk 与其相邻的 free chunk 合并时，会触发 **unlink** 操作，将该 chunk 从双向链表中摘除。

**unlink 的安全检查（glibc 2.23+）：**

```c
if (__builtin_expect(chunksize(P) != (next_chunk(P))->prev_size, 0))
    malloc_printerr(check_action, "corrupted size vs. prev_size", P, AV);
```

即要求：
```
chunk_size(P) == next_chunk(P)->prev_size
```

**双向链表完整性检查：**

```c
FD = P->fd;
BK = P->bk;
if (__builtin_expect(FD->bk != P || BK->fd != P, 0))
    malloc_printerr(check_action, "corrupted double-linked list", P, AV);
```

即要求：
```
FD->bk == P  且  BK->fd == P
```

### 1.4 unsorted bin 与 small bin 的分割机制

**small bin 范围内的 chunk 在合并时**，其上一 chunk 是根据当前 chunk 的 **prev_size** 决定的。

在一般情况下，unsorted bin 在分割时，会将下一 chunk 的 **prev_size** 一同更新：

```c
remainder_size = size - nb;
remainder = chunk_at_offset(victim, nb);

set_foot(remainder, remainder_size);
```

其中 `set_foot` 宏定义为：

```c
#define set_foot(p, s) (((mchunkptr)((char *)(p) + (s)))->prev_size = (s))
```

展开后等价于：

```c
(((mchunkptr)((char *)(remainder) + (remainder_size)))->prev_size = (remainder_size))
```

> **关键点：** 这段代码的含义是——将 remainder 之后的那个 chunk 的 prev_size 设置为 remainder_size，从而维护堆块之间的 prev_size 一致性。

## 二、Chunk Shrink

### 2.1 核心原理

Chunk Shrink 的核心思路是利用 **off-by-null** 漏洞将一个 chunk 的 **size 字段缩小**，使得 ptmalloc 在寻找下一个 chunk 时基于被篡改的 size 进行计算，从而跳过对下一 chunk 的 **prev_size** 和 **PREV_INUSE** 位的修改。随后通过 free 操作触发合并，构造出 **chunk overlap**。

### 2.2 ptmalloc 中 next chunk 的定位方式

**重要区别：** ptmalloc 中是根据当前 chunk 的 **size** 来寻找下一个 chunk 的，而不是根据下一 chunk 的 prev_size。

```c
#define chunk_at_offset(p, s) ((mchunkptr)(((char *)(p)) + (s)))
```

展开后：

```c
((mchunkptr)(((char *)(victim)) + (nb)))
```

这意味着：

- 通过 off-by-null 漏洞将 chunk 的 size 修改小之后，ptmalloc 在计算 next chunk 时会基于**被缩小后的 size** 进行偏移
- 因此**不会对下一 chunk 的 prev_size 与 PREV_INUSE 进行修改**
- 此时通过 free 下一 chunk，就能将两个 chunk 合并后放入 unsorted bin，构造出 **chunk overlap**

### 2.3 利用限制与绕过方法

Chunk Shrink 的利用需要绕过以下限制：

#### 限制一：伪造 prev_size

要对 shrink 后的 chunk 的下一 chunk 位置**伪造一个 prev_size**。

chunk 首次进入 unsorted bin 时，`last_remainder = 0`，不能够直接进行切割，会进入 **small bin** 中。而在从 small bin 中取出时，会用到 unlink，在 unlink 中就有以下限制：

```c
if (__builtin_expect(chunksize(P) != (next_chunk(P))->prev_size, 0))
    malloc_printerr(check_action, "corrupted size vs. prev_size", P, AV);
```

要求 `chunk_size == nextchunk_prevsize`。

#### 限制二：再次触发 unlink 检查

为了构造 chunk overlap，我们需要在原 chunk 的位置再分配出一个 chunk，然后将这个 chunk 与下一 chunk 进行合并。而这时又会进到 unlink 过程中，仍会有 `chunksize == nextchunk_prevsize` 的需求。

**最终构造的效果应该如下：**

```
chunk1 | chunk2 | chunk3
```

执行 `free(chunk3)` 使 chunk1、chunk2、chunk3 全部合并。

#### 绕过方法

为了满足要求，在申请出 chunk1、chunk2 后，**再将 chunk1 释放掉**，这样就会在 chunk2 的位置写入 chunk1 的 size，从而绕过限制。

原理：当 chunk1 被 free 后，chunk2 的 prev_size 字段会被写入 chunk1 的 size 值，同时 PREV_INUSE 位被清除。这样在后续操作中，unlink 检查就能通过。

### 2.4 完整利用流程

```
步骤 1: 申请 3 个 chunk
        - 第一个 chunk 用于触发 off-by-null
        - 第 2、3 个 chunk 大小均大于 0x100（进入 unsorted bin 范围）

步骤 2: 在 chunk2 中布置好 fake_prev_size
        - free(chunk2)
        - 利用 chunk1 触发 off-by-null 使 chunk2 的 size 缩小

步骤 3: 再申请两个 chunk
        - 将 unsorted bin 清空

步骤 4: free 二次申请的第一个 chunk
        - 构造好 prev_size

步骤 5: free(chunk3)
        - 使 chunk2 -> chunk3 之间的内存全部合并
        - 构造出 chunk overlap
```

### 2.5 利用流程图

```
初始状态:
┌──────────┬──────────┬──────────┬──────────┐
│  chunk1  │  chunk2  │  chunk3  │  chunk4  │
│ (small)  │ (>0x100) │ (>0x100) │ (guard)  │
└──────────┴──────────┴──────────┴──────────┘

Step 1: 在 chunk2 中布置 fake_prev_size
┌──────────┬──────────────────────────┬──────────┬──────────┐
│  chunk1  │  chunk2 (含 fake_prev)   │  chunk3  │  chunk4  │
└──────────┴──────────────────────────┴──────────┴──────────

Step 2: free(chunk2) → chunk2 进入 unsorted bin
┌──────────┬──────────────────────────┬──────────┬──────────┐
│  chunk1  │  chunk2 (free, unsorted) │  chunk3  │  chunk4  │
└──────────┴──────────────────────────┴──────────┴──────────┘

Step 3: 利用 chunk1 触发 off-by-null → chunk2.size 缩小
┌──────────┬─────────────┬──────────┬──────────┐
│  chunk1  │ chunk2(shrunk)│  chunk3 │  chunk4  │
│          │             │← 间隙 →  │          │
└──────────┴─────────────┴──────────┴──────────┘

Step 4: 再申请两个 chunk 清空 unsorted bin
┌──────────┬─────────────┬──────────┬──────────┬──────────┬──────────┐
│  chunk1  │ chunk2(shrunk)│  chunk3 │  new_A   │  new_B   │  chunk4  │
└──────────┴─────────────┴──────────┴──────────┴──────────┴──────────┘

Step 5: free(new_A) → 构造好 prev_size
Step 6: free(chunk3) → chunk2 + chunk3 + new_A 全部合并 → chunk overlap!
──────────┬─────────────────────────────────────┬──────────┐
│  chunk1  │     chunk overlap 区域               │  chunk4  │

```

## 三、House of Einherjar

### 3.1 技术背景

**House of Einherjar** 是一种堆利用技术，由 **Hiroki Matsukuma** 提出。

该堆利用技术可以**强制使得 malloc 返回一个几乎任意地址的 chunk**。其核心在于滥用 free 中的**后向合并操作**（合并低地址的 chunk），从而使得尽可能避免碎片化。

利用这个方法需要修改下一个堆块的 **prev_size** 与 **PREV_INUSE** 比特位。

### 3.2 核心原理

**基本思路：**

1. 将目标 chunk 的 **prev_size** 字段设置为我们想要的目的位置与当前 chunk 的差值
2. 在溢出后，释放当前 chunk
3. 由于 PREV_INUSE 位被清除，ptmalloc 会认为前一个 chunk 是 free 的，从而触发**后向合并**
4. 合并后的新 chunk 起始位置为：`chunk_at_offset(p1, -(long)prevsize)`
5. 这个位置就是我们想要的目的位置

```
目标地址 = 当前 chunk 地址 - prev_size
```

**示意图：**

```
假设我们想让 malloc 返回地址 0x602000 处的 chunk：

当前 chunk 地址: 0x602100
目标地址:        0x602000
差值 (prev_size): 0x100

设置当前 chunk 的 prev_size = 0x100
清除下一个 chunk 的 PREV_INUSE 位

free(当前 chunk) → 触发后向合并
合并后的 chunk 起始地址 = 0x602100 - 0x100 = 0x602000 ✓
```

### 3.3 绕过 unlink 限制

这种方法在一般情况下需要绕过 unlink 的限制，即我们需要手动设置 **fake_chunk 的 fd 与 bk 合法**。

#### 常规 unlink 绕过

对于 unlink 时，通常设置 fake_chunk 的 fd、bk 为 `p-24` 和 `p-16`：

```
FD = p->fd = p - 24
BK = p->bk = p - 16

FD->bk = (p-24)->bk = p  ✓
BK->fd = (p-16)->fd = p  ✓
```

满足 `FD->bk == P && BK->fd == P`。

#### House of Einherjar 中的简化绕过

但在 House of Einherjar 中，我们**并没有打算让 p 值改变**，只是为了绕过限制完成 unlink 与合并而已。

因此，**设置 fd、bk 都为 chunk 本身地址即可**：

```
FD = p->fd = p
BK = p->bk = p

FD->bk = p->bk = p  ✓
BK->fd = p->fd = p  ✓
```

显然满足 `FD->bk == P && BK->fd == P`。

> **关键洞察：** 由于我们的目的不是通过 unlink 修改指针，而仅仅是通过安全检查让合并顺利进行，所以让 fd 和 bk 都指向自身是最简单有效的绕过方式。

### 3.4 完整利用流程

```
步骤 1: 规划目标地址
        - 确定希望 malloc 返回的地址 target_addr
        - 计算 prev_size = 当前 chunk 地址 - target_addr

步骤 2: 构造堆布局
        - 在目标位置附近布置好 fake_chunk 的头部
        - 设置 fake_chunk 的 size 字段（需要合理，通过大小检查）
        - 设置 fake_chunk 的 fd = fake_chunk 地址
        - 设置 fake_chunk 的 bk = fake_chunk 地址

步骤 3: 设置 prev_size 和 PREV_INUSE
        - 在当前 chunk 的 prev_size 字段写入计算好的差值
        - 利用 off-by-null 将下一个 chunk 的 PREV_INUSE 位清零
          （off-by-null 写入 \x00 恰好清除 bit 0）

步骤 4: 触发合并
        - free(当前 chunk)
        - ptmalloc 检测到 PREV_INUSE = 0，触发后向合并
        - 合并后的 chunk 起始地址 = 当前地址 - prev_size = target_addr

步骤 5: 利用任意地址 chunk
        - 再次 malloc 时，malloc 返回 target_addr 处的 chunk
        - 实现对几乎任意地址的读写
```

## 四、两种技术对比

| 对比项 | Chunk Shrink | House of Einherjar |
|-------|-------------|-------------------|
| **漏洞类型** | off-by-null | off-by-null |
| **核心目标** | 构造 chunk overlap | malloc 返回任意地址 |
| **利用机制** | 缩小 chunk size + unlink 合并 | 修改 prev_size + 后向合并 |
| **需要伪造的内容** | fake_prev_size | fake_chunk 头部（fd, bk, size） |
| **unlink 绕过方式** | 利用 free chunk 自动写入 prev_size | fd = bk = chunk 自身地址 |
| **利用难度** | 较高（多步骤配合） | 中等（需要精确计算偏移） |
| **适用场景** | 需要 overlap 覆盖相邻 chunk | 需要任意地址分配 |
| **提出者** | — | Hiroki Matsukuma |

## 五、实战注意事项

### 5.1 环境依赖

- 两种技术均基于 **ptmalloc**（glibc 的堆分配器）
- 不同版本的 glibc 对 unlink 的检查严格程度不同
- glibc 2.23 及以下版本检查相对宽松，2.27+ 引入了 tcache 机制，利用方式有所变化

### 5.2 Chunk Shrink 注意事项

1. **chunk 大小要求：** 第 2、3 个 chunk 大小需大于 0x100，确保进入 unsorted bin 而非 tcache
2. **fake_prev_size 的精确性：** 必须与 shrink 后 chunk 的实际 size 一致，否则 unlink 检查失败
3. **unsorted bin 清空：** 中间需要申请两个 chunk 清空 unsorted bin，避免 last_remainder 机制干扰
4. **guard chunk：** 最后需要一个 guard chunk 防止合并到 top chunk

### 5.3 House of Einherjar 注意事项

1. **目标地址对齐：** 目标地址需要满足堆块对齐要求（通常为 0x10 对齐）
2. **fake_chunk 的 size 字段：** 需要合理设置，通过 glibc 的大小检查（不能太小，也不能太大）
3. **PREV_INUSE 清除：** off-by-null 写入的 `\x00` 恰好能清除 PREV_INUSE 位（bit 0），这是该技术成立的前提
4. **地址计算：** prev_size = 当前 chunk 地址 - 目标地址，需确保差值为正且合理
