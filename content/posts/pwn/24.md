## 一、tcache 简介

### 1.1 背景

在 **GLIBC 2.26** 中，引入了一种新的 bins，叫做 **tcache**（Thread Local Cache，线程本地缓存）。

### 1.2 基本特性

- tcache 类似于 fastbin，但每条链上**最多可以有 7 个 chunk**。
- **free 时**：当 tcache 满了之后，才会将 chunk 放入 fastbin 或 unsorted bin。
- **malloc 时**：优先去 tcache 中查找，tcache 中没有才去其他 bins 找。

### 1.3 与 fastbin 的关系

> 换句话说，tcache 是比 fastbin **优先级更高、范围更大** 的一类 bins。

| 特性 | fastbin | tcache |
|------|---------|--------|
| 引入版本 | 较早 | GLIBC 2.26 |
| 每链最大 chunk 数 | 无明确限制（实际受大小限制） | 7 |
| 优先级 | 低 | 高（malloc 优先查 tcache） |
| 线程安全 | 全局共享 | 线程本地（per-thread） |
| 检查机制 | 较少 | 几乎无（早期版本） |

## 二、tcache 数据结构

### 2.1 tcache_entry

```c
/* We overlay this structure on the user-data portion of a chunk */
typedef struct tcache_entry
{
    struct tcache_entry *next;
} tcache_entry;
```

- `tcache_entry` 是存放 tcache 链表的**节点**。
- 在 GLIBC 2.27 中，它与 `unsigned int` 并没有太大差别。
- 它被**覆盖在 chunk 的 user-data 区域**上。

### 2.2 tcache_perthread_struct

```c
/* There is one of these for each thread, which contains the per-thread cache */
typedef struct tcache_perthread_struct
{
    char counts[TCACHE_MAX_BINS];
    tcache_entry *entries[TCACHE_MAX_BINS];
} tcache_perthread_struct;
```

- `tcache_perthread_struct` 是 tcache 的**管理结构**，每个线程各有一个。
- **counts**：存放每个 tcache 链上 chunk 的个数，最大值是 **255**（`char` 类型，即 `unsigned int8`）。
- **entries**：与 fastbin 差不多，是 tcache 链表的**入口指针数组**。

### 2.3 结构关系图

```
tcache_perthread_struct (每个线程一个)
├── counts[TCACHE_MAX_BINS]    // 每条链的 chunk 计数
│   ├── counts[0]  → 对应 size 0x20 的链上 chunk 数量
│   ├── counts[1]  → 对应 size 0x30 的链上 chunk 数量
│   ── ...
└── entries[TCACHE_MAX_BINS]   // 每条链的头指针
    ├── entries[0] → tcache_entry → tcache_entry → ... → NULL
    ├── entries[1] → tcache_entry → tcache_entry → ... → NULL
    └── ...
```

## 三、tcache 核心函数

tcache 中有两个重要的函数：**`tcache_get()`** 和 **`tcache_put()`**，分别用于**取出**与**放入** tcache，在 `malloc` 与 `free` 时会**优先调用**。

### 3.1 tcache_put()

```c
static void
tcache_put (mchunkptr chunk, size_t tc_idx)
{
    tcache_entry *e = (tcache_entry *) chunk2mem (chunk);
    assert (tc_idx < TCACHE_MAX_BINS);
    e->next = tcache->entries[tc_idx];
    tcache->entries[tc_idx] = e;
    ++(tcache->counts[tc_idx]);
}
```

**执行流程：**

1. 将 chunk 转换为 `tcache_entry` 指针 `e`。
2. 断言 `tc_idx < TCACHE_MAX_BINS`。
3. 将 `e->next` 指向当前链头 `tcache->entries[tc_idx]`。
4. 将链头更新为 `e`（头插法）。
5. 对应链的 `counts` 加 1。

### 3.2 tcache_get()

```c
static void *
tcache_get (size_t tc_idx)
{
    tcache_entry *e = tcache->entries[tc_idx];
    assert (tc_idx < TCACHE_MAX_BINS);
    assert (tcache->entries[tc_idx] > 0);
    tcache->entries[tc_idx] = e->next;
    --(tcache->counts[tc_idx]);
    return (void *) e;
}
```

**执行流程：**

1. 取出链头 `e = tcache->entries[tc_idx]`。
2. 断言 `tc_idx < TCACHE_MAX_BINS`。
3. 断言链表非空（`tcache->entries[tc_idx] > 0`）。
4. 将链头更新为 `e->next`。
5. 对应链的 `counts` 减 1。
6. 返回 `e` 作为分配的内存。

### 3.3 malloc 中的 tcache 调用

```c
#if USE_TCACHE
    /* int_free also calls request2size, be careful to not pad twice. */
    size_t tbytes;
    checked_request2size (bytes, tbytes);
    size_t tc_idx = csize2tidx (tbytes);

    MAYBE_INIT_TCACHE ();

    DIAG_PUSH_NEEDS_COMMENT;
    if (tc_idx < mp_.tcache_bins
        /*&& tc_idx < TCACHE_MAX_BINS*/  /* to appease gcc */
        && tcache
        && tcache->entries[tc_idx] != NULL)
    {
        return tcache_get (tc_idx);
    }
    DIAG_POP_NEEDS_COMMENT;
#endif
```

**关键逻辑：**

- 在 `malloc` 时，只要 `tc_idx < mp_.tcache_bins`（即申请的大小不是 largebin）**且** tcache 中存在对应大小的 chunk，就**直接取出**。
- 在 `tcache_get` 中，也**没有过多检查**。

### 3.4 free 中的 tcache 调用

```c
#if USE_TCACHE
    {
        size_t tc_idx = csize2tidx (size);

        if (tcache
            && tc_idx < mp_.tcache_bins
            && tcache->counts[tc_idx] < mp_.tcache_count)
        {
            tcache_put (p, tc_idx);
            return;
        }
    }
#endif
```

**关键逻辑：**

- 在 `free` 时，只要 **size 和地址合法**，且 `size < large bin`，对应大小的 tcache **未满（< 7）**，就会将其放入对应的 tcache 中。

## 四、tcache attack 原理

### 4.1 攻击基础

tcache 为了效率，**几乎没有任何安全检查**，这使得它非常容易利用。

#### 4.1.1 任意地址 malloc

> 通过覆盖 tcache 中的 `next` 指针，**不需要伪造任何 chunk 结构**即可实现 malloc 到任何地址。

**原因：**

- `tcache_get()` 中仅做简单的断言检查，没有对 `next` 指针做合法性验证。
- 只要我们能修改某个 tcache entry 的 `next` 字段为任意地址，下一次 `malloc` 对应大小时就会返回该任意地址。

**攻击步骤：**

1. 分配一个 chunk 并 free 进入 tcache。
2. 通过堆溢出等漏洞，覆盖该 chunk 的 `next` 指针为目标地址。
3. 再次 `malloc` 相同大小，`tcache_get()` 会返回目标地址。

#### 4.1.2 Double Free

> `tcache_put()` 中**没有任何检查**，可以很容易地实现 double free 而不需要做任何绕过。

**原因：**

- `tcache_put()` 不检查 chunk 是否已经在 tcache 链中。
- 同一个 chunk 可以被多次 free 进入同一条 tcache 链。

**攻击效果：**

- 同一个 chunk 在 tcache 链中出现多次。
- 后续多次 malloc 会返回同一块内存，实现**任意写**。

### 4.2 tcache 的 free 范围扩大

对于 tcache 来说，它的 free 范围变大了。也就是说：

- 直接 free 一块 **unsorted bin 大小**的 chunk，并**不会直接进入 unsorted bin**，而是会**先进入 tcache**。
- 只有对应大小的 tcache **满了以后**，才会放入 unsorted bin。

这意味着传统的 unsorted bin 攻击手法需要先填满 tcache。

## 五、获取 unsorted bin 的方法

由于 tcache 的存在，想要得到一个 unsorted bin 有以下方法：

### 方法 1：Free 一个 largebin

> largebin **不会**放入 tcache，会直接进入 unsorted bin 或 largebin。

```
free(large_chunk)  →  unsorted bin / largebin
```

### 方法 2：先连续 free 填满 tcache，再 free 放进 unsorted bin

```
free(chunk) × 7  →  tcache 满
free(chunk)      →  unsorted bin
```

### 方法 3：利用 UAF 快速填满 tcache

在存有 **UAF（Use-After-Free）** 的时候，可以先连续 free 两次，再 malloc 三次快速填满 tcache。

**原理详解：**

1. 先 free 两次造成 **double free**，令 `next` 始终指向自身，此时 `count` 为 2。
2. 再连续申请 3 次：
   - 每申请一次 `count` 就会 -1。
   - 申请时**并不判断 count 是否为负**。
   - 3 次申请后，`count` 变为 `2 - 3 = -1`。
3. 在比较时 `count` 是 `char` 类型（即 `unsigned int8`），**-1 远大于 7**。
4. 导致 tcache 认为已满，后续 free 进入 unsorted bin。

```
free(chunk) × 2   →  double free, count = 2, next 指向自身
malloc() × 3      →  count = 2 - 3 = -1 (unsigned char: 255)
                     255 > 7, tcache 认为已满
free(chunk)       →  进入 unsorted bin
```

### 方法 4：打 tcache_perthread_struct 修改 count 后 free

通过漏洞修改 `tcache_perthread_struct` 中的 `counts` 字段，将对应链的 count 值改为 7（或更大），使 tcache 认为已满，后续 free 直接进入 unsorted bin。

## 六、tcache 的安全保护机制

tcache 看起来是一个十分容易利用的 bins，因为其为了效率，几乎没有任何安全检测。

但是不幸的是，在**新版本的 tcache bin** 中引入了几种保护措施。

### 6.1 Double Free Check

在 `tcache_put` 中，放入 chunk 后，加入了 `e->key = tcache`：

```c
static __always_inline void
tcache_put (mchunkptr chunk, size_t tc_idx)
{
    tcache_entry *e = (tcache_entry *) chunk2mem (chunk);
    assert (tc_idx < TCACHE_MAX_BINS);

    /* Mark this chunk as "in the tcache" so the test in _int_free
       detect a double free. */
    e->key = tcache;

    e->next = tcache->entries[tc_idx];
    tcache->entries[tc_idx] = e;
    ++(tcache->counts[tc_idx]);
}
```

在 `_int_free` 中，free 之前会检查 chunk 的 `key` 字段：

```c
#if USE_TCACHE
    size_t tc_idx = csize2tidx (size);
    if (tcache != NULL && tc_idx < mp_.tcache_bins)
    {
        /* Check to see if it's already in the tcache. */
        tcache_entry *e = (tcache_entry *) chunk2mem (p);

        /* This test succeeds on double free. However, we don't 100%
           trust it (it also matches random payload data at a 1 in
           2^64 chance), so verify it's not an unlikely coincidence
           before aborting. */
        if (__glibc_unlikely (e->key == tcache))
        {
            tcache_entry *tmp;
            LIBC_PROBE (memory_tcache_double_free, 2, e, tc_idx);
            for (tmp = tcache->entries[tc_idx];
                 tmp;
                 tmp = tmp->next)
                if (tmp == e)
                    malloc_printerr ("free(): double free detected in tcache 2");
            /* If we get here, it was a coincidence. We've wasted a
               few cycles, but don't abort. */
        }

        if (tcache->counts[tc_idx] < mp_.tcache_count)
        {
            tcache_put (p, tc_idx);
            return;
        }
    }
#endif
```

**保护逻辑：**

1. 每次 `tcache_put` 时，将 chunk 的 `key` 字段设置为 `tcache` 指针的值。
2. 在 `free` 时，检查 chunk 的 `key` 是否等于 `tcache`。
3. 如果相等，则遍历整条 tcache 链，确认该 chunk 是否真的已在链中。
4. 如果确认在链中，则报错 `"free(): double free detected in tcache 2"` 并 abort。

**绕过思路：**

- 修改 chunk 的 `key` 字段，使其不等于 `tcache` 指针值。
- 通过堆溢出覆盖 `key` 字段。

### 6.2 Safe Linking

> Safe Linking 是 GLIBC 2.32 引入的保护机制，对 tcache 和 fastbin 的指针进行加密。

**原理：**

- 对链表中的 `next` 指针进行**异或加密**：`encrypted_next = next ^ (chunk_addr >> 12)`。
- 解密时：`next = encrypted_next ^ (chunk_addr >> 12)`。

**影响：**

- 无法直接覆盖 `next` 指针为任意地址，需要知道加密密钥（即 chunk 地址的高位部分）。
- 增加了任意地址 malloc 的难度。

## 七、总结

### 7.1 tcache 核心要点

| 要点 | 说明 |
|------|------|
| 引入版本 | GLIBC 2.26 |
| 存储位置 | 线程本地（per-thread） |
| 每链最大 chunk 数 | 7 |
| malloc 优先级 | 最高（优先于 fastbin、unsorted bin 等） |
| free 行为 | 优先放入 tcache，满了才放入其他 bins |
| 早期安全检查 | 几乎无 |
| 新版本保护 | double free check、safe linking |

### 7.2 tcache attack 核心思路

1. **任意地址 malloc**：覆盖 tcache entry 的 `next` 指针。
2. **Double Free**：`tcache_put` 无检查，同一 chunk 可多次 free。
3. **获取 unsorted bin**：填满 tcache 或利用 count 下溢。
4. **绕过保护**：修改 `key` 字段绕过 double free check，利用 safe linking 特性绕过指针加密。

### 7.3 学习建议

1. **理解数据结构**：掌握 `tcache_entry` 和 `tcache_perthread_struct` 的内存布局。
2. **阅读源码**：结合 GLIBC 源码理解 `tcache_get`、`tcache_put` 的实现细节。
3. **动手实践**：通过 CTF 题目练习 tcache attack 的各种手法。
4. **关注版本差异**：不同 GLIBC 版本的 tcache 保护机制不同，需注意版本。
