## 1. Unsorted Bin Attack

### 1.1 基本来源

Unsorted Bin 中的 chunk 主要来自以下三种情况：

- **分割产生**：当一个较大的 chunk 被分割成两半后，如果剩下的部分大于 `MIN_SIZE`，就会被放到 unsorted bin 中。
- **释放产生**：释放一个不属于 fast bin 的 chunk，并且该 chunk 不和 top chunk 紧邻时，该 chunk 会被首先放到 unsorted bin 中。
- **合并产生**：当进行 `malloc_consolidate` 时，可能会把合并后的不和 top chunk 相邻的 chunk 放到 unsorted bin 中。

### 1.2 基本使用情况

Unsorted Bin 在使用的过程中，采用的遍历顺序是 **FIFO**（先进先出）：

- **插入**：插入到 unsorted bin 的 **头部**
- **取出**：从链表 **尾部** 获取

在程序 `malloc` 时，如果在 fastbin、small bin 中找不到对应大小的 chunk，就会尝试从 Unsorted Bin 中寻找 chunk。如果取出来的 chunk 大小刚好满足，就会直接返回给用户；否则就会把这些 chunk 分别插入到对应的 bin 中（small bin 或 large bin）。

### 1.3 攻击原理

在 `_int_malloc` 函数中，当将一个 unsorted bin 取出的时候，会将 `bk->fd` 的位置写入本 Unsorted Bin 的位置。

关键源码如下：

```c
/* remove from unsorted list */
unsorted_chunks(av)->bk = bck;
bck->fd = unsorted_chunks(av);
```

**攻击思路**：

如果我们能够伪造一个 chunk，使其 `bk` 指针指向我们想要写入的目标地址（例如某个全局变量或栈上变量的地址减去 `0x10`），那么当这个伪造的 chunk 从 unsorted bin 中被取出时：

1. `bck = victim->bk` → `bck` 指向目标地址
2. `bck->fd = unsorted_chunks(av)` → 将 unsorted bin 的地址写入目标地址

这样就实现了**任意地址写入一个堆地址**（unsorted bin 的地址）。

### 1.4 攻击示例代码

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    long long int cnt = 0x12345678;
    printf("First:%p\n", cnt);

    unsigned long long *ptr1, *ptr2;
    ptr1 = malloc(0x500);
    ptr2 = malloc(0x10);

    free(ptr1);

    // 伪造 chunk 的 bk 指针，指向 &cnt - 0x10
    // 这样 bck->fd 就对应 cnt 的位置
    ptr1[1] = (char *)&cnt - 0x10;

    // 触发 unsorted bin 的取出操作
    malloc(0x500);

    printf("Now:%p", cnt);
    return 0;
}
```

**运行结果**：

```
→ 7.unsorted bin attack ./demo
First:0x12345678
Now:0x7feaa0c18b78
→ 7.unsorted bin attack
```

**分析**：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | `ptr1 = malloc(0x500)` | 分配一个大 chunk，后续 free 会进入 unsorted bin |
| 2 | `ptr2 = malloc(0x10)` | 分配一个小 chunk，防止 ptr1 与 top chunk 合并 |
| 3 | `free(ptr1)` | ptr1 进入 unsorted bin |
| 4 | `ptr1[1] = (char *)&cnt - 0x10` | 伪造 ptr1 的 bk 指针，指向 cnt 变量前 0x10 的位置 |
| 5 | `malloc(0x500)` | 触发 unsorted bin 取出，执行 `bck->fd = unsorted_chunks(av)`，将堆地址写入 cnt |

**注意**：`ptr1[1]` 对应的是 chunk 的 `bk` 指针位置（偏移 `0x10` 处，即 chunk header 之后的第二个指针）。`&cnt - 0x10` 是因为 `bck->fd` 的偏移是 `0x10`，所以要让 `bck->fd` 恰好等于 `cnt` 的地址。

## 2. Large Bin Attack

### 2.1 Large Bin 结构

Large Bin 的结构比 Unsorted Bin 复杂得多：

| 特性 | 说明 |
|------|------|
| bin 数量 | 共 **63 个 bins** |
| chunk 大小 | 每个 bin 中的 chunk 大小不一致，处于一定区间范围内 |
| 分组 | 63 个 bin 被分成 **6 组**，每组 bin 中的 chunk 大小之间的公差一致 |
| 管理方式 | 双向循环链表 - FIFO |
| 大小范围 | 大于 `0x400`（64位） |
| 排序规则 | 按照大小从大到小排序；若大小在同一区间，按照 free 时间排序 |

**fd_nextsize / bk_nextsize 指针说明**：

- 若干个大小在同一区间的块，只有**首堆块**的 `fd_nextsize` 和 `bk_nextsize` 会指向其他堆块，后面的堆块的 `fd_nextsize` 和 `bk_nextsize` 均为 0
- size 最大的 chunk 的 `bk_nextsize` 指向最小的 chunk
- size 最小的 chunk 的 `fd_nextsize` 指向最大的 chunk
- `fd_nextsize` 指向**小**的 chunk，`bk_nextsize` 指向**大**的 chunk

**Large Bin 链表结构示意**：

```
        ┌──────────┐
        │  bin[64]  │
        ────┬─────┘
             │ fd / bk
     ┌───────┴───────────┐
     ▼                   ▼
┌─────────┐       ┌─────────┐
│ C3(0x420)│◄─────►│ C4(0x420)│  ← 同一区间，通过 fd_nextsize/bk_nextsize 连接
────┬────┘       └────┬────┘
     │ fd_nextsize     │ fd_nextsize
     ▼                 ▼
┌─────────┐       ┌─────────┐
│ C1(0x430)│       │ C2(0x440)│  ← 不同区间，通过 fd/bk 连接
└─────────┘       └─────────┘
```

### 2.2 攻击原理（场景一）

**前提条件**：victim chunk 的 size < large bin 中最小的 chunk

**插入过程**：

1. large bin 中 `bin->fd` 指向最大的块，`bin->bk` 指向最小的块
2. 首先判断如果我们的 size < 最小的块，就将其插入到 bin 的**最尾部**

**关键写入操作**：

```c
victim->bk_nextsize = fwd->fd->bk_nextsize;
fwd->fd->bk_nextsize = victim->bk_nextsize->fd_nextsize = victim;
```

**攻击思路**：

如果我们控制了 `fwd->fd->bk_nextsize` 的值，就可以做到**任意地址写一个堆地址**。

具体而言：
- `fwd->fd->bk_nextsize` 被写入 `victim` 的地址
- 通过伪造 `bk_nextsize` 指针，可以控制写入的目标位置

### 2.3 攻击原理（场景二）

**前提条件**：victim chunk 的 size >= large bin 中某个 chunk 的 size

**插入过程**：

从最大的开始，找到第一个 size 小于将插入 chunk 的位置，将 chunk 插入进去。

**注意**：不能让 size 与其相等，如果相等的话，就会直接链入了。

**关键写入操作**：

```c
victim->bk_nextsize = fwd->bk_nextsize;
victim->bk_nextsize->fd_nextsize = victim;
```

同时，结合：

```c
bk = fwd->bk;
bk->fd = victim;
```

**攻击效果**：

- `victim->bk_nextsize->fd_nextsize = victim` → 可以在一个位置写入堆地址
- `bk->fd = victim` → 可以在**另一个位置**写入堆地址

即场景二可以实现**两个位置的任意地址写入**。

### 2.4 glibc 2.31 的防护

在 glibc 2.31 中，加入了新的 check：

```c
fwd->bk_nextsize->fd_nextsize == fwd
```

这使得**第二种利用方式**很难使用了，需要使用第一种来进行 large bin attack。

**glibc 2.31 源码中的关键检查**：

```c
if ((unsigned long) size
    == (unsigned long) chunksize_nomask(fwd))
{
    /* Always insert in the second position. */
    fwd = fwd->fd;
}
else
{
    victim->fd_nextsize = fwd;
    victim->bk_nextsize = fwd->bk_nextsize;
    if (__glibc_unlikely(fwd->bk_nextsize->fd_nextsize != fwd))
        malloc_printerr("malloc(): largebin double linked list corrupted (nextsize)");
    fwd->bk_nextsize = victim;
    victim->bk_nextsize->fd_nextsize = victim;
}
bk = fwd->bk;
if (bk->fd != fwd)
    malloc_printerr("malloc(): largebin double linked list corrupted (bk)");
```

新增的检查项：
1. `fwd->bk_nextsize->fd_nextsize != fwd` → 检查 large bin 的 nextsize 链表完整性
2. `bk->fd != fwd` → 检查 large bin 的 bk 链表完整性

## 3. 总结与对比

| 特性 | Unsorted Bin Attack | Large Bin Attack |
|------|---------------------|------------------|
| **触发条件** | 从 unsorted bin 取出 chunk 时 | 向 large bin 插入 chunk 时 |
| **写入内容** | unsorted bin 的地址（堆地址） | victim chunk 的地址（堆地址） |
| **写入位置数** | 1 个位置 | 场景一：1 个位置；场景二：2 个位置 |
| **利用难度** | 较低 | 较高 |
| **glibc 2.31 影响** | 仍可使用 | 场景二被防护，需用场景一 |
| **关键指针** | `bk` → `bck->fd` | `bk_nextsize` / `fd_nextsize` |
| **典型利用目标** | 修改全局变量、函数指针、栈变量 | 同左，且场景二可写两个位置 |

### 利用前提（通用）

两种攻击都需要满足以下条件：

1. **能够控制 chunk 的指针字段**（bk、bk_nextsize 等）
2. **存在堆溢出或 UAF 漏洞**，可以修改已释放 chunk 的元数据
3. **目标地址可写**，且写入堆地址后能产生可利用的效果（如修改函数指针、返回地址等）

### 防护建议

- 使用 glibc 2.31+ 版本，large bin attack 的场景二已被防护
- 启用 **tcache**（glibc 2.26+），减少 chunk 进入 unsorted/large bin 的机会
- 使用 **Safe Linking**（glibc 2.32+），对 fd/bk 指针进行加密
- 开启 **ASLR** 和 **Stack Canary** 等常规防护
